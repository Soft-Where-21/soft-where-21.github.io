### 1.1 B 树与 B+ 树 ⭐⭐⭐

**Q [⭐⭐⭐]【1.1.Q1】：什么是 B 树？m 阶 B 树有哪些性质？**

A：**B 树**是一种**多路平衡查找树**（不是二叉树）：每个结点可以存多个关键字、有多个孩子，从而**降低树高**，减少磁盘 I/O。
**m 阶 B 树的定义**：① 每个结点最多 **m 棵子树、m-1 个关键字**；② 根结点若不是叶子，至少 **2 棵子树**；③ 除根外的每个非叶结点至少 **$\lceil m/2\rceil$ 棵子树**（即至少 $\lceil m/2\rceil-1$ 个关键字，保证"不太空"）；④ 结点内关键字**有序**，各子树的关键字落在相邻关键字划出的区间内（$k_1 <$ 子树 1 $< k_2 <$ 子树 2 $< \dots$）；⑤ **所有叶子都在同一层**（完全平衡）；⑥ **所有结点都存数据**（关键字 + 卫星数据/记录指针）。

**Q [⭐⭐⭐]【1.1.Q2】：什么是 B+ 树？它和 B 树有什么区别？（北航真题）**

A：**B+ 树**是 B 树的变体：**内部结点只存索引 key（不存数据）**，**所有数据都在叶子**，叶子按 key 顺序**用链表相连**。
区别：

| | B 树 | B+ 树 |
|---|---|---|
| 数据位置 | **所有结点**都能存数据 | **只有叶子**存数据，内部只存 key |
| key 是否重复 | 不重复 | 内部 key 会在叶子**重复出现** |
| 查找终点 | 可能在内部结点命中、**提前结束** | **必须走到叶子**，路径长度稳定 |
| 单结点容量 | 小（要挤下数据） | **大**（只存 key + 指针）→ 树更矮 → I/O 更少 |
| 范围查询 | 需中序遍历 + 回溯 | **叶子链表**顺序扫描，极快 |
| 应用 | 部分文件系统、内存索引 | **数据库索引**（MySQL InnoDB） |

**Q [⭐⭐⭐]【1.1.Q3】：数据库为什么用 B+ 树做索引？**

A：因为数据库的瓶颈是**磁盘 I/O**，而 I/O 以**块（页）**为单位，所以要"**让每次 I/O 尽可能多地缩小搜索范围、让树尽可能矮**"：
① **内部结点只存 key** → 同样一页能容纳几百个 key（m 很大）→ 树高只有 3~4 层就能索引千万甚至上亿条记录 → **I/O 次数极少**；
② **所有数据在叶子且叶子有序链表相连** → **范围查询 / ORDER BY / 全表顺序扫描**只需沿链表顺序读，不用反复回溯；
③ **查找路径长度稳定**（必到叶子）→ 查询性能可预测；
④ 叶子层还可以串成双向链表支持"上一页/下一页"，天然适配分页与 `BETWEEN`。
（B 树的缺陷：数据分散在所有结点，单结点能放的 key 少 → 树更高 → I/O 更多；范围查询还要中序回溯。）

**Q [⭐⭐⭐]【1.1.Q4】：数据库查询优化有哪些方法？（北航真题）**

A：按层次答：
① **索引**：给 `WHERE`/`JOIN`/`ORDER BY` 的**高区分度**列建 B+ 树索引；**覆盖索引**（查询列全在索引里 → 免回表）；**联合索引遵循最左前缀**；避免在索引列上做函数运算、隐式类型转换、前置通配符 `LIKE '%x'`（会**导致索引失效**）；
② **SQL 重写**：用 `JOIN` 代替嵌套子查询；只取需要的列（别 `SELECT *`）；让过滤条件尽早生效（**谓词下推**）；大表分页用**延迟关联/游标分页**替代大 `OFFSET`；大表用 `EXISTS` 替代 `IN`；不需要去重时用 `UNION ALL`；
③ **执行计划**：`EXPLAIN` 看 `type`（访问类型）、`key`（命中索引）、`rows`（扫描行数）、`Extra`（是否出现 `Using filesort` / `Using temporary`），据此改写；
④ **表结构**：范式化减少冗余或适度反范式减少 JOIN；字段类型尽量小；大表**分区 / 水平分表**；
⑤ **数据库内部**：基于代价的优化（CBO）——按统计信息估算选择率与代价，选**连接顺序**（动态规划/贪心）和**连接算法**（嵌套循环 / 哈希连接 / 排序合并连接），统计信息要定期 `ANALYZE`；
⑥ **架构**：加缓存（Redis）、读写分离、批量代替逐条、缩短事务避免锁竞争。
**一句话兜底**：查询优化 = **少读数据（索引、减少 I/O）+ 早点过滤（谓词下推、减少中间结果）+ 别让优化器选错（统计信息、避免索引失效）**。核心指标永远是"扫描了多少行、发生了几次 I/O"。

### 1.2 哈夫曼树与哈夫曼编码 ⭐⭐⭐

**Q [⭐⭐⭐]【1.2.Q1】：什么是哈夫曼树？什么是带权路径长度 WPL？**

A：**哈夫曼树（最优二叉树）**：给定 n 个带权**叶子**结点，构造一棵**带权路径长度最小**的二叉树。
**带权路径长度**：

$$\text{WPL} = \sum_{i=1}^{n} w_i \times l_i$$

其中 $w_i$ 是第 i 个叶子的权值，$l_i$ 是该叶子到根的**路径长度（经过的边数）**。WPL 越小说明"权值大的叶子离根越近"，这正是哈夫曼树的目标。
**性质**：① **没有度为 1 的结点**（每次都是两两合并）；② n 个叶子共 **2n-1** 个结点；③ 等权时树形**不唯一**，但 **WPL 相同**。

**Q [⭐⭐]【1.2.Q2】：哈夫曼树怎么构造？复杂度是多少？**

A：**贪心构造**：① 把 n 个权值各看成一棵只有根的树，放入集合 F；② 从 F 中取**权值最小的两棵树**，合并成一棵新树（根的权 = 两子树根权之和，两棵树分别作左右孩子）；③ 把新树放回 F；④ 重复 ②③，直到 F 中只剩一棵树。
用**小根堆**维护"取两个最小值"：每次取最小两次 + 插入一次，各 O(log n)，共合并 n-1 次 → 总复杂度 **$O(n\log n)$**（快排同期排序亦可，但堆是最标准的做法）。

**Q [⭐⭐⭐]【1.2.Q3】：什么是哈夫曼编码？为什么它是变长编码？（北航真题）**

A：**哈夫曼编码**是依据**字符出现频率**构造的**变长前缀编码（异字头编码）**，使**平均码长最短**：由哈夫曼树得到——左分支记 0、右分支记 1，从根到每个叶子的路径比特序列就是该字符的编码。
**为什么变长**：让**频率高的字符编码短、频率低的编码长**（权值大的叶子离根近、路径短）→ 平均码长 $\bar{L} = \sum p_i l_i$ 最小，等于 WPL 除以总频率。对比**定长编码**需要 $\lceil \log_2 n \rceil$ 位/字符，哈夫曼编码在频率分布不均匀时能省下大量空间。

**Q [⭐⭐⭐]【1.2.Q4】：哈夫曼编码为什么不需要分隔符？有什么应用？**

A：因为它是**前缀编码（异字头编码）**：编码只对应哈夫曼树的**叶子**，任何一个叶子都不可能是另一个叶子的祖先，因此**没有任何一个编码是另一个编码的前缀** → 解码时从左到右逐位读、一旦匹配到某个叶子就输出该字符并回到根继续，**不会产生歧义，无需分隔符**。
**应用**：文件压缩（ZIP 的 DEFLATE、JPEG/MP3 的熵编码）、传真机编码。
**局限**：需要**事先统计全部字符频率**（要两遍扫描，不能边读边压）；只能整数位编码（达不到信息论下界，算术编码可突破）；频率估计失真时压缩率下降 → 用**自适应（动态）哈夫曼**边读边更新。

### 1.3 最小生成树：Prim 与 Kruskal ⭐⭐⭐

**Q [⭐⭐⭐]【1.3.Q1】：什么是生成树？什么是最小生成树？**

A：**生成树（spanning tree）**：连通无向图 $G=(V,E)$ 的一个**包含全部 n 个顶点、恰好 n-1 条边**的**连通无圈子图**（即图的极小连通子图）。
**最小生成树（MST, Minimum Spanning Tree）**：所有生成树中**边权之和最小**的那棵。
三点要点：① **只有连通图才有生成树**，非连通图得到的是**最小生成森林**；② 边权和唯一，但 **MST 本身不一定唯一**（存在等权边时）；③ MST 只针对**无向图**（有向图的对应问题是最小树形图，用朱刘算法）。

**Q [⭐⭐⭐]【1.3.Q2】：Prim 算法的思想和复杂度是什么？**

A：**Prim（普里姆）——从点扩展的贪心**：
① 任选一个顶点加入集合 $S$（已生成的部分），其余在 $V-S$；
② 维护 `d[v]` = 顶点 v **到集合 S 中任一点的最小边权**，`pre[v]` 记录这条边；
③ 每轮从 $V-S$ 中取 `d[v]` **最小**的顶点 u 加入 S，并把边 $(u, pre[u])$ 计入结果；
④ 用 u 的邻边**松弛** $V-S$ 中所有点（`w(u,v) < d[v]` 就更新）；
⑤ 重复 n-1 次（即加入 n 个点）。
**复杂度**：邻接矩阵 + 朴素选最小 **$O(V^2)$**；邻接表 + 二叉堆 **$O(E\log V)$**；斐波那契堆 $O(E + V\log V)$。

**Q [⭐⭐⭐]【1.3.Q3】：Kruskal 算法的思想和复杂度是什么？**

A：**Kruskal（克鲁斯卡尔）——从边扩展的贪心**：
① 把**所有边按权值从小到大排序**；
② 依次取每条边 $(u,v)$，用**并查集**判断 u、v 是否已在同一连通分量；
③ 若**不在**同一分量 → 选入该边并**合并**两个分量；若**已在**同一分量 → **丢弃**（选它会成环）；
④ 选满 **n-1** 条边即结束（也可能因图不连通而提前耗尽所有边）。
**复杂度**：排序 $O(E\log E)$ + 并查集（路径压缩 + 按秩合并，近似 $O(\alpha(E))$ ≈ O(1)）→ 总计 **$O(E\log E)$**。

**Q [⭐⭐⭐]【1.3.Q4】：Prim 和 Kruskal 有什么区别？分别适合什么图？**

A：

| 维度 | Prim | Kruskal |
|------|------|---------|
| 贪心对象 | **顶点**（每次选离树最近的点） | **边**（每次选最小且不成环的边） |
| 关键结构 | 优先队列 / 数组存 `d[]` | **排序 + 并查集** |
| 复杂度 | $O(V^2)$ / $O(E\log V)$ | $O(E\log E)$ |
| 适合 | **稠密图**（$E$ 接近 $V^2$） | **稀疏图**（$E \ll V^2$） |
| 中间状态 | 始终是**一棵树** | 可能是**森林**，最后才连成树 |
| 判环 | 天然无环（只从 $V-S$ 取点） | 靠**并查集**判环 |

**Q [⭐⭐]【1.3.Q5】：为什么 Prim 和 Kruskal 的贪心能得到全局最优？**

A：依据 **切割性质（cut property）**：对图的任意一个顶点划分 $(S, V-S)$，**横跨该切割的权最小的边**一定属于某棵 MST。用**交换论证**：若某棵 MST 不含这条最轻横切边 e，把 e 加进去会形成环，环上必有另一条横跨同一切割的边 f（$w(f) \ge w(e)$），用 e 换掉 f 后仍是生成树且边权和**不增大** → 说明"选这条边不会错过最优解"。
- Prim 每步都是在切割 $(S, V-S)$ 上选最轻横切边；
- Kruskal 每步选的是"使两棵子树连通的最轻边"，同样可由切割性质保证。
所以两者都是**贪心 + 该性质**，得到全局最优。

**Q [⭐⭐⭐]【1.3.Q6】：Prim 算法和 Dijkstra 算法的关键区别是什么？（高频易混）**

A：代码骨架几乎相同（都是"取最近点 + 松弛邻边"），但**含义完全不同**：
- **Prim 的 `d[v]`** = v 到**已生成树集合 S** 的最小**边权**，松弛用 `w(u,v)`；
- **Dijkstra 的 `dist[v]`** = v 到**起点 s** 的**路径长度**，松弛用 `dist[u] + w(u,v)`。
- 结论：Prim 求的是"**连通所有点的最小代价**"（MST，允许图非连通则得森林）；Dijkstra 求的是"**从起点到各点的最短路径**"（要求非负权）。**一个是选边权、一个是累加路径长**，务必别背混。

### 1.4 最短路径：Dijkstra、Bellman-Ford 与 Floyd ⭐⭐⭐

**Q [⭐⭐⭐]【1.4.Q1】：Dijkstra 算法的思想、流程和复杂度是什么？**

A：**用途**：单源最短路，**要求所有边权非负**。**思想**：**贪心**——每次在未确定的点中取当前 `dist` 最小的，就认为它的最短路已最终确定，然后松弛它的出边。
**流程**：① 初始化 `dist[s]=0`，其余为 ∞，所有点未确定；② 从未确定的点中取 `dist` 最小的 u，**标记为已确定**；③ 用 u 松弛其所有出边：`dist[u]+w(u,v) < dist[v]` 则更新 `dist[v]` 并记 `pre[v]=u`；④ 重复 n 次。
**复杂度**：邻接矩阵朴素实现 **$O(V^2)$**（适合稠密图）；邻接表 + 二叉堆（优先队列）**$O(E\log V)$**（适合稀疏图）。需要记录路径时用 `pre[]` 回溯。

**Q [⭐⭐⭐]【1.4.Q2】：为什么 Dijkstra 不能处理负权边？（北航真题）**

A：因为它的正确性依赖一条**贪心假设**："一旦某点被取出（`dist` 最小），它的最短路就**已最终确定、不会再被更新**。"
**负权会打破这个假设**：之后经过负权边可能得到更短的路径，但算法已把该点"封"了、不再修正 → 结果偏大（错误）。
**反例**：边  $A\to B=2,\ A\to C=5,\ C\to B=-4$ ，Dijkstra 先确定 $dist[B]=2$（经 $A\to B$），而真实最短路是 $A\to C\to B = 1$ ，1 < 2，但 B 已确定、停留在 2，**答错**。
**有负权边 → 用 Bellman-Ford（$O(VE)$，还能检测负环）或 SPFA**；全源且无负环 → Floyd。

**Q [⭐⭐⭐]【1.4.Q3】：Floyd 算法的思想、状态定义和复杂度是什么？**

A：**用途**：**全源最短路**（任意两点间），可含负权但不能有负环。**思想**：**区间 DP**——按"允许使用哪些点作为中转"分阶段递推。
**状态**：$d^{(k)}[i][j]$ = 只允许用前 k 个顶点作**中转点**时，i 到 j 的最短距离。
**转移方程**：

$$d[i][j] = \min\bigl(d[i][j],\ d[i][k] + d[k][j]\bigr)$$

**初始化**：`d[i][i]=0`、`d[i][j]=w(i,j)`、无边为 ∞。
**复杂度**：三重循环 **$O(V^3)$**，空间 $O(V^2)$（可直接在原矩阵上就地更新）。适合**小图**（V 几百以内）或需要"任意两点距离表"的场景。

**Q [⭐⭐⭐]【1.4.Q4】：Floyd 算法为什么必须把中转点 k 放在最外层循环？**

A：因为 **k 是"阶段"（DP 的阶段变量），i、j 是"状态"**：$d^{(k)}$ 只能由 $d^{(k-1)}$ 推出，即"允许用前 k 个点中转"必须建立在"允许用前 k-1 个点中转"已经算好之上。
如果把 k 放在最内层，`d[i][j]` 会在同一轮里用到**尚未准备完整**的 `d[i][k]`、`d[k][j]`，**阶段顺序被破坏** → 递推关系不成立、结果可能错误。这是 Floyd 最经典的实现陷阱。

**Q [⭐⭐]【1.4.Q5】：Floyd 能处理负权吗？怎么检测负权回路？**

A：**能处理负权边**（因为它是 DP 而不是贪心，不依赖"提前确定"的假设），但**不能有负权回路**——有负环时"最短路"可以无限绕圈变小、根本没有下界。
**检测方法**：跑完三重循环后检查是否存在 `d[i][i] < 0`：初始 `d[i][i]=0`，若无负环则最短回路长仍为 0；若发现某个 `d[i][i] < 0`，说明从 i 出发能到达一个负权回路。
**工程注意**：用 `0x3f3f3f3f` 之类作 ∞ 时，要防止 `d[i][k] + d[k][j]` 两个 ∞ 相加溢出（先判断 `d[i][k] != INF && d[k][j] != INF`）。

**Q [⭐⭐⭐]【1.4.Q6】：Dijkstra、Floyd、Bellman-Ford 有什么区别？**

A：

| 对比项 | Dijkstra | Floyd | Bellman-Ford |
|--------|----------|-------|--------------|
| 解决问题 | 单源 | **全源** | 单源 |
| 负权 | ❌ 不允许 | ✅ 允许（不能有负环） | ✅ 允许（能检负环） |
| 核心思想 | **贪心**（每次取最近点） | **区间 DP**（k 为中转） | **边松弛 DP**（对所有边松弛 V-1 轮） |
| 复杂度 | $O(V^2)$ / $O(E\log V)$ | $O(V^3)$ | $O(VE)$ |
| 典型场景 | 导航、OSPF 路由 | 小图任意两点、传递闭包 | 汇率套利检测、有负权场景 |

补充：**SPFA** 是 Bellman-Ford 的队列优化（平均 $O(KE)$，最坏 $O(VE)$）；**无权图**用 BFS 即可（$O(V+E)$）。

### 1.5 0-1 背包与伪多项式时间 ⭐⭐⭐

**Q [⭐⭐⭐]【1.5.Q1】：0-1 背包的状态定义、转移方程和时间复杂度是什么？（北航真题）**

A：**问题**：n 件物品，第 i 件重 $w_i$、价值 $v_i$，背包容量 W，每件**要么全拿要么不拿**，求最大总价值。
**状态定义**：$dp[i][w]$ = **只考虑前 i 件物品、容量为 w 时能获得的最大价值**。
**转移方程**：

$$dp[i][w] = \begin{cases} dp[i-1][w], & w < w_i \\ \max\bigl(dp[i-1][w],\ dp[i-1][w-w_i] + v_i\bigr), & w \ge w_i \end{cases}$$

（含义：第 i 件**不拿**就是 $dp[i-1][w]$；**拿**就是 $dp[i-1][w-w_i]+v_i$，取两者较大。）
**边界**：$dp[0][w]=0$、$dp[i][0]=0$；**答案**：$dp[n][W]$。
**复杂度**：外层枚举 n 件物品、内层枚举容量 0~W，每次转移 O(1) → **时间 $O(nW)$**；空间二维 $O(nW)$，可用**滚动数组**压到 $O(W)$。

**Q [⭐⭐⭐]【1.5.Q2】：$O(nW)$ 是多项式时间复杂度吗？（北航真题）**

A：**不是，它是"伪多项式时间（pseudo-polynomial time）"**——这是本题最关键的考点。
理由：**复杂度的"多项式"是相对"输入规模（输入的长度、即编码位数）"而言的**。输入里表示容量 W 只需要 $\lceil \log_2 W\rceil$ 个二进制位，所以**输入长度只有 $O(\log W)$ 级别，而 W 本身可以是指数级大的数值**。写成输入长度的形式 $O(nW) = O(n \cdot 2^{\log W})$——**对输入长度而言是指数级**。直觉：容量从 W 变成 2W，输入只多 1 个二进制位，算法时间却翻倍。
**为什么必须澄清**：0-1 背包的**判定版本**（"是否存在价值 ≥ V 的装法"）是 **NP 完全**的；如果 $O(nW)$ 算多项式时间，就等于证明了 P = NP——所以它**不可能**是多项式时间。这也说明"背包是 NP 完全问题"与"有 $O(nW)$ 算法"并不矛盾：**弱 NP 完全问题**允许存在伪多项式算法。
**特例**：若题目保证 $W$ 是 n 的多项式（$W = \text{poly}(n)$），则 $O(nW)$ 在这个受限输入类上就是多项式时间。

**Q [⭐⭐]【1.5.Q3】：为什么说"伪多项式"这个名字是合理的？**

A：因为它"**看起来是多项式**"——$O(nW)$ 对 n 和 W **数值**都是线性的、形式上和多项式一样；但一旦换成"**对输入长度**"的标准定义，就变回指数级。
关键区分：**数值大小（value）** vs **编码长度（bit length）**。任何"依赖于某个输入数值大小"的算法，如果那个数值可以用多项式位数的输入表示成指数级大小，它的复杂度就是伪多项式。同类例子：**素性判断的试除法 $O(\sqrt{n})$**（对输入长度 $\log n$ 是指数级）、**子集和问题**。
反过来，真正多项式时间的例子：**分数背包**用贪心 $O(n\log n)$（与 W 的大小无关）。

**Q [⭐⭐]【1.5.Q4】：0-1 背包的滚动数组优化为什么容量要倒序枚举？**

A：一维数组 `dp[j]` 表示"容量为 j 时的最大价值"，更新 `dp[j] = max(dp[j], dp[j-w[i]] + v[i])` 时，`dp[j-w[i]]` 必须是**上一层（还没考虑第 i 件物品）**的值。
**倒序**枚举 j（从 W 递减到 w[i]）时，`j - w[i] < j`，而这个较小下标在**本轮还没被更新**，读到的是上一层的值 → 每件物品**只用一次** → 正确实现 **0-1 背包**。
如果**正序**枚举，`dp[j-w[i]]` 已在**本轮**被更新过（即第 i 件物品可能已经被用过一次），相当于每件物品可以拿**无限次** → 变成了**完全背包**。**一个循环方向区分两个问题**，是极高频的追问点。

**Q [⭐⭐]【1.5.Q5】：0-1 背包和分数背包有什么区别？**

A：**0-1 背包**：物品不可分割，只能整体拿或不拿 → **必须用 DP**，$O(nW)$（伪多项式），且是 NP 完全的判定问题。**分数背包**：物品可以任意切分（拿一部分）→ **贪心即可最优**：按**单位价值（性价比）$v_i/w_i$ 从大到小**依次尽量装，装不下就切分填满 → $O(n\log n)$，是真正的**多项式时间**。
为什么贪心在 0-1 上失效：按性价比贪心可能"用一件小物品占掉了本该给另一件物品的空间"，无法通过交换证明最优（反例：容量 10，物品 A(10, 60)、B(5, 30)、C(5, 30) 之类，具体构造见详细版）。

### 1.6 数组名、数组指针与指针数组 ⭐⭐⭐

**Q [⭐⭐⭐]【1.6.Q1】：C 语言中数组名是什么类型？它和指针是一回事吗？（北航真题）**

A：`int a[5];` 中 **`a` 的类型是 `int[5]`（数组类型）**，**不是指针变量**——它是"数组对象的名字"，代表一整块连续内存。
但在**大多数表达式中数组名会"退化（decay）"成指向首元素的指针 `int*`**（值为首地址），所以 `a[i]` 等价于 `*(a+i)`、数组能传给形参是指针的函数。
**不是一回事**：数组名不是**左值**，**不能赋值、不能自增**；`sizeof(a)` 得到**整个数组**的字节数（`5*sizeof(int)` = 20），而 `sizeof` 一个指针是 8；"数组名就是常量指针"是**不严谨的说法**——值上像，类型与语义上不同。

**Q [⭐⭐⭐]【1.6.Q2】：数组名在什么情况下不会退化为指针？**

A：① **`sizeof(a)`**：得到整个数组的字节数（大小 = 元素个数 × 元素大小），而不是指针大小；② **`&a`**：得到"**指向整个数组的指针**" `int (*)[5]`，`&a + 1` 会跳过**整个数组**（20 字节），而 `a + 1` 只跳过**一个元素**（4 字节）。
（严格说还有字符串字面量初始化字符数组等情形，但面试答上面两条即可。）
**关键结论**：`a` 与 `&a[0]` 的**值相同**，但**类型不同**——`int*` 与 `int(*)[5]`；指针的值决定"指向哪"，指针的**类型**决定"加减 1 走多远、解引用取多少字节"。

**Q [⭐⭐⭐]【1.6.Q3】：数组名、数组首地址、数组指针有什么区别？（北航真题）**

A：

| 写法 | 类型 | `+1` 跳过 | 说明 |
|------|------|-----------|------|
| `a`（`int a[5]`） | `int[5]`，表达式中退化为 `int*` | 4 字节（一个元素） | 数组名，非左值，不能赋值/自增 |
| `&a[0]` | `int*` | 4 字节 | 数组**首地址**（首元素地址） |
| `&a` | `int (*)[5]` | **20 字节（整个数组）** | **数组指针**（指向整个数组） |
| `int (*p)[5]` | 指向"含 5 个 int 的数组"的**指针** | 20 字节 | 数组指针变量，`p = a;` 合法 |

一句话：**数组名**是数组对象的名字（退化为首元素指针）、**首地址**是首元素的地址（`int*`）、**数组指针**是指向整个数组的指针（`int(*)[N]`）——三者数值可能相同，但**类型不同、+1 的步长不同**。

**Q [⭐⭐]【1.6.Q4】：数组指针和指针数组有什么区别？**

A：看**运算符优先级**：`()` 和 `[]` 优先于 `*`。
- **数组指针** `int (*p)[5]`——括号先结合，`p` 是**指针**，指向"含 5 个 int 的数组"；`(*p)[i]` 访问元素，`p+1` 跳过 20 字节。
- **指针数组** `int *p[5]`——`[]` 先结合，`p` 是**数组**，有 5 个元素，每个元素是 `int*`；`p[i]` 本身是指针。
记忆：**"谁先结合谁是本质"**——先和 `[]` 结合就是数组，先和 `*` 结合（被括号括住）就是指针。

**Q [⭐]【1.6.Q5】：函数名、函数指针、函数入口地址有什么区别？（北航真题）**

A：**函数名**：类型是函数类型（如 `int(int,int)`），在表达式中**退化为函数指针**，`f` 与 `&f` 的值都是函数的入口地址。**函数入口地址**：函数被编译成一段代码，其**首字节地址**就是入口地址，是一个数值（地址）。**函数指针**：`int (*fp)(int,int) = f;` 是一个**变量**，保存入口地址，**可以赋值、可以放入数组/结构体、可以作为回调参数**，`(*fp)(1,2)` 与 `fp(1,2)` 等价。
一句话区别：**函数名不可赋值（是函数的名字，退化为地址）；函数指针是可赋值的变量（存的正是那个地址）；入口地址是那段代码的起始地址（一个数值）**。

**Q [⭐⭐]【1.6.Q6】：数组作为函数参数时会退化成什么？怎么在函数内求数组长度？**

A：`void f(int a[5])`、`void f(int a[])`、`void f(int *a)` **三者完全等价**——编译器只传**首地址**，形参退化为 `int*`。后果：① 函数内 `sizeof(a)` 得到的是**指针大小（8）**，不是数组大小（20）——"在函数里用 sizeof 求数组长度"是经典错误；② 想要真正的"整块数组"，必须显式写 `int (*a)[5]` 才不退化为 `int*`。
**正确做法**：把长度**另作参数传**（`void f(int a[], int n)`），这也是 C89 风格代码里到处传 `n` 的原因；或用**哨兵值**结尾；或包一层 `struct { int a[5]; }` 整体传。

### 1.7 struct 与 union ⭐⭐⭐

**Q [⭐⭐⭐]【1.7.Q1】：结构体（struct）和共用体（union）有什么区别和共同点？**

A：**共同点**：都由**多个不同类型成员**组成，都是用户自定义的复合类型，成员都用 `.`（指针用 `->`）访问，都可以定义变量/数组/指针。
**不同点**：
- **内存分配**：struct 给**每个成员各分配**空间（可能插入**对齐填充**）；union 让所有成员**共用同一块空间**（起始地址相同）。
- **大小**：struct ≥ 各成员之和（+填充）；union = **最大成员的大小**（向上取到最大对齐）。
- **同时有效**：struct 的成员**同时存在、互不干扰**；union 同一时刻**只有一个成员有效**，**新的赋值会重写覆盖**旧成员（同一块内存被重新解释）。
- **用途**：struct 用于"把多个属性打包成一个整体"；union 用于"多个成员**互斥复用**内存"（省内存、协议解析、类型双关）。
- **初始化（C89）**：struct 可按顺序初始化所有成员；union **只能初始化第一个成员**（C99 起可用指定初始化器）。

**Q [⭐⭐]【1.7.Q2】：struct 和 union 的大小分别怎么算？**

A：`struct S { char c; int i; };` 通常 **sizeof = 8**：`c` 占 1 字节，为让 `i` 按 4 字节对齐要**填充 3 字节**，再加 `i` 的 4 字节 = 8；结构体总大小还要补到**最大成员对齐数的整数倍**。
`union U { char c; int i; };` 通常 **sizeof = 4**：取最大成员（int = 4），并满足最大对齐。
**内存对齐规则**：每个成员的偏移量必须是其自身大小的整数倍；结构体总大小是最大成员对齐数的整数倍。所以 `struct { char c; int i; }` 是 8 而不是 5；把小的成员排在一起（如 `{int i; char c; char d;}` 之类）可以**减少填充**、省内存。

**Q [⭐⭐]【1.7.Q3】：union 有什么实际用途？**

A：① **判断大小端**：

```c
union { unsigned int i; unsigned char c[4]; } u;
u.i = 1;
if (u.c[0] == 1) printf("小端\n"); else printf("大端\n");
```

（小端时低位字节存在低地址，`c[0]` 就是 1；大端反之。）
② **协议/报文解析**：同一段字节按不同格式解释（如 4 字节整体 vs 2 个 `short`）；③ **嵌入式省内存**：多个互斥字段复用一块空间；④ **类型双关（type punning）**：用同一块内存按不同类型读取/写入——注意这依赖**字节序与平台对齐**，行为是实现定义的，**跨平台不可靠**。

### 1.8 static 关键字的作用 ⭐⭐⭐

**Q [⭐⭐⭐]【1.8.Q1】：static 修饰全局变量、局部变量、函数分别有什么作用？**

A：要分**链接属性**和**存储期**两层说：

| 修饰对象 | 作用 | 要点 |
|----------|------|------|
| **全局变量** | 外部链接 → **内部链接** | 只对**本文件**可见，其他文件即使 `extern` 也访问不到；用于隐藏实现、避免命名冲突 |
| **函数** | 外部链接 → **内部链接** | 只在**定义它的文件内**可调用（所以头文件里声明给外部用的函数不能加 static） |
| **局部变量** | 改变**存储期**（作用域**不变**） | 从自动存储期改为**静态存储期**：存静态数据区而非栈，函数返回后**值保留**；**初始化只做一次**；未初始化则**自动为 0** |

**Q [⭐⭐]【1.8.Q2】：static 局部变量和普通局部变量有什么区别？**

A：

| 维度 | 普通局部变量 | static 局部变量 |
|------|--------------|-----------------|
| 存储位置 | **栈**（自动存储期） | **静态数据区**（.data/.bss，静态存储期） |
| 生存期 | 函数返回即销毁 | **整个程序运行期** |
| 初值 | 未初始化是**垃圾值** | 未初始化**自动置 0** |
| 初始化次数 | 每次进函数都重新初始化 | **只在程序启动时初始化一次** |
| 作用域 | 块内 | 块内（**不扩大**，外面仍看不见） |
| 线程安全 | 各自独立、安全 | **多线程共享 → 需加锁或改用线程局部存储** |

**Q [⭐⭐]【1.8.Q3】：C++ 中 static 还有什么含义？**

A：在 C++ 里 `static` 还能修饰**类成员**：① **静态成员变量**——属于**类**而不是某个对象，所有对象**共享一份**，不占对象空间（除了可能的 padding），必须在**类外定义并初始化**；② **静态成员函数**——**没有 `this` 指针**，不能访问非静态成员（也无法是虚函数），可用 `类名::函数名()` 直接调用。
另外 C++11 起**函数内 static 局部变量的初始化是线程安全的**（C 不保证），所以"局部 static 做单例延迟初始化"在 C++ 中是常见写法。

### 1.9 面向对象的三大特性 ⭐⭐⭐

**Q [⭐⭐⭐]【1.9.Q1】：面向对象的三大特性是什么？各自的含义是什么？（北航真题）**

A：**封装、继承、多态**（有的教材再加"抽象"成为四大）。
- **封装**：把**数据**与**操作数据的函数**捆绑在一起，对外只暴露必要接口、隐藏实现细节（`private`/`protected`/`public`）→ 降低耦合、防止外部随意改动内部状态。
- **继承**：子类**复用**父类的属性与方法并加以扩展/覆盖，描述 **is-a** 关系 → 代码复用、层次化建模、便于扩展。
- **多态**：**同一接口**在不同对象上表现出**不同行为**，调用哪个实现由对象的**动态类型**决定 → 解耦调用者与实现，便于替换和扩展（开闭原则）。
（**抽象**：提取一类事物的共性形成接口，是三者共同服务的目标。）

**Q [⭐⭐⭐]【1.9.Q2】：多态是怎么实现的？**

A：多态分两类：
- **编译期多态（静态绑定）**：函数**重载**（同名不同参数）、**模板/泛型**、运算符重载——编译时就确定调用哪个；
- **运行期多态（动态绑定）**：**虚函数**——运行时根据对象的**实际类型**决定调用哪个实现。
C++ 的实现机制通常是"**虚函数表 vtable + 虚指针 vptr**"：含虚函数的类在编译期生成一张**虚函数表**（每个类一张，表中放各虚函数的地址）；对象内存布局的开头（常见实现）存一个指向该表的**虚指针 vptr**；通过**基类指针/引用**调用虚函数时，运行期沿 `vptr → vtable → 对应槽位` 取出函数地址再调用，这就是**动态绑定**。
**推论**：构造函数/析构函数中调用虚函数**不会**触发多态（此时 vptr 还指向基类）；虚函数带来一次间接跳转的开销，且对象要多存一个 vptr。

**Q [⭐⭐]【1.9.Q3】：C 语言如何模拟面向对象？**

A：① **封装**：用结构体保存数据 + 一组操作它的函数；用 `static` 函数隐藏内部实现；用**不透明指针**（头文件里只声明 `struct Foo;` 不给定义，操作只能用提供的函数）实现真正的信息隐藏。
② **继承**：把"基类结构体"作为**第一个成员**内嵌进"派生类结构体"（如 `struct Circle { struct Shape base; double r; };`），利用"结构体首地址相同"做向上转型（把 `Circle*` 直接当 `Shape*` 用）。
③ **多态**：在结构体里放一个**函数指针表**（相当于自建 vtable，如 `struct ShapeOps { double (*area)(const struct Shape*); ... };`），不同对象初始化为不同函数；调用统一走 `s->ops->area(s)`。
这正是 Linux 内核、GLib/GObject、CPython 等 C 项目里"用 C 写面向对象"的标准手法。
（另：**封装/继承/多态的边界**——C 的"封装"只能靠约定（结构体成员其实都能被访问），不像 C++ 有编译期访问控制。）

## 2. 线性结构

### 2.1 数组与链表 ⭐⭐⭐

**Q [⭐⭐⭐]【2.1.Q1】：数组和链表有什么区别？各自的优缺点是什么？（北航真题）**

A：**存储**——数组是一块连续内存，链表是离散结点靠指针相连。
**访问**：数组支持**随机访问 O(1)**（地址 = 首地址 + 下标 × 元素大小）；链表必须从头遍历 **O(n)**。
**插入/删除**：数组要搬移元素 **O(n)**；链表已知前驱时只改指针 **O(1)**。
**空间**：数组无额外开销但要预留（可能浪费）；链表每结点多一个指针域。
**缓存**：数组**缓存友好**（连续存储、预取有效）；链表跳跃访问、命中率低。
**扩容**：静态数组不能扩，动态数组要整体拷贝；链表天然可增长。
一句话：**数组查快改慢，链表改快查慢**。

**Q [⭐⭐⭐]【2.1.Q2】：为什么数组的随机访问是 O(1)？**

A：因为数组元素地址可以**直接算出**：$\text{addr}(a_i) = \text{首地址} + i \times \text{sizeof}(T)$，一次乘加就定位，**与 i 无关**。链表要沿指针走 i 步，代价与 i 成正比，所以是 O(n)。这也是"数组支持随机访问、链表只支持顺序访问"的本质。

**Q [⭐⭐⭐]【2.1.Q3】：为什么说数组的缓存友好性更好？**

A：CPU 按 **cache line（典型 64 字节）** 为单位把内存搬进缓存。数组元素连续存放，访问一个元素时邻居会被顺带装入，且硬件预取器能识别顺序访问模式提前加载；链表结点散落在堆上，每次 `p = p->next` 都可能 **cache miss**，且无法预取。**结论**：虽然数组插入是 O(n)、链表是 O(1)，但常数因子与缓存效应常常让数组在实际中更快——"链表插入 O(1)"并不总是划算。

**Q [⭐⭐]【2.1.Q4】：什么场景用数组、什么场景用链表？**

A：**用数组**——以随机访问/查询为主、元素个数能估计、需要缓存友好的批量遍历（如动态数组 `std::vector`、哈希表桶、堆）。**用链表**——频繁在中间插入删除、元素个数变化剧烈且无法预估、不需要随机访问（如 LRU 链表、邻接表、内存分配器的空闲块表）。**折中方案**：跳表（链表 + 多级索引，Redis zset）、块状链表、动态数组（尾插摊还 O(1)）。

### 2.2 栈与队列 ⭐⭐⭐

**Q [⭐⭐⭐]【2.2.Q1】：栈和队列的定义与区别是什么？**

A：**栈**：只能在**栈顶**插入和删除的线性表，**LIFO 后进先出**，操作 `push/pop/top`，都是 O(1)。**队列**：**队尾入队、队头出队**的线性表，**FIFO 先进先出**，操作 `enqueue/dequeue`，都是 O(1)。
区别：**操作端不同**（栈同一端进出，队列两端）、**取出顺序不同**（后进先出 vs 先进先出）。共同点：都是"操作受限的线性表"，限制反而带来特定场景的高效。

**Q [⭐⭐⭐]【2.2.Q2】：栈有哪些典型应用？**

A：① **函数调用栈**——每次调用压入参数、返回地址、局部变量，返回时弹栈，**递归的本质就是利用调用栈**；② **表达式求值**——后缀表达式用一个栈即可计算（遇操作数入栈、遇运算符弹出两个数算完入栈；因为后缀式无括号、无优先级）；③ **中缀转后缀**——用运算符栈，遇 `(` 入栈、遇 `)` 弹到 `(`、遇运算符弹出优先级不低于它的栈顶再入栈；④ **括号匹配**；⑤ **DFS 的非递归实现**（用显式栈模拟递归）；⑥ 浏览器的前进/后退、编辑器的撤销/重做。

**Q [⭐⭐⭐]【2.2.Q3】：什么是循环队列？为什么需要它？怎么判空判满？**

A：顺序存储的队列出队后，队头前面会留下**无法再利用的空位**（假溢出），即使数组后面是空的也判不满——把数组首尾相接成"环"来复用空间即**循环队列**。
判空：`front == rear`。
判满：常用**牺牲一个存储单元**的办法：`(rear + 1) % size == front`（此时最多存 `size-1` 个元素）；也可维护计数器 `count`（`count == 0` 空、`count == size` 满）或标志位区分，这样不浪费单元。

**Q [⭐⭐]【2.2.Q4】：前缀、中缀、后缀表达式分别是什么？后缀表达式怎么求值？**

A：**中缀** `a + b * c`——运算符在操作数中间，需要优先级和括号；**后缀（逆波兰）** `a b c * +`、**前缀（波兰）** `+ a * b c`——运算符在操作数之后/之前，**不需要括号、不需要优先级规则**。
后缀求值：从左到右扫描，遇操作数**入栈**；遇运算符**弹出两个操作数**（先弹出的是右操作数），运算后把结果**压回栈**；扫描结束栈顶即结果。

### 2.3 堆、栈、队列的定义与区别 ⭐⭐⭐

**Q [⭐⭐⭐]【2.3.Q1】：堆、栈、队列三者有什么区别？**

A：

| 维度 | 栈 | 队列 | 堆 |
|------|-----|------|-----|
| 逻辑结构 | 受限线性表 | 受限线性表 | **完全二叉树**（非线性） |
| 取出规则 | LIFO 后进先出 | FIFO 先进先出 | 每次取**最值**（大根堆取最大） |
| 底层实现 | 数组 / 链表 | 循环数组 / 链表 | **数组**（靠下标关系，不存指针） |
| 插入 / 删除 | O(1) / O(1) | O(1) / O(1) | O(log n) / O(log n)（取顶 O(1)） |
| 顺序性 | 按时间完全有序 | 按时间完全有序 | **只有堆顶是最值**，兄弟无序 |
| 用途 | 递归、DFS、括号匹配、撤销 | BFS、调度、消息缓冲 | 优先队列、Top-K、堆排序、Huffman |

共同抽象：三者都在回答"**从哪里取元素**"——栈取最新、队列取最旧、堆取最值。

**Q [⭐⭐⭐]【2.3.Q2】：数据结构中的"堆"和操作系统内存中的"堆"是一回事吗？**

A：**不是，毫无关系**，只是英文都叫 heap。
**数据结构的堆**是一种满足堆序的完全二叉树（优先队列），解决"动态反复取最值"；
**操作系统内存的堆区**是进程地址空间中由 `malloc/free` 管理的一块内存，与"栈区"相对。
所以 `malloc` 返回的指针指向**内存堆区**，跟堆这种数据结构无关——面试时主动点明这一点是加分项。

**Q [⭐⭐]【2.3.Q3】：内存中的栈区和堆区有什么区别？**

A：

| 维度 | 栈区 stack | 堆区 heap |
|------|-----------|-----------|
| 管理者 | **编译器自动**分配/释放 | **程序员** `malloc/free` |
| 内容 | 局部变量、函数参数、返回地址 | 动态申请的对象/数组 |
| 生长方向 | 通常向**低地址** | 通常向**高地址** |
| 大小 | 小（几 MB） | 大（受虚拟内存限制） |
| 速度 | **快**（移动栈指针） | 慢（需查找空闲块，可能系统调用） |
| 典型问题 | 递归过深 → **栈溢出** | 内存泄漏、碎片、重复释放 |

## 3. 哈希表

### 3.1 哈希的定义与哈希函数 ⭐⭐⭐

**Q [⭐⭐⭐]【3.1.Q1】：什么是哈希（hash）？哈希表为什么能实现 O(1) 查找？**

A：**哈希（散列）**：用一个**哈希函数** $h$ 把关键字 $key$ 直接映射为存储地址 $h(key)$，查找时"算一下就知道在哪"，**无需逐个比较**。
**哈希表 = 数组 + 哈希函数 + 冲突解决策略**。
**为什么 O(1)**：它把寻址代价从"与元素个数 n 相关"变成"与 n 无关"——只要哈希函数把 key 均匀打散，平均查找长度就与 n 无关（**期望 O(1)**）。对比：有序数组二分是 $O(\log n)$、BST 是 $O(\log n)$。
注意是**平均 O(1)**，**最坏 O(n)**（所有 key 冲突到同一位置）。

**Q [⭐⭐]【3.1.Q2】：常见的哈希函数构造方法有哪些？设计原则是什么？**

A：**除留余数法** $h(k) = k \bmod m$（最常用，$m$ 取**质数**、避免取 $2^n$，分布更均匀）；**直接定址法** $h(k)=a\cdot k+b$（无冲突但要求 key 连续，浪费空间）；**数字分析法**（取 key 中分布均匀的若干位，如学号后几位）；**平方取中法**（取 $k^2$ 的中间几位，中间位受全体数字影响）；**折叠法**（长 key 分段相加）；**随机数法**。
设计原则：① 计算**快**；② 地址**分布均匀**（减少冲突）；③ 值域落在表长内。

**Q [⭐⭐⭐]【3.1.Q3】：哈希冲突能被完全避免吗？为什么？**

A：**不能**。由**鸽巢原理**：只要 key 的可能取值个数大于哈希表长度（实际场景必然如此，key 空间远大于表长），就必然有至少两个 key 映射到同一地址。好的哈希函数只能**减少**冲突概率、让分布更均匀，**不能消除**冲突——所以哈希表必须配一套冲突解决策略。

### 3.2 哈希冲突及解决方法 ⭐⭐⭐

**Q [⭐⭐⭐]【3.2.Q1】：什么是哈希冲突？有哪些解决方法？**

A：**冲突（碰撞）**：$key_1 \ne key_2$ 但 $h(key_1) = h(key_2)$，两者争同一个位置。
解决方法：① **链地址法（拉链法）**——同一位置的 key 用链表串起来；② **开放寻址法**——冲突时按探测序列找下一个空位；③ **再哈希法**——用第二个哈希函数重算地址；④ **建立公共溢出区**——冲突元素统一放到溢出区。
工程上最常用**链地址法**（Java `HashMap`、Go `map`）。

**Q [⭐⭐⭐]【3.2.Q2】：链地址法和开放寻址法各有什么优缺点？**

A：

| 方法 | 思想 | 优点 | 缺点 |
|------|------|------|------|
| **链地址法** | 同位置的 key 用链表串起 | 实现简单；不怕冲突多；删除方便；装载因子可 > 1 | 指针有额外开销；链过长退化为 O(n)（可升级为红黑树，如 Java 8 的 HashMap） |
| **开放寻址法** | 按探测序列找下一个空位 | 无指针开销、**缓存友好**、空间利用率高 | **删除麻烦**（要留"墓碑"标记）；聚集严重；装载因子必须 < 1 |

**Q [⭐⭐⭐]【3.2.Q3】：开放寻址法的三种探测策略有什么区别？**

A：① **线性探测** $h(k)+1, h(k)+2, \dots$——最简单，但会产生**一次聚集**（连续占位连成长块，之后任何映射到该块的 key 都要走很长探测链）；② **二次探测** $h(k) \pm 1^2, \pm 2^2, \dots$——减轻一次聚集，但存在**二次聚集**（哈希值相同的 key 走同一条探测序列）；③ **双重散列** $h_1(k) + i\cdot h_2(k)$——用第二个哈希函数决定步长，**分散最好**，接近理想随机探测，代价是多算一次哈希。

### 3.3 装载因子与扩容 ⭐⭐

**Q [⭐⭐⭐]【3.3.Q1】：什么是装载因子？它对性能有什么影响？**

A：**装载因子** $\alpha = \dfrac{\text{已存元素数}\,n}{\text{哈希表长度}\,m}$，衡量表的"满"的程度。$\alpha$ 越大 → 冲突越多 → 平均查找长度越长：
- **链地址法**：成功查找平均约 $1 + \alpha/2$，与 $\alpha$ 同阶，$\alpha$ 可以大于 1；
- **开放寻址法**：$\alpha$ **必须小于 1**（元素数不能超过表长），且 $\alpha$ 趋近 1 时探测次数急剧上升，通常 $\alpha > 0.7$ 就该扩容。
要点：**"平均 O(1)"的前提是好的哈希函数 + 合适的装载因子**。

**Q [⭐⭐]【3.3.Q2】：哈希表什么时候扩容？扩容的代价是多少？**

A：当 $\alpha$ 超过阈值（如 Java HashMap 的 **0.75**）时扩容：新建约 **2 倍**大小的表，把旧元素**逐个重新计算哈希**插入新表（rehash）。
单次扩容代价 **O(n)**，但触发间隔随表长翻倍，所以**摊还代价 O(1)**。扩容阈值是"空间 vs 时间"的折中：阈值太小 → 频繁扩容浪费内存与时间；太大 → 冲突多、查找变慢。

## 4. 树形结构

### 4.1 二叉树与三种遍历 ⭐⭐⭐

**Q [⭐⭐⭐]【4.1.Q1】：前序、中序、后序遍历的定义分别是什么？（北航真题）**

A：按"**访问根结点**的时机"命名：
- **前序（先序）**：**根 → 左子树 → 右子树**（根左右）；
- **中序**：**左子树 → 根 → 右子树**（左根右）；
- **后序**：**左子树 → 右子树 → 根**（左右根）。
（另有**层序**：逐层从左到右，用队列实现。）
三个名字里的"前/中/后"指的都是**根被访问的顺序**，左右子树的相对次序始终是"先左后右"。

**Q [⭐⭐⭐]【4.1.Q2】：三种遍历各有什么用途？**

A：**前序**：序列第一个必定是根 → 适合**复制/序列化整棵树**、输出目录树结构、前缀表达式。**中序**：对**二叉搜索树**而言中序序列是**递增有序**的 → 适合排序输出、判断是否 BST。**后序**：序列最后一个必定是根 → 适合**释放内存**（先释放左右子树再释放父结点）、统计子树规模、表达式求值（后缀式）。**层序**：求最短步数/BFS。

**Q [⭐⭐⭐]【4.1.Q3】：已知两种遍历序列，能唯一确定一棵二叉树吗？**

A：**前序 + 中序 → 能**（前序第一个是根，在中序中定位根即可切出左右子树，递归还原）；**后序 + 中序 → 能**（后序最后一个是根，同理）；**层序 + 中序 → 能**；但 **前序 + 后序 → 不能**——它只能确定根和子树集合，**无法区分左右**（当某结点只有一个孩子时，无法判断这个孩子是左还是右），结果可能对应多棵树。**结论：必须有中序**。

**Q [⭐⭐]【4.1.Q4】：层序遍历怎么实现？**

A：用**队列**：把根入队；循环"出队一个结点、访问它、把它的左右孩子依次入队"，直到队列为空。这样保证同一层的结点按从左到右的顺序被访问（BFS 在二叉树上的特例）。若要按层分组，可在每轮循环开始时记录当前队列大小 `n`，只处理这 n 个结点即为"一层"。

### 4.2 BST 的问题 → 平衡树的诞生 ⭐⭐⭐

**Q [⭐⭐⭐]【4.2.Q1】：什么是二叉搜索树（BST）？它的查找复杂度是多少？**

A：**BST（二叉搜索树 / 二叉排序树）**：对**任一**结点，其**左子树所有结点值 < 根 < 右子树所有结点值**（对整棵子树都成立，不只是直接孩子）。
复杂度 = **树高 $h$**：查找、插入、删除都是 $O(h)$——**平衡时 $O(\log n)$，退化成链时 $O(n)$**。所以 BST 的效率完全取决于树的形状，这正是不平衡树的痛点。

**Q [⭐⭐]【4.2.Q2】：BST 在什么情况下会退化？怎么解决？**

A：**退化场景**：按**有序序列**依次插入（1, 2, 3, …, n）时，每个新结点都成为右孩子，树变成一条单链，查找退化为顺序查找 $O(n)$。
**解决**：引入平衡机制——**AVL 树**（严格平衡，高度差 ≤ 1）、**红黑树**（近似平衡，最长路径 ≤ 2×最短路径），把树高稳定控制在 $O(\log n)$。此外还有 Treap、Splay、替罪羊树等。

**Q [⭐⭐⭐]【4.2.Q3】：AVL 树和红黑树有什么区别？**

A：

| 维度 | AVL 树 | 红黑树 |
|------|--------|--------|
| 平衡标准 | **严格**：任一结点左右子树高度差 ≤ 1 | **近似**：最长路径 ≤ 2 × 最短路径 |
| 树高 | 更低（约 $1.44\log n$） | 稍高（≤ $2\log n$） |
| 查找 | **更快**（树更矮） | 稍慢 |
| 插入删除 | 旋转**频繁**（可能一路旋转到根） | 旋转**少**（插入最多 2 次旋转，删除最多 3 次, 主要靠变色） |
| 适用 | **查找密集**、插删少 | **插删查混合**，工程默认 |

**Q [⭐⭐]【4.2.Q4】：为什么工程中多用红黑树而不是 AVL 树？**

A：因为真实负载是**插删查混合**：AVL 为了维持"高度差 ≤ 1"这一严格条件，插入/删除后可能要沿路径连续旋转，**维护平衡的代价高**；红黑树允许"最长 ≤ 2 倍最短"的宽松平衡，插入最多 2 次、删除最多 3 次旋转即可修复（其余靠**变色**），**插删均摊代价更低**，而查找只比 AVL 慢常数级。因此 STL `map/set`、Java `TreeMap`、Linux CFS 调度器、epoll 的红黑树索引都用红黑树。

### 4.3 堆（优先队列）⭐⭐⭐

**Q [⭐⭐⭐]【4.3.Q1】：什么是堆？堆和二叉搜索树有什么区别？**

A：**堆**是一棵**满足堆序性质的完全二叉树**：**大根堆**中每个结点 ≥ 其孩子（根是全局最大），**小根堆**反之。
与 **BST 的关键区别**：BST 保证的是"左 < 根 < 右"的**全序关系**，因此能有序查找、中序输出有序序列；堆只保证"父 ≥ 子"的**偏序关系**，**左右孩子之间没有大小关系**，所以堆**不能**做有序查找、**不能**中序输出有序序列。堆擅长的是**反复取最值**，BST 擅长的是**查找与有序遍历**。

**Q [⭐⭐]【4.3.Q2】：堆为什么用数组存储？父子下标关系是什么？**

A：因为堆是**完全二叉树**，除最后一层外每层都填满、最后一层从左到右连续，**没有空洞**，所以可以按层序连续存进数组，用**下标算术**代替指针——空间最省（无指针开销）、缓存友好（连续访问）、便于回溯父结点。
下标关系：**从 1 开始**时 `parent(i)=i/2`、`left(i)=2i`、`right(i)=2i+1`；**从 0 开始**时 `parent(i)=(i-1)/2`、`left(i)=2i+1`、`right(i)=2i+2`。结点总数 n 时，**最后一个非叶结点**是 `n/2 - 1`（0 起）。

**Q [⭐⭐⭐]【4.3.Q3】：堆的插入、删除、建堆分别怎么实现？复杂度多少？**

A：① **插入**：把新元素放到数组**末尾**（保持完全二叉树），然后**向上调整（上浮 sift-up）**——若比父大就交换，直到满足堆序，**O(log n)**；
② **删除堆顶**：把**末尾元素补到堆顶**，堆长度减 1，然后**向下调整（下沉 sift-down）**——在两个孩子中选较大的交换，直到满足堆序，**O(log n)**；取堆顶本身是 **O(1)**；
③ **建堆**：从**最后一个非叶结点** `n/2-1` 开始向前对每个结点下沉，**O(n)**（不是 $O(n\log n)$：高度为 h 的结点约 $\frac{n}{2^{h+1}}$ 个，代价 $\sum_h \frac{n}{2^{h+1}}h = O(n)$——越靠下结点越多但下沉越浅，级数收敛）。

**Q [⭐⭐]【4.3.Q4】：堆排序的过程和复杂度是什么？**

A：① 先把整个数组**建成大根堆**（O(n)）；② 把**堆顶（当前最大值）与末尾元素交换**，堆长度减 1；③ 对新的堆顶做一次**下沉**（O(log n)）恢复堆序；④ 重复 ②③ 共 n-1 次 → 数组从后往前依次排好。
复杂度：**任何情况都是 $O(n\log n)$**（无最坏退化），空间 **O(1)**（原地）。缺点：跳跃访问、**缓存不友好**、常数比快排大，且**不稳定**。

**Q [⭐⭐]【4.3.Q5】：大根堆和小根堆分别用在什么场景？**

A：**大根堆**（根最大）→ 升序堆排序（每次把最大值甩到末尾）、求第 K 小、需要快速取最大值的调度场景。**小根堆**（根最小）→ **Top-K 最大元素**（维护大小为 K 的小根堆，新元素比堆顶大就替换堆顶，$O(n\log K)$）、优先队列（按优先级最小的先出）、**Dijkstra 取最近点**、**Huffman 建树取两个最小权值**、**k 路归并取最小**。

## 5. 图

### 5.1 图的存储方法 ⭐⭐⭐

**Q [⭐⭐⭐]【5.1.Q1】：数据结构中存储图有哪些方法？**

A：① **邻接矩阵**：二维数组存边权（无边存 0 / ∞），"行 = 出边、列 = 入边"；② **邻接表**：每个顶点一个链表，存所有邻接点（带权再加权域）；③ **逆邻接表**：存"哪些顶点指向我"，方便求有向图的**入度**；④ **边集数组**：只存所有边 `(u, v, w)`；⑤ **十字链表**：有向图专用，每个弧结点同时挂在"出边链"和"入边链"上；⑥ **邻接多重表**：无向图专用，每条边只对应一个结点、被两端共享，便于删边；⑦ **链式前向星**：用 `head[]/nxt[]/to[]/w[]` 数组模拟邻接表（竞赛与工程常用，无指针、缓存友好）。

**Q [⭐⭐⭐]【5.1.Q2】：邻接矩阵和邻接表有什么区别？分别适合什么图？**

A：

| 维度 | 邻接矩阵 | 邻接表 |
|---|---|---|
| 空间 | $O(V^2)$ | $O(V+E)$（稀疏时省很多） |
| 查边 | **O(1)**（直接下标） | O(度数)（要遍历该点链表） |
| 遍历全部边 | O(V²) | O(V+E) |
| 适用 | **稠密图**（$E$ 接近 $V^2$）、需频繁判边、Floyd | **稀疏图**（绝大多数实际场景） |
| 缺点 | 稀疏图浪费空间 | 判边慢；有向图求入度不便（需逆邻接表） |

一句话：**实际中大多数图是稀疏的（如社交网络人均好友几百），用邻接表**；只有稠密图或需要 O(1) 判边才用矩阵。

**Q [⭐⭐]【5.1.Q3】：邻接矩阵有哪些值得注意的性质？**

A：① **无向图**的邻接矩阵**对称**（$a_{ij}=a_{ji}$），可只存上三角压缩空间；② **有向图**中**行和 = 出度、列和 = 入度**；③ **$A^k$ 的第 $(i,j)$ 元素 = 从 i 到 j 长度为 k 的通路条数**（所以 $A^k$ 非零对角元素可判断回路）；④ 带权图用 ∞ 表示无边，用 Floyd 时要注意 **∞ + ∞ 溢出**。

**Q [⭐]【5.1.Q4】：十字链表、邻接多重表、链式前向星分别解决什么问题？**

A：**十字链表**（有向图）：邻接表求入度要遍历全表、逆邻接表求出度要遍历全表，十字链表让每个弧结点同时属于"出边链"和"入边链"，**出度入度都能快速求**。**邻接多重表**（无向图）：邻接表里一条无向边存了两份（u 的表和 v 的表各一），删边要删两处；邻接多重表让**每条边只对应一个结点、被两端共享**，删边只需 O(1)。**链式前向星**：用数组模拟邻接表（`head`/`nxt`/`to`/`w`），避免动态指针、内存连续、缓存友好，是竞赛与工程里最常用的建图方式。

### 5.2 深度优先与广度优先遍历 ⭐⭐⭐

**Q [⭐⭐⭐]【5.2.Q1】：深度优先遍历（DFS）和广度优先遍历（BFS）的定义是什么？**

A：**DFS（深度优先遍历）**：从某顶点出发，沿一条分支**尽可能深入地走**，走到不能再深入（无未访问邻接点）就**回溯**到上一个还有未访问分支的顶点继续深入；**每个结点只访问一次**。
**BFS（广度优先遍历）**：从起点出发**按层系统地扩散**——先访问所有距离为 1 的顶点，再访问距离为 2 的……直到所有可达顶点都被访问（"彻底地搜索整张图，直到找到结果"）。两者都要求"每个顶点只访问一次"，实现上靠 `visited[]` 数组标记。

**Q [⭐⭐⭐]【5.2.Q2】：DFS 和 BFS 各自有什么特点？分别用什么数据结构实现？**

A：

| 维度 | DFS | BFS |
|---|---|---|
| 数据结构 | **栈**（递归调用栈 / 显式栈） | **队列** |
| 访问顺序 | 一根筋到底，再回溯 | 一层一层向外扩散 |
| 空间 | O(最长路径/树高)，深时**可能栈溢出** | O(最宽一层的顶点数) |
| 最短路 | **不保证** | 无权图**得到最短路** |
| 典型应用 | 连通分量、环检测、拓扑排序、割点/桥、回溯求解（全排列、N 皇后、迷宫所有解） | 无权最短路/最短步数、层次遍历、二分图判定、社交网络 N 度好友、洪泛爬虫 |

共同点：**两者都是所有图算法的基础**，复杂度都是 **O(V+E)**（邻接表）/ O(V²)（邻接矩阵）。

**Q [⭐⭐⭐]【5.2.Q3】：为什么 BFS 能求无权图最短路而 DFS 不能？**

A：BFS 按"距离起点 1、2、3…"的**层序**扩展，第一次到达某顶点时走的必然就是**最少边数**的路径（队列保证"先发现的先扩展"）；DFS 可能先沿一条很长的路径到达目标才从短路径到达，而且它**不回溯重算**，所以**不保证最短路**。
注意：BFS 只对**无权图（或边权全相等）**给最短路；**带权图**要用 Dijkstra（非负权）或 Bellman-Ford / Floyd。

**Q [⭐⭐]【5.2.Q4】：DFS 和 BFS 的时间复杂度与应用场景是什么？**

A：**复杂度**：邻接表 **O(V+E)**（每个顶点和每条边各访问常数次）；邻接矩阵 O(V²)（要扫描整行）。
**选谁**：求**最短步数/最少层数** → BFS；求**所有解/是否存在解/连通性/拓扑序/环** → DFS（写起来短）。**工程注意**：DFS 深度大时会**栈溢出**（如 10⁵ 层的递归），要么改显式栈、要么改 BFS；BFS 在"宽度极大"的图上队列会**爆内存**（如层的结点数极大），此时用双向 BFS 或迭代加深。

## 6. 排序算法

### 6.1 常见排序算法对比 ⭐⭐⭐

**Q [⭐⭐⭐]【6.1.Q1】：常见排序算法的时间复杂度、空间复杂度和稳定性分别是什么？（北航真题）**

A：

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|------|------|------|------|------|
| 冒泡 | O(n²) | O(n²) | O(1) | ✅ | 简单；加 flag 提前退出后最好 O(n) |
| 选择 | O(n²) | O(n²) | O(1) | ❌ | 交换次数最少（n-1 次） |
| 插入 | O(n²) | O(n²) | O(1) | ✅ | **近似有序时接近 O(n)** |
| 希尔 | O(n^1.3) | O(n²) | O(1) | ❌ | 插入排序的增量改进 |
| 快排 | **O(n log n)** | O(n²) | O(log n) | ❌ | **实际最快** |
| 归并 | O(n log n) | O(n log n) | O(n) | ✅ | **稳定排序首选**、外排基础 |
| 堆排 | O(n log n) | O(n log n) | O(1) | ❌ | 原地、无最坏退化、缓存不友好 |
| 计数 | O(n+k) | O(n+k) | O(n+k) | ✅ | 非比较，要求 key 是小范围整数 |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ | 非比较，按位 d 轮稳定排序 |

**Q [⭐⭐⭐]【6.1.Q2】：快速排序的过程是什么？为什么它是实际最快的排序？**

A：**过程**（分治）：① 选一个**基准 pivot**；② **分区（partition）**——把序列调整成"左边都 ≤ pivot、右边都 ≥ pivot"，pivot 落到最终位置；③ 对左右两个子区间**递归**同样处理。
**为什么实际最快**：① **原地排序**（不用辅助数组）；② 内层循环极其简单、**常数因子小**；③ **缓存友好**（顺序扫描连续数组，局部性好）；④ 平均 $O(n\log n)$（$T(n)=2T(n/2)+O(n)$）。所以虽然渐近复杂度和归并/堆排同级，实测常数最小。

**Q [⭐⭐]【6.1.Q3】：快速排序的最坏情况是什么？怎么规避？**

A：**最坏 $O(n^2)$**：每次划分都极不均匀（如**已有序**的数组 + 固定取首元素为 pivot，划分退化成 1 : n-1，递归深度 n）。
**规避**：① **随机化选 pivot**；② **三数取中**（首、中、尾取中位数）；③ 小区间（如 ≤ 16）改用**插入排序**；④ 递归太深时转**堆排**。
这四条合起来就是 **Introsort**——`std::sort` 的工业实现，保证最坏 $O(n\log n)$。

**Q [⭐⭐]【6.1.Q4】：实际工程中怎么选择排序算法？**

A：**要求稳定** → 归并（或插入/冒泡）；**要求原地且最坏也 O(n log n)** → 堆排；**通用最快** → 快排（配随机化/Introsort）；**key 是小范围整数** → 计数 / 基数排序（可达线性）；**数据量极大、内存装不下** → **外部排序**（分块排序 + **多路归并**）；**小数组** → 插入排序（常数小）；**链表** → 归并（不需要随机访问）。

### 6.2 排序的稳定性 ⭐⭐⭐

**Q [⭐⭐⭐]【6.2.Q1】：什么是稳定排序？哪些排序是稳定的？（北航真题）**

A：**定义**：若待排序序列中**两个元素关键字相等**（$k_i = k_j$），排序**前后它们的相对次序保持不变**，则该排序算法**稳定**；否则不稳定。形式化：排序前 $i < j$ 且 $k_i = k_j$，排序后 i 仍排在 j 之前。
**稳定的**：冒泡、插入、**归并**、计数、基数。
**不稳定的**：选择、**快排**、**堆排**、希尔。
口诀：**"冒插归计基"稳定，其余三种比较排序都不稳定**。

**Q [⭐⭐⭐]【6.2.Q2】：为什么需要稳定的排序算法？举例说明。**

A：**多关键字排序**：先按**次要关键字**排一遍，再按**主要关键字**排一遍；第二轮**必须用稳定算法**才能保住第一轮的次序。
例：先按"成绩"排序，再按"班级"排序 —— 若用稳定算法，结果就是"**按班级分组、组内按成绩有序**"（一次稳定排序顶一次复合排序）；若用不稳定算法，同班级内部成绩顺序会被打乱。
其他场景：数据库 `ORDER BY` 常要求相等键保持原有顺序（结果可复现）；UI 上按价格排序商品时同价商品不应乱跳。

**Q [⭐⭐]【6.2.Q3】：快速排序为什么不稳定？**

A：因为**分区（partition）时会发生远距离交换**，会跨越相等元素。例：以首元素为 pivot 的划分中，序列 `[3a, 3b, 1]` 会把 1 与 3a 交换（或把 3a 甩到右侧），使 3a 与 3b 的相对次序颠倒。**根因**：快排靠"交换到对面"来分区，不是靠相邻移动。

**Q [⭐⭐]【6.2.Q4】：选择排序和堆排序为什么不稳定？**

A：**选择排序**：每轮把最小值与"未排序区首位"**交换**，这一交换会把首位那个元素甩到后方，跨越其它相等元素。反例：`[2a, 2b, 1]` → 第一轮把 1 与 2a 交换 → `[1, 2b, 2a]`，2a 与 2b 次序颠倒。
**堆排序**：取堆顶时把**堆顶与末尾元素交换**，末尾元素被拽到根再一路**下沉**，跨度极大，必然打乱相等元素的相对次序。
**共性**：两者都存在**远距离交换**（相隔很远的元素互换位置），而稳定排序（冒泡、插入）只做相邻移动、归并靠"相等取左半"。

### 6.3 二路归并排序 ⭐⭐⭐

**Q [⭐⭐⭐]【6.3.Q1】：二路归并排序的思想是什么？**

A：**二路归并排序（merge sort）**：把序列**两两对半**地分（所以叫"二路"），**递归**把左右两半各自排好，再把两个**有序子序列归并**成一个有序序列——是**分治思想**最标准的体现：**分、治、合**。
**归并（merge）过程**：两个指针分别指向两个有序段的头部，每次**取较小的那个**放进辅助数组（相等时**优先取左边**以保持稳定），某一路取完就把另一路剩余部分整体拷过去。**递归基**：区间长度 ≤ 1 时天然有序，直接返回。
复杂度递推：$T(n) = 2T(n/2) + O(n)$。

**Q [⭐⭐⭐]【6.3.Q2】：归并排序的时间复杂度和空间复杂度是多少？**

A：**时间**：任何情况下都是 **$O(n\log n)$**——递归式 $T(n)=2T(n/2)+O(n)$ 由主定理情形 2 得 $O(n\log n)$；用递归树理解：共 $\log n$ 层，每层合并的总代价是 O(n)，故 $n\log n$。**没有最坏退化**（这是相对快排的最大优势）。
**空间**：**$O(n)$** 的辅助数组（快排是 O(log n) 递归栈、堆排是 O(1)）——这是归并的主要缺点；此外递归实现还有 O(log n) 的调用栈。

**Q [⭐⭐⭐]【6.3.Q3】：归并排序是稳定的吗？为什么？**

A：**是稳定的**。关键在归并那一步写成 `if (a[i] <= a[j])` 取**左半**：当两个元素**相等**时优先取左半（即原序列中**靠前**的那一个），因此相等元素永远保持原有相对次序。
如果错写成 `if (a[i] < a[j])`（相等时取右半），就会变成**不稳定**——一个小符号决定稳定性，这是常被追问的细节。

**Q [⭐⭐⭐]【6.3.Q4】：多路归并是什么？为什么外部排序要用它？**

A：**外部排序**（数据量大到内存装不下）：① 把大文件切成若干能装进内存的块，**块内排序**后写回磁盘，得到若干**有序归并段（run）**；② 再对这些归并段做 **k 路归并**（同时合并 k 段），边读边写、只做**顺序 I/O**。
**为什么要多路**：归并的**趟数** $= \lceil \log_k m\rceil$（m 为归并段数），**k 越大趟数越少 → 磁盘 I/O 次数越少**——外部排序的瓶颈是 I/O 而不是 CPU，所以宁可增加内存比较次数来减少 I/O。
**代价与优化**：k 路每次要从 k 个候选里选最小，朴素比较是 O(k)，可用**败者树**把每次选最小降到 $O(\log k)$，或直接用**小根堆**维护 k 个当前元素。这也是"堆"在海量数据场景的又一用途。

## 7. 算法思想专题

### 7.1 分治与动态规划的异同 ⭐⭐⭐

**Q [⭐⭐⭐]【7.1.Q1】：分治思想和动态规划思想的异同是什么？（北航真题）**

A：**相同点**：① 都基于"**把大问题分解为子问题**、递归/递推求解"的核心思想；② 都要求问题具备**最优子结构**（原问题的最优解包含子问题的最优解）；③ 都常用于求最优化问题，都能用递归表达式描述。
**不同点**：

| 维度 | 分治 | 动态规划 |
|------|------|----------|
| **子问题关系** | 相互**独立**、互不重叠 | **重叠**（同一子问题被多次求解） |
| 重复计算 | 会重复算（重叠时退化为指数级） | 用**表/记忆化**保证每个子问题只算一次 |
| 求解方向 | 自顶向下分解，再合并 | 通常**自底向上**递推（也可自顶向下记忆化） |
| 额外要求 | 最优子结构 + 子问题独立 | 最优子结构 + **重叠子问题** + **无后效性** |
| 典型问题 | 归并排序、二分查找、大整数乘法、Strassen | 0-1 背包、LCS、编辑距离、Floyd |

一句话：**区别的根子在"子问题是否重叠"，联系是"DP = 分治 + 记忆化"**。

**Q [⭐⭐⭐]【7.1.Q2】：为什么说"DP = 分治 + 记忆化"？**

A：因为两者的求解框架一样（都是"分解 → 求子问题 → 组合"），差异只在**子问题是否被重复求解**：
- 子问题**不重叠**时（如归并排序左右两半完全独立），分治直接递归即可，加记忆化只是徒增空间；
- 子问题**重叠**时，朴素分治会对同一个子问题反复求解，**代价爆炸**；此时把算过的子问题的解**存进表**（记忆化 / 递推填表），每个子问题只算一次 → 分治就"升级"为 DP。
所以 DP 不需要新的思想，只是在分治上加了"**存表避免重复**"这一步。

**Q [⭐⭐]【7.1.Q3】：举一个分治的子问题重叠后退化的例子。**

A：**斐波那契数列**：$F(n) = F(n-1) + F(n-2)$。
朴素递归直接照写：`fib(n) = fib(n-1) + fib(n-2)`——递归树里 $F(n-2)$ 会被算两次、$F(n-3)$ 被算三次……重复次数随 n 指数增长，时间复杂度 **$O(2^n)$**（准确说是 $O(\varphi^n)$，$\varphi = 1.618$）。
而 $F(n)$ 只有 n 个**不同的**子问题，所以加记忆化（或改成自底向上递推）后每个子问题只算一次 → **$O(n)$**。这就是"分治 → DP"的价值最直观的例子。类似例子：矩阵链乘、LCS 的朴素递归。

**Q [⭐⭐]【7.1.Q4】：动态规划需要满足哪两个条件？和贪心有什么关系？**

A：**两个条件**：① **最优子结构**——问题的最优解包含子问题的最优解（可以用子问题的最优解构造出原问题的最优解）；② **重叠子问题**——不同分支会反复求解同一子问题（有它才值得存表）。实践中还常要求**无后效性**（状态一旦确定，后续决策只依赖该状态、与到达它的路径无关），否则状态定义需要扩充。
**与贪心的关系**：贪心可以看作 DP 的**退化情形**——当"局部最优必然导向全局最优"（**贪心选择性质**成立）时，DP 的状态转移只依赖一个最优分支，于是不需要回头比较，每步直接选局部最优即可。所以：**贪心更快但适用范围更窄**，能用贪心必须能证明（常用**交换论证**）。反例：0-1 背包不能贪心、分数背包可以。

## 8. C 语言基础（面试常问）

### 8.1 for(a;b;c) 的三个表达式 ⭐⭐

**Q [⭐⭐⭐]【8.1.Q1】：for(a;b;c) 中 a、b、c 各自的含义和执行时机是什么？**

A：

| 表达式 | 名称 | 含义 | 执行时机 |
|--------|------|------|----------|
| `a` | 初始化表达式 | 进入循环体**之前**做的准备（如 `i = 0`） | **仅执行一次** |
| `b` | 条件表达式 | 判断是否继续循环，非 0 为真 | 每轮**进入循环体前**求值一次 |
| `c` | 步进表达式 | 循环体结束后的收尾（如 `i++`） | 每轮**循环体执行完**（含 `continue` 跳过后）执行一次 |

**执行顺序**：`a → b → body → c → b → body → c → …` 直到 b 为假。
整体等价于 `{ a; while (b) { body; c; } }`——注意差别在于 **`continue` 会跳到 `c`**，而 while 版本的 `continue` 会跳过步进。

**Q [⭐⭐]【8.1.Q2】：for 的三个表达式都可以省略吗？省略后等价于什么？**

A：**都可以省略，但两个分号不能省**：
- `for (;;)` ≡ `while (1)`——`b` 为空视为**恒真**，是**死循环**，靠 `break` 退出；
- `for (; b;)` ≡ `while (b)`——`a`、`c` 都留空时两者**完全等价**（这是"for 与 while 等价"这句话成立的准确条件）；
- `for (a; b;)` ≡ `a; while (b) { body; }`——缺 `c` 时步进要自己写在循环体里；
- `for (a; ; c)`——`b` 空 ⇒ 死循环，但每轮仍执行 `c`。
**另一个易错点**：`a` 在 **C89 中不能是声明**（`for (int i = 0; …)` 是 C99 才有的语法）——北航机试要求 `-std=c89`，所以循环变量必须在 `for` 之前声明。

**Q [⭐⭐]【8.1.Q3】：break 和 continue 对 for 的 c 表达式有什么影响？**

A：**`break`**：立刻跳出整个循环，**不再执行 `c`**，程序从循环后面继续。**`continue`**：只跳过本次循环体内**剩余**的语句，**仍会执行 `c`**，然后回到 `b` 判断是否进入下一轮。这正是 `for(;;)` 与"手写 while"在语义上的差别：在 while 里 `continue` 会跳过你写在循环体末尾的步进语句，容易写成死循环；用 `for` 把步进放在 `c` 位置就不容易出这个错。

### 8.2 #define 与 const ⭐⭐

**Q [⭐⭐⭐]【8.2.Q1】：#define 和 const 声明的常量有什么区别？**

A：

| 维度 | `#define` | `const` |
|------|-----------|---------|
| 处理阶段 | **预处理**：做**文本替换** | **编译**阶段，是真正的变量（对象） |
| 类型 | **无类型** | **有类型**，编译器做类型检查 |
| 作用域 | 从定义处到 `#undef` 或文件末尾（**无视块作用域**） | 遵循 C 的作用域规则 |
| 存储 | 不占空间（编译后名字不复存在） | 通常占空间（可被优化掉），**可以取地址 `&MAX`** |
| 调试 | 调试器看不到该符号 | 可见、可查看值 |
| 安全性 | **低**（不查类型、要手动加括号） | **高**，一旦初始化就不可修改 |

**结论**：`#define` 是**简单的替换**，`const` 是一个**常量**、一旦声明就**无法修改，安全性更高**——所以常量优先用 `const`（或 `enum`），`#define` 留给**条件编译、头文件保护、字符串化/拼接**等 `const` 做不到的场景。
（可能被追问：C 中文件作用域的 `const` 默认是**外部链接**（与 C++ 相反）；C89 里 `const int n = 10; int a[n];` **不能**用于数组长度——它不是常量表达式，C99 才允许，且那实际上是 VLA。）

**Q [⭐⭐]【8.2.Q2】：用 #define 定义函数宏有什么陷阱？**

A：① **缺少括号**：

```c
#define SQR(x) x * x           /* 危险 */
SQR(1 + 2)                     /* 展开成 1 + 2 * 1 + 2 = 5，不是 9 */
#define SQR_OK(x) ((x) * (x))  /* 正确：参数和整体都要加括号 */
```

② **参数被重复求值**：`SQR_OK(i++)` 里 `i++` 出现了两次，`i` 会自增两次——宏**无法避免重复求值**，这类场景应改用 `static inline` 函数或 `_Generic`；③ **结尾别写分号**：`#define MAX 100;` 会让 `if (x > MAX)` 展开成 `if (x > 100;)` 编译错误；④ 没有类型检查、无法调试、无法取地址。

### 8.3 全局变量与局部变量重名 ⭐⭐

**Q [⭐⭐⭐]【8.3.Q1】：全局变量和局部变量可以重名吗？局部怎么访问全局变量？**

A：**可以重名**——C 允许内层作用域的同名声明**遮蔽（shadow）**外层的同名标识符。
**直接访问只能得到局部变量**：名字解析的规则是"**从最内层作用域开始逐层向外查找**"，函数体内直接用 `x` 只会命中局部变量。
**局部要访问被遮蔽的全局变量**：C **没有** C++ 的**作用域解析运算符 `::`**，所以不能写 `::x`。可行手段有：
① **给全局变量改个不会冲突的名字**（工程上最常用：全局加前缀 `g_`，局部用小写）；
② 在**内层块**里再写一次 `extern` 声明，让它重新指回文件作用域的变量：

```c
int x = 1;                         /* 全局 */
void f(void)
{
    int x = 2;                     /* 局部，遮蔽全局 */
    {
        extern int x;               /* 本层的 x 重新引用文件作用域的 x */
        printf("%d\n", x);          /* 输出 1 */
    }
    printf("%d\n", x);              /* 输出 2 */
}
```

③ 通过函数/指针把全局变量**接口化**暴露出来。

**Q [⭐⭐]【8.3.Q2】：在 C 语言中用 `::x` 能访问全局变量吗？（⚠️ 勘误）**

A：**不能**。`::` 是 **C++ 的作用域解析运算符**，在 C 语言里是**语法错误**。
如果参考资料写"`::x` 可以访问全局变量 x"，那是 **C++ 的规则**，（本笔记有意更正）——**在 C 中必须换名字、或用内层 `extern` 声明技巧、或把全局变量接口化**。面试时务必说清"**C 不支持 `::`，C++ 才有**"，否则被追问时会露怯。

**补充**：① 形式参数**也是局部变量**，与函数体内**同一作用域**的变量不能重名（内层块可以重名）；② 全局变量与 `static` 全局变量重名会冲突（同一作用域内重复定义）；③ 局部遮蔽全局后，其他文件里用 `extern` 引用的那个全局变量**不受影响**（别的文件里没有这个局部变量）。

### 8.4 变长参数函数 ⭐⭐⭐

**Q [⭐⭐⭐]【8.4.Q1】：C 语言如何写一个变长参数函数？**

A：用 `<stdarg.h>` 提供的 `va_list` / `va_start` / `va_arg` / `va_end`：

```c
#include <stdio.h>
#include <stdarg.h>

int sum(int n, ...)              /* n 是后续参数的个数，由调用者保证正确 */
{
    va_list ap;
    int i, s = 0;

    va_start(ap, n);             /* 以最后一个具名参数 n 为基准初始化 */
    for (i = 0; i < n; i++)
        s += va_arg(ap, int);    /* 取一个 int，并让 ap 前进 */
    va_end(ap);                  /* 必须调用 */
    return s;
}
```

**三条硬性规则**：① **必须至少有一个具名参数**（`va_start` 要靠它定位后续参数，所以 `int f(...)` 非法）；② **必须自己知道参数个数与类型**（C 运行期无从得知——`printf` 靠格式串、`sum` 靠计数 n、`execl` 靠末尾的 NULL 哨兵）；③ **`va_arg` 写的类型必须与实际实参"提升后"的类型一致**，否则是未定义行为。省略号只能放**参数表最后**。

**Q [⭐⭐⭐]【8.4.Q2】：va_start / va_arg 的原理是什么？**

A：函数调用时参数按**调用约定**放到约定位置：x86-64 SysV 下前 6 个整型参数依次进 `rdi, rsi, rdx, rcx, r8, r9`，其余压栈；x86-32 的 `cdecl` 下全部**从右向左**压栈。
`va_start(ap, last)` 根据**最后一个具名参数**的位置，推算出"变长部分的起点"并记录在 `ap` 里；`va_arg(ap, T)` 按类型 T 的大小**读出值、并让 ap 前进到下一个参数**；`va_end` 做清理。
**本质**：变长参数就是"**按地址顺序依次取参数**"——所以**必须在参数个数可推断的前提下才安全**，这正是 C 变长参数"不安全"的根源（无编译期检查、个数或类型对不上就是 UB）。
需要**多次遍历**参数时要先用 `va_copy` 复制一份 `va_list`（因为 `va_arg` 会破坏原 `va_list`）。

**Q [⭐⭐]【8.4.Q3】：变长参数函数有哪些坑？**

A：① **默认实参提升**：变长部分中 `char`、`short` 会**提升为 `int`**，`float` 会**提升为 `double`**——所以**不能写 `va_arg(ap, char)`（应写 int 再强转）、不能写 `va_arg(ap, float)`（应写 double）**，写错就取到错误字节、错位甚至崩溃；② **完全无类型检查**（`printf("%d", 3.14)` 是典型 UB）——GCC/Clang 可用 `__attribute__((format(printf, 1, 2)))` 让编译器按 printf 规则检查；③ **个数无法自动获知**，漏传哨兵/计数值会导致读到垃圾数据；④ 变长参数**不做类型提升之外的处理**，结构体传值、指针与 int 混用都可能出事。
**更安全的替代**：传"数组 + 长度"、传结构体指针、用哨兵值结尾。**易混点**：**变长参数（`...`）≠ 变长数组参数**（`int f(int n, int a[n])` 是 C99 的 VLA 参数，长度由前面的参数决定，与 `...` 无关）。

- [ ] **Prim 贪点**（`d[v]` = 到**树**的最小边权，$O(V^2)$，稠密图）；**Kruskal 贪边**（排序 + **并查集**判环，$O(E\log E)$，稀疏图）；依据 = **切割性质**
- [ ] **Prim 与 Dijkstra 的区别**：`d[v]` 是"到树的最小边权" vs "到起点的路径长"（松弛用 `w(u,v)` vs `dist[u]+w(u,v)`）
- [ ] **Dijkstra** 单源 + 贪心 + **非负权**；负权打破"取出即最终确定"的假设 → 改用 Bellman-Ford
- [ ] **Floyd** 全源 + DP：$d[i][j]=\min(d[i][j], d[i][k]+d[k][j])$，$O(V^3)$，**k 必须在最外层**（阶段变量）；可负权不可负环，`d[i][i]<0` 表示有负环
- [ ] 0-1 背包：$dp[i][w]=\max(dp[i-1][w], dp[i-1][w-w_i]+v_i)$，时间 $O(nW)$、空间可滚动到 $O(W)$；**容量倒序 = 0-1 背包，正序 = 完全背包**
- [ ] **$O(nW)$ 是伪多项式时间**：W 是**数值**不是**输入规模**（只需 $\log W$ 位），按输入长度看是指数级；否则 P = NP；分数背包贪心 $O(n\log n)$ 才是真多项式
- [ ] 数组名类型是 `int[5]`（非指针，不可赋值），表达式中**退化**为 `int*`；**例外：`sizeof(a)` 和 `&a`**
- [ ] `&a` 是 **`int(*)[5]`**，`&a+1` 跳过**整个数组**；`a+1` 只跳一个元素；三者值同、**类型不同**
- [ ] **数组指针 `int (*p)[5]`**（先结合 `*`）vs **指针数组 `int *p[5]`**（先结合 `[]`）
- [ ] 形参 `int a[5]` ≡ `int a[]` ≡ `int *a`（退化为指针，`sizeof` 得 8）→ 长度必须**另传参数**
- [ ] **函数名**退化为函数指针、**函数指针**是可赋值的变量、**入口地址**是那串代码的首地址
- [ ] struct 各成员**独立占空间**（有对齐填充）、union **共享一块内存**（大小 = 最大成员）、**新赋值覆盖旧值**
- [ ] `struct {char c; int i;}` 是 8（填充 3）；`union {char c; int i;}` 是 4；对齐 = 成员大小整数倍、总大小 = 最大对齐整数倍
- [ ] union 用途：**判大小端**（`u.i=1; u.c[0]==1` → 小端）、协议解析、类型双关
- [ ] static 全局/函数 → **内部链接**（只本文件可见）；static 局部 → **静态存储期**（值保留、只初始化一次、默认 0、**作用域不变**）；C++ 类 static 属于类、无 `this`
- [ ] 面向对象三特性：**封装**（捆绑 + 隐藏）、**继承**（复用 + is-a）、**多态**（同接口不同行为）；运行期多态靠**虚函数表 vtable + 虚指针 vptr**；C 用**函数指针表 + 基类结构体首成员**模拟

**其余章节**

- [ ] 数组 vs 链表：**随机访问 O(1) vs O(n)、插删 O(n) vs O(1)、缓存友好度**；地址公式 `首地址 + i × 元素大小`
- [ ] 栈 LIFO（一端进出）、队列 FIFO（两端进出）；循环队列判满 `(rear+1)%size == front`（牺牲一个单元）
- [ ] 后缀表达式求值：一个栈，遇操作数入栈、遇运算符弹两个算完入栈
- [ ] **堆、栈、队列**：栈/队列是受限线性表、堆是完全二叉树（取最值）；**内存的"堆区/栈区"与数据结构的堆无关**（只同名）
- [ ] 内存栈区（编译器管、小、快、栈溢出）vs 堆区（`malloc` 管、大、慢、泄漏碎片）
- [ ] 哈希 = 数组 + 哈希函数 + 冲突解决；**期望 O(1)、最坏 O(n)**；冲突**不可完全避免**（鸽巢原理）
- [ ] 冲突解决：**链地址法**（简单、α 可 > 1）/[**开放寻址法**（缓存友好、α < 1、删除要留墓碑）；探测策略：线性→一次聚集、二次→二次聚集、双重散列最好
- [ ] 装载因子 $\alpha = n/m$；开放寻址 $\alpha > 0.7$ 就扩容；扩容 2 倍 + rehash，摊还 O(1)
- [ ] 三种遍历：**前序根左右、中序左根右、后序左右根**；**前序+中序（后序+中序）可唯一还原，前序+后序不行**
- [ ] BST 退化成链的触发条件：**有序插入**；平衡手段 AVL（高度差 ≤ 1）／红黑树（最长 ≤ 2×最短）
- [ ] AVL 查找快、红黑树**旋转少插删快** → 工程多用红黑树（STL map/set、Java TreeMap）
- [ ] 堆用**数组**存（完全二叉树无空洞）；下标 0 起：`parent=(i-1)/2`、`left=2i+1`、`right=2i+2`
- [ ] 堆操作：插入**上浮**、删顶**下沉** O(log n)、**建堆 O(n)**；堆排 O(n log n) 原地不稳定；建堆从 `n/2-1` 开始
- [ ] 堆 vs BST：堆只有**偏序**（父≥子），不能有序查找/中序输出
- [ ] 图的存储：**邻接矩阵**（O(V²)、判边 O(1)、稠密图、Floyd）/ **邻接表**（O(V+E)、稀疏图、求入度不便）/ 边集数组（Kruskal）/ 十字链表（有向出入度）/ 邻接多重表（无向删边）
- [ ] 邻接矩阵：无向对称、**行和=出度列和=入度**、**$A^k$ 元素 = 长度 k 的通路条数**
- [ ] DFS 用**栈**、一根筋到底、不保证最短路、路径深会栈溢出；BFS 用**队列**、按层扩散、**无权图给最短路**；都是 **O(V+E)**
- [ ] 排序总表：快排平均 O(n log n)/最坏 O(n²)；归并稳定且永远 O(n log n) 但空间 O(n)；堆排原地 O(1) 不稳定
- [ ] 快排实际最快的原因：**原地 + 常数小 + 缓存友好**；最坏发生在**已有序 + 固定取首元素为 pivot**，用随机化/三数取中规避（Introsort）
- [ ] **稳定排序：冒泡、插入、归并、计数、基数**；不稳定：选择、快排、堆排、希尔
- [ ] 为什么要稳定：**多关键字排序**（先次要键、后主要键，第二轮稳定才能保住第一轮次序）
- [ ] 不稳定的根因：**远距离交换**（快排分区、选择排序交换、堆排堆顶与末尾交换）；归并靠 `<=` **相等取左半**保证稳定
- [ ] 二路归并 = 对半分 + 两个有序段合并；$T(n)=2T(n/2)+O(n)$；**稳定**（`a[i] <= a[j]` 取左）；空间 O(n)
- [ ] 外部排序 = 分块内排序 + **k 路归并**；k 越大**趟数越少 → 磁盘 I/O 越少**（瓶颈是 I/O），用**败者树/小根堆**优化选最小
- [ ] 分治 vs DP：**子问题独立 vs 重叠**；都要**最优子结构**；DP 还需**重叠子问题 + 无后效性**；**DP = 分治 + 记忆化**（fib 朴素 $O(2^n)$ → DP $O(n)$）
- [ ] `for(a;b;c)`：a 初始化（一次）、b 条件（每轮前）、c 步进（每轮后，**continue 也会执行**）；`for(;b;)` ≡ `while(b)`；`for(;;)` 死循环；**C89 中 a 不能是声明**
- [ ] `#define` 是**预处理文本替换**（无类型、无作用域、不查错、不可取地址），`const` 是**有类型的常量**（可检查、可取地址、安全）
- [ ] 宏陷阱：参数与整体都要加括号、`i++` 会被求值两次、结尾别写分号
- [ ] 全局与局部**可以重名**（遮蔽），直接访问只得到局部；**C 没有 `::`**（那是 C++），需改名字或内层 `extern`
- [ ] 变长参数：`va_list` + `va_start(ap, 最后一个具名参数)` + 循环 `va_arg` + `va_end`；**必须自备个数与类型**；char/short→int、float→double **提升**；`printf` 靠**格式串**
