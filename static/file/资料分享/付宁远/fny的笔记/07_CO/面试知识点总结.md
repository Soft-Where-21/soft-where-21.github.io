# 计算机组成（CO） - 保研面试知识点总结

> [!info]+ 复习策略
> CO 的核心逻辑是"硬件如何为软件提供支撑"。从最底层的数制运算到最上层的虚拟存储，每个层次都是"解决前一层的问题"——ALU 解决计算、流水线解决速度、Cache 解决速度差距、虚拟存储解决容量限制。面试时先想"它解决什么硬件瓶颈"，再展开细节。
>
> 重点标注：⭐⭐⭐ 高频 | ⭐⭐ 中频 | ⭐ 低频但重要
>
> 北航软院面试高频考点：局部性原理、虚拟内存/TLB、开机过程

---

> [!abstract]+ 学科总览
> CO 可以按照"从运算到存储"的逻辑分成两半：
>
> - **运算与控制**（第1-4章）：数的表示与运算 → 数字逻辑电路 → MIPS 汇编 → CPU 流水线。这条线回答"CPU 如何执行指令"——数制是语言，逻辑电路是工具，汇编是人和硬件的接口，流水线是提速手段。
> - **存储层次**（第5-8章）：主存 → Cache → 虚拟存储 → 链接。这条线回答"数据如何存取"——SRAM/DRAM 是物理层，Cache 是速度层，虚拟存储是容量+保护层，链接是软件层。
>
> 两半的关系：运算需要数据，数据来自存储——**流水线受限于访存速度，Cache 和虚拟存储就是为此而生的**。局部性原理是整条存储层次的共同根基。

---

## 1. 数制与运算

> [!note]+ 章节导引
> **本章知识点之间的关系**：计算机用二进制表示一切，但"怎么表示负数"和"怎么表示小数"是两个核心问题。逻辑链：**原码**（直观但运算麻烦）→ **反码**（过渡方案）→ **补码**（统一加减法，最终方案）→ **IEEE 754 浮点**（用科学计数法表示小数，精度与范围的权衡）。
>
> **与上一章的关系**：无（起点）。
>
> **与学科的关系**：数制是计算机"理解数字"的底层语言，补码和浮点是面试常考基础。

### 1.1 原码 / 反码 / 补码 ⭐⭐⭐

| 表示 | 正数 | 负数 | 0 的表示 | 加法 |
|------|------|------|----------|------|
| **原码** | 符号位 0 + 绝对值 | 符号位 1 + 绝对值 | +0/-0 两种 | 不能直接加 |
| **反码** | = 原码 | 符号位 1 + 按位取反 | +0/-0 两种 | 循环进位 |
| **补码** | = 原码 | 反码 + 1 | **唯一零** | **直接加** |

> [!tip]+ 为什么用补码
> 补码把减法变加法（$A - B = A + (-B)$），且 0 的表示唯一。现代计算机一律用补码表示整数。

### 1.2 IEEE 754 浮点数 ⭐⭐⭐

$$(-1)^S \times 1.M \times 2^{E-\text{偏移量}}$$

- 单精度：1 符号位 + 8 阶码 + 23 尾数
- 双精度：1 符号位 + 11 阶码 + 52 尾数

> [!tip]+ 关键
> 阶码用**偏移码**（非补码），尾数的隐含 1 省了一位——这是精度与范围的经典权衡。

## 2. 数字逻辑基础

> [!note]+ 章节导引
> **本章知识点之间的关系**：逻辑电路是"用硬件实现运算"的工具。逻辑链：**组合逻辑**（输出只看当前输入：编码器、译码器、多路选择器、ALU）→ **时序逻辑**（输出还看历史：锁存器→触发器→寄存器）→ **有限状态机**（Moore vs Mealy，是 CPU 控制器的设计模型）。
>
> **与上一章的关系**：第1章定义了"运算规则"，本章实现"运算硬件"。
>
> **与学科的关系**：数字逻辑是 CPU 设计的基础，面试主要考 Moore vs Mealy 和 ALU 标志位。

### 2.1 组合 vs 时序 ⭐⭐

| | 组合逻辑 | 时序逻辑 |
|---|---|---|
| 输出依赖 | 仅当前输入 | 当前输入 + 历史状态 |
| 有记忆？ | 无 | **有**（锁存器/触发器） |
| 典型 | ALU、编码器、译码器 | 寄存器、计数器、FSM |

### 2.2 Moore vs Mealy ⭐⭐⭐

| | Moore 机 | Mealy 机 |
|---|---|---|
| 输出依赖 | **仅状态** | **状态 + 输入** |
| 输出变化 | 在时钟沿后 | 可在输入变化时立即变 |
| 状态数 | 通常更多 | 通常更少 |

## 3. MIPS 汇编与指令系统

> [!note]+ 章节导引
> **本章知识点之间的关系**：汇编是"人和硬件的接口"——人写汇编，硬件执行机器码。逻辑链：**三种指令格式**（R/I/J）→ **寻址方式**（立即数、基址+偏移、PC 相对、伪直接）→ **寄存器约定**（哪些由调用者/被调用者保存）→ **编程范式**（if/while/函数调用的汇编实现）。
>
> **与上一章的关系**：第2章的 ALU 和寄存器是本章指令的执行基础。
>
> **与学科的关系**：MIPS 是理解 CPU 工作原理的最佳教学 ISA，面试常考 R/I/J 格式和寄存器约定。

### 3.1 R / I / J 格式 ⭐⭐⭐

| 格式 | 操作码 | 域 | 典型指令 |
|------|--------|-----|----------|
| **R** | opcode=0 | rs, rt, rd, shamt, funct | add, sub, and, or, slt |
| **I** | opcode | rs, rt, immediate | addi, lw, sw, beq |
| **J** | opcode | target address | j, jal |

> [!tip]+ RISC vs CISC
> MIPS 是 RISC（指令少而规整，定长编码），x86 是 CISC（指令多而复杂，变长编码）。RISC 更适合流水线。

## 4. CPU 与流水线

> [!note]+ 章节导引
> **本章知识点之间的关系**：流水线是 CPU 提速的核心技术，但它引入了新的问题。逻辑链：**理想流水线**（5 级：IF/ID/EX/MEM/WB，CPI=1）→ **三种冒险**（结构冒险→数据冒险→控制冒险）→ **解决冒险**（前递/旁路、Load-Use 暂停、分支预测）。前递解决大部分数据冒险，分支预测解决控制冒险。
>
> **与上一章的关系**：流水线需要多条指令同时在执行——这就产生了指令之间的依赖，即"冒险"问题。
>
> **与学科的关系**：流水线是现代 CPU 性能的基石，面试常考三种冒险及其解决方案。

### 4.1 三种冒险 ⭐⭐⭐

| 冒险 | 原因 | 解决方案 |
|------|------|----------|
| **结构冒险** | 硬件资源冲突（同时访存） | 增加硬件（指令 Cache + 数据 Cache 分离） |
| **数据冒险** | 后指令需要前指令的结果 | **前递（Forwarding/Bypassing）**；Load-Use 需暂停 1 拍 |
| **控制冒险** | 分支指令改变了 PC | **分支预测**（静态/动态预测） |

> [!tip]+ 关键
> 前递能解决大部分数据冒险（EX→EX、MEM→EX），但 **Load-Use 冒险**（上一条 lw 的结果紧接着被用）必须暂停 1 拍——这是面试最爱考的例外。

## 5. 存储系统

> [!note]+ 章节导引
> **本章知识点之间的关系**：存储是 CO 的"下半场"——CPU 越来越快，但存储跟不上，所以需要层次化存储。逻辑链：**SRAM vs DRAM**（快但贵 vs 慢但便宜）→ **主存组织**（ROM 类型、刷新方式）→ **局部性原理**（Cache 和虚拟存储的共同理论根基）→ **Cache**（解决 CPU-主存速度差距）→ **虚拟存储**（解决主存-磁盘容量差距）。
>
> **与上一章的关系**：流水线的瓶颈从"计算"转移到"访存"——存储层次就是为解决这个瓶颈而设计的。
>
> **与学科的关系**：存储层次是"用廉价介质模拟昂贵介质"的工程哲学——Cache 用 SRAM 模拟更快的存储，虚拟存储用磁盘模拟更大的内存。

### 5.1 SRAM vs DRAM ⭐⭐⭐

| | SRAM | DRAM |
|---|---|---|
| 存储单元 | 6 管触发器 | 1 管电容 |
| 速度 | **快**（ns 级） | 慢（10x SRAM） |
| 成本 | **贵** | 便宜 |
| 是否需刷新 | 不需要 | **需要**（电容漏电） |
| 用途 | **Cache** | **主存** |

**DRAM 刷新方式**：分散刷新（每行分散在不同时间）、集中刷新（一段时间全刷新）、异步刷新（折中）

### 5.2 Cache ⭐⭐⭐（面试极高频）

**Cache 三个核心问题**：映射方式（放哪）、替换策略（满了谁走）、写策略（改了怎么办）

**三种映射方式**：

| 方式 | 地址结构 | 优点 | 缺点 |
|------|----------|------|------|
| **直接映射** | 标记 + 索引 + 偏移 | 查找快，硬件简单 | 冲突多（同一索引只能放一个） |
| **全相联** | 标记 + 偏移 | 冲突最少 | 查找慢，硬件贵 |
| **组相联** | 标记 + 索引 + 偏移 | **折中**，实际最常用 | N 路组相联 |

**写策略组合**：

| | 写命中 | 写缺失 |
|---|---|---|
| Write Through + No Write Allocate | 同时写 Cache 和主存 | 只写主存，不调入 Cache |
| Write Back + Write Allocate | 只写 Cache，脏位标记退出时写回 | 调入 Cache 再写 |

> [!tip]+ Cache vs 虚拟存储
> Cache 解决**速度**差距（CPU↔主存），虚拟存储解决**容量**限制（主存↔磁盘）。两者都基于局部性原理，但管理方式不同：Cache 由硬件管理，虚拟存储由 OS+硬件管理。

### 5.3 虚拟存储 ⭐⭐⭐⭐

**虚拟存储**让每个进程以为自己独占整个内存——实际只加载当前需要的页，其余在磁盘。

**地址转换**：虚拟地址 → **页表** → 物理地址

**TLB**（页表的高速缓存）：命中时 1 次访存得到物理地址，否则要查页表（2 次访存）

**页面置换算法**：OPT（理论最优）> LRU（实际最优）> Clock（LRU 近似）> FIFO（有 Belady 异常）

> [!tip]+ Belady 异常
> FIFO 独有的"反直觉"问题：更多页框可能导致更多缺页！LRU 和 Clock 不会有。

## 附：CO 面试速查表

| 问题 | 一句话回答 |
|------|-----------|
| 补码 vs 原码 | 补码统一加减法，0 唯一 |
| Moore vs Mealy | Moore 输出只看状态，Mealy 还看输入 |
| 三种冒险 | 结构（资源冲突）→ 数据（前递解决）→ 控制（分支预测） |
| SRAM vs DRAM | SRAM 快贵（Cache），DRAM 慢便宜（主存） |
| Cache 映射 | 直接映射快但冲突多，组相联折中 |
| 局部性原理 | 时间局部性+空间局部性，是 Cache 和虚拟存储的根基 |
| TLB 作用 | 页表的高速缓存，命中则 1 次访存 |
| 虚拟内存原理 | 局部性→按需调页→缺页中断→页面置换 |
