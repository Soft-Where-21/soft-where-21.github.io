## 1. 网络体系结构

### 1.1 OSI 七层 vs TCP/IP 四层 ⭐⭐⭐

**Q [⭐⭐⭐]【1.1.Q1】：请写出 OSI 七层模型与 TCP/IP 四层模型的对应关系。**

A：

- **OSI 七层**（自下而上）：物理层 → 数据链路层 → 网络层 → 传输层 → 会话层 → 表示层 → 应用层
- **TCP/IP 四层**（自下而上）：网络接口层 → 网际层 IP → 运输层 → 应用层
- **对应关系**：应用层 = OSI 的**应用层 + 表示层 + 会话层**；运输层 = OSI 传输层；网际层 = OSI 网络层；网络接口层 = OSI **数据链路层 + 物理层**

**Q [⭐⭐]【1.1.Q2】：什么是五层教学模型？**

A：物理层 → 数据链路层 → 网络层 → 传输层 → 应用层。即把 TCP/IP 四层中的"**网络接口层**"**拆成物理层 + 数据链路层**，其余与四层模型一致（谢希仁教材体系，面试常与七层并列提问）。

**Q [⭐⭐]【1.1.Q3】：为什么要分层？**

A：各层**相互独立、灵活、可替换**——每层只解决一种通信问题、向上层提供服务而屏蔽实现细节，把复杂通信拆成可复用的模块，**降低复杂度**。分层后任一层内部的技术升级不影响其他层。

### 1.2 各层的作用 ⭐⭐⭐【北航真题】

**Q [⭐⭐⭐]【1.2.Q1】：计算机网络各层的作用分别是什么？（北航真题）**

A：

- **物理层**：**透明的传输比特流**——屏蔽不同传输媒体与通信手段的差异，确定机械/电气/功能/过程四大特性；设备：中继器、集线器
- **数据链路层**：把网络层传来的 **IP 数据报封装成帧**——概括为**封装成帧、透明传输、差错控制、流量控制、介质访问控制**；设备：网桥、交换机
- **网络层**：把分组**封装成 IP 数据报**，完成**路由选择与分组转发**——跨网络的逻辑寻址（IP 地址）+ 路由，还包括 ARP/ICMP/IGMP 等配套协议
- **传输层**：**进程到进程**的通信——通过端口号多路复用/分用，TCP 可靠、UDP 不可靠
- **应用层**：面向**用户的服务**——HTTP、DNS、SMTP、DHCP、TFTP 等

**Q [⭐⭐]【1.2.Q2】：记忆口诀怎么背各层作用？**

A：物理层"**透明传比特**"，链路层"**组帧管相邻**"，网络层"**寻路跨网络**"，传输层"**端口连进程**"，应用层"**服务给用户**"。

### 1.3 数据在各层的传输单位（PDU）⭐⭐⭐

**Q [⭐⭐⭐]【1.3.Q1】：数据在各层的传输单位分别是什么？**

A：

| 层次 | 传输单位（PDU） |
|---|---|
| 应用层 | **报文**（message） |
| 传输层 | TCP：**报文段**（segment）；UDP：**用户数据报** |
| 网络层 | **IP 数据报 / 分组**（packet） |
| 数据链路层 | **帧**（frame） |
| 物理层 | **比特**（bit） |

**Q [⭐⭐]【1.3.Q2】：数据在各层之间是如何传输的？**

A：**发送方逐层封装**（加首部/尾部）：应用层产生报文 → 传输层加端口号等首部成报文段 → 网络层加 IP 首部成数据报 → 链路层加 MAC 地址首尾部成帧 → 物理层转成比特流发送。**接收方逐层解封装**（去首部），把数据交上层。

### 1.4 协议、接口、服务 ⭐⭐

**Q [⭐⭐]【1.4.Q1】：协议、接口、服务三者的区别是什么？**

A：

- **协议**是**水平的**——对等层实体之间通信的规则（如两台主机的传输层之间按 TCP 规则交互）
- **服务**是**垂直的**——下层向上层提供的功能（如链路层为网络层提供成帧、差错检测）
- **接口**是上下层之间交换信息的**连接点与规则**（如何调用下层服务）
- 一句话：**协议是水平方向（对等层），服务是垂直方向（下层向上层提供），接口是层间交互的通道**。

### 1.5 三种交换方式 ⭐⭐⭐

**Q [⭐⭐⭐]【1.5.Q1】：电路交换、报文交换、分组交换的区别是什么？**

A：

| | 电路交换 | 报文交换 | 分组交换 |
|---|---|---|---|
| 通信前 | **建立连接**（独占线路） | 无需连接 | 无需连接 |
| 数据单元 | 连续比特流 | **整个报文** | **分组**（报文拆分） |
| 时延 | 建立连接时延大，传输时延小 | 整文存储转发，时延大 | 存储转发，时延**较小** |
| 线路利用 | 独占、利用率低 | 共享链路 | 共享链路、利用率**高** |
| 特点 | 实时性好、可靠 | 无速率/格式转换问题 | **路由器存储转发**，灵活、健壮 |

**Q [⭐⭐]【1.5.Q2】：为什么分组交换优于报文交换？**

A：① 分组比整个报文**短得多**，存储转发**时延更小**；② 避免**过长的报文长时间占用链路**；③ 各结点交换机在发送分组的同时还能缓存后续分组，**流水线式**工作；④ 分组小，**更利于差错控制**。两者都无需预先建立连接，适合**突发数据**。

### 1.6 传统电话网络 vs 计算机网络 ⭐

**Q [⭐⭐]【1.6.Q1】：传统的电话网络和计算机网络有什么区别？**

A：**核心区别：电话网络是电路交换，计算机网络是分组交换。**

| | 传统电话网络 | 计算机网络 |
|---|---|---|
| 交换方式 | **电路交换** | **分组交换** |
| 连接 | 先建立连接，通信期间**独占线路** | 无连接、**按需共享带宽** |
| 资源分配 | 预先分配固定带宽，空闲也浪费 | 动态竞争使用，利用率高 |
| 适合流量 | **持续的大流量**（语音） | **突发流量**（网页/文件） |
| 时延特征 | 建立连接时延大、之后稳定 | 有存储转发和**排队时延**，可变 |

**Q [⭐]【1.6.Q2】：电话网能不能改成分组交换？**

A：技术上可以（VoIP 就是分组化的语音），但电路交换对语音更自然：语音是**持续、恒定速率**的流量，电路交换的**时延稳定、无抖动**优于分组交换的排队时延。分组交换的优势（突发流量、统计复用）对语音帮助不大。

## 2. 物理层

### 2.1 奈氏定理与香农定理 ⭐⭐⭐

**Q [⭐⭐⭐]【2.1.Q1】：奈氏定理（Nyquist）的内容是什么？**

A：**理想无噪声信道**下，极限数据率为
$$\text{极限数据率} = 2W \log_2 V \quad (\text{b/s})$$
其中 $W$ 为信道带宽（Hz），$V$ 为码元的**离散状态数**（电平数）。含义：带宽一定时，码元速率有上限（$2W$ Baud），要提速只能**提高每码元承载的比特数** $\log_2 V$。

**Q [⭐⭐⭐]【2.1.Q2】：香农定理（Shannon）的内容是什么？**

A：**有噪声信道**下，极限数据率为
$$\text{极限数据率} = W \log_2\left(1 + \dfrac{S}{N}\right) \quad (\text{b/s})$$
其中 $S/N$ 为信噪比。信噪比的常用表示：$\text{信噪比(dB)} = 10\log_{10}(S/N)$。

**Q [⭐⭐]【2.1.Q3】：奈氏定理和香农定理有什么关系？**

A：**奈氏**限定**码元速率**上限（无噪声、与 $S/N$ 无关），**香农**限定**信息速率**上限（有噪声）。二者从不同角度给上限，**实际最大数据率 = min(奈氏上限, 香农上限)**。

**Q [⭐]【2.1.Q4】：物理层的四大特性是什么？**

A：**机械特性**（接口形状、引脚数）、**电气特性**（电压范围、阻抗）、**功能特性**（某电平表示何意）、**过程特性**（事件出现顺序）。物理层的任务就是**透明地传输比特流**。

**Q [⭐]【2.1.Q5】：物理层的典型设备有哪些？它们的作用是什么？**

A：**中继器**：对衰减的信号**再生放大**，延长传输距离；**集线器（Hub）**：多端口中继器，把收到的比特流广播到所有端口。二者都工作在物理层，**既不隔离冲突域也不隔离广播域**。

## 3. 数据链路层

### 3.1 三种可靠传输协议 ⭐⭐⭐

**Q [⭐⭐⭐]【3.1.Q1】：停等协议、GBN、SR 三种可靠传输协议有什么区别？**

A：

| 协议 | 窗口 | 重传方式 | 效率 |
|---|---|---|---|
| **停止等待协议** | 发送窗口 = 1 | 超时重传当前帧 | 低 |
| **GBN（后退 N 帧）** | 发送窗口 > 1，接收窗口 = 1 | 超时重传**所有已发送未确认帧** | 中 |
| **SR（选择重传）** | 发送窗口 > 1，接收窗口 > 1 | **只重传出错帧** | 高（但窗口有限制） |

**Q [⭐⭐]【3.1.Q2】：SR 的窗口为什么要有限制？**

A：SR 接收方要缓存**乱序到达的正确帧**，若窗口过大，接收方无法区分"新帧"与"重传帧"（序号会绕回重叠），因此窗口尺寸受序号空间限制（如发送窗口 ≤ 序号空间的一半）。

### 3.2 CSMA/CD ⭐⭐⭐

**Q [⭐⭐⭐]【3.2.Q1】：CSMA/CD 的工作原理是什么？**

A：**载波监听多点接入/碰撞检测**（以太网的核心协议），四个要点：

- **先听后发**：发送前监听信道是否空闲
- **边发边听**：发送过程中持续监听是否发生冲突
- **冲突停发**：检测到冲突立即停止发送，并发出干扰信号
- **随机重发**：等待随机时间后重试（二进制指数退避）

**Q [⭐⭐⭐]【3.2.Q2】：什么是最短帧长？为什么以太网最短帧长是 64 字节？**

A：发送方必须在**发送完毕之前**就能检测到冲突，即"发送一帧的时间 ≥ 端到端往返传播时延"。以太网规定**争用期 = 512 比特时间**（10 Mb/s 下为 51.2 μs），对应最短帧长 **64 字节**；短于 64 字节的帧会在检测到冲突前就发完，无法判错，故**一律按无效帧丢弃**。

**Q [⭐⭐]【3.2.Q3】：什么是争用期（碰撞窗口）？**

A：冲突最晚能被发现的时间窗口 = **最坏情况下的端到端往返传播时延**，即发送方"边发边听"到确认没人撞所需的最长时间。只有发送时长 ≥ 争用期，才能保证察觉所有冲突。

**Q [⭐]【3.2.Q4】：CSMA/CD 中发生冲突后如何重发？**

A：采用**二进制指数退避**：第 $i$ 次冲突后从 $0 \sim 2^{i}-1$ 个时间片中**随机**取一个作为等待时间（$i$ 有上限），冲突越多等待越久，从而降低再次碰撞概率；连续多次（如 16 次）失败则放弃并向上层报错。

### 3.3 PPP 协议 ⭐

**Q [⭐⭐]【3.3.Q1】：PPP 协议是什么？有什么特点？**

A：**点对点协议**（Point-to-Point Protocol），点对点信道上使用最广泛的数据链路层协议。

- **应用场景**：用户计算机与 **ISP** 通信的拨号链路（广域网串行链路）；与以太网（广播信道）相对，PPP 工作在**点对点信道**
- **特点**：面向**字节**、**不可靠**——不提供差错控制/流量控制，只做差错检测，纠错交给上层
- 可**查错**（有 FCS）但**不能纠错**，也**可以有身份鉴别**

**Q [⭐⭐]【3.3.Q2】：PPP 的三个组成部分是什么？**

A：① **封装方法**：把 IP 数据报封装到串行链路；② **链路控制协议 LCP**：建立/释放数据链路层连接、协商链路参数；③ **网络控制协议 NCP**：配置网络层，为用户分配**临时的 IP 地址**。

**Q [⭐]【3.3.Q3】：PPP 如何实现透明传输？**

A：帧首尾的标志字段 F = 0x7E。透明传输两类做法：**同步传输用零比特填充**（发现 5 个连续 1 就插入一个 0）；**异步传输用字节填充**（7E→7D 5E、7D→7D 5D、控制字符前加 7D）。

**Q [⭐]【3.3.Q4】：PPP 链路建立与释放的过程？**

A：**五个状态**：链路静止（无物理连接）→ **链路建立**（LCP 协商）→ **鉴别**（可选，PAP/CHAP 身份认证）→ **网络层协议**（NCP 配置网络层、分配临时 IP）→ **链路打开**（可传数据）→ **链路终止**。

对应到通信过程：**建立**：拨号建立物理连接 → **LCP** 协商建立数据链路层连接 →（可选**鉴别**）→ **NCP** 配置网络层、分配临时 IP。**释放**：**NCP 先**释放网络层连接并收回 IP → **LCP 再**释放数据链路层连接 → **最后**释放物理层连接。PPP **能查错（有 FCS）但不能纠错**，且**可以有身份认证**。

### 3.4 VLAN 虚拟局域网 ⭐⭐

**Q [⭐⭐]【3.4.Q1】：什么是 VLAN？它的本质是什么？**

A：**VLAN**（Virtual LAN）是由一些局域网网段构成的**与物理位置无关的逻辑组**，用**以太网交换机**很方便地实现（标准 **IEEE 802.1Q**）。每个 VLAN 的帧带有明确的标识符，指明发送该帧的计算机属于哪个 VLAN。本质：VLAN 只是局域网给用户提供的一种**服务**，**不是**一种新型局域网。

**Q [⭐⭐]【3.4.Q2】：VLAN 有什么作用？三大优点是什么？**

A：**隔离广播域**——每个 VLAN 是一个广播域，限制了接收广播的工作站数，防止"**广播风暴**"使网络性能恶化。三大优点：**改善性能**（减少到其他 VLAN 的不必要通信）→ **简化管理**（地理位置分散的用户可划入同一 VLAN，无需移动设备）→ **降低成本**（用便宜的交换机代替路由器来划分广播域）。

**Q [⭐⭐]【3.4.Q3】：VLAN 的划分方法有哪些？**

A：按所在层次分——① 基于**端口**划分（第 1 层，最简单常用）；② 基于 **MAC 地址**划分（第 2 层，需输入管理大量 MAC 地址）；③ 基于**协议类型**划分（第 2 层）；④ 基于 IP 子网 / 高层应用划分（第 3 层）。

**Q [⭐⭐]【3.4.Q4】：跨 VLAN 通信为什么必须经过网络层？**

A：二层交换机（工作于链路层）只能**隔离广播域**、不能互转发不同 VLAN 的帧；**跨 VLAN 通信必须经过网络层**——需要路由器或**三层交换机**（如 VLAN 接口充当各 VLAN 的网关）。

### 3.5 令牌传送机制 ⭐⭐

**Q [⭐⭐]【3.5.Q1】：简述令牌传送的机制。**

A：**受控接入**（受控访问）的介质访问控制方式，与 CSMA/CD 的随机接入相对，用于**令牌环**、**令牌总线**网络。

- **原理**：网中只有一个特殊帧"**令牌（token）**"沿环（或总线）传递，**只有拿到令牌的站才能发送数据**，发完把令牌传给下一站
- **无冲突**：同一时刻只有一台主机有发送权，**不会发生碰撞**，故没有最短帧长限制
- **优劣势**：**重负载时效率高**（不像 CSMA/CD 那样因冲突频繁而性能骤降）；**轻负载时效率低**（必须等令牌绕一圈才能发，等待时间长）

### 3.6 各层设备对比 ⭐⭐⭐

**Q [⭐⭐⭐]【3.6.Q1】：数据链路层的互联设备有哪些？中继器、集线器、网桥、交换机、路由器各工作在什么层次？能否隔离冲突域/广播域？**

A：

| 设备 | 工作层次 | 功能 | 隔离冲突域 | 隔离广播域 |
|---|---|---|---|---|
| **中继器** | 物理层 | **信号再生**放大，延长传输距离 | 不隔离 | 不隔离 |
| **集线器（Hub）** | 物理层 | 多端口中继器，转发比特流 | 不隔离（全部端口一个冲突域） | 不隔离 |
| **网桥** | 数据链路层 | 连接两个网段，**按 MAC 地址**有选择地转发帧 | **隔离**（每端口一个冲突域） | 不隔离 |
| **交换机** | 数据链路层 | 多端口网桥，硬件查表转发，支持 VLAN | **隔离** | 不隔离（VLAN 可隔离） |
| **路由器** | 网络层 | 按 **IP 地址**路由选择并转发分组 | **隔离** | **隔离**（每个接口一个广播域） |

**Q [⭐⭐]【3.6.Q2】：为什么说"只有路由器才叫网络互连"？**

A：中继器/集线器只能"放大 + 转发"比特；网桥/交换机只是把一个网络**扩大**（仍是一个网络、同一广播域）。只有路由器（或三层交换机）能**按 IP 地址跨网络转发**、隔离广播域，所以**跨网络必须用路由器**，这才是"网络互连"。

**Q [⭐⭐]【3.6.Q3】：交换机的工作内容（实现原理）是什么？交换机和路由器有什么区别？**

A：

- **交换机（数据链路层，多端口网桥）**：① **自学习**建立**MAC 地址表**（记录"源 MAC ↔ 端口 + 时间"）；② 收到帧后查表转发——**表中有目的 MAC 则只从对应端口转发**（单播），**查不到则向除入端口外的所有端口泛洪**；③ 表项有老化时间；④ 硬件（ASIC）查表转发，每个端口一个冲突域，支持 VLAN（VLAN 间需三层设备）
- **路由器（网络层）**：① 维护**路由表**（由 RIP/OSPF/BGP 等协议生成）；② 收到分组后按**目的 IP** 查表决定下一跳/出接口；③ 出接口用 **ARP 解析下一跳 MAC**，**重新封装成新的帧**（改源/目的 MAC，IP 首部 TTL 减 1）；④ 隔离广播域，能跨网络转发
- **对比**：工作层次不同（链路层 vs 网络层）；**寻址依据不同**（MAC vs IP）；交换机转发快、成本低，但**不能跨网段、不隔离广播域**；路由器能跨网互连、隔离广播域，但转发较慢、成本较高

### 3.7 网络接口卡（网卡/网络适配器）⭐

**Q [⭐]【3.7.Q1】：网卡（NIC）的功能有哪些？**

A：网卡是计算机与局域网的连接接口，工作于数据链路层（同时完成物理层的比特收发）。四大功能：

- **串行/并行转换**：总线上是并行数据，线路上是串行比特流
- **数据缓存**：网络数据率与总线数据率不同，靠缓存匹配速度差异
- **实现以太网协议**：封装/解封装 MAC 帧、实现 CSMA/CD
- **MAC 地址**：48 位全球唯一 MAC 地址**固化在网卡 ROM 中**（还需设备驱动程序配合操作系统收发）

**Q [⭐]【3.7.Q2】：MAC 地址有什么特点？**

A：**48 位**（6 字节）全球唯一，**固化在网卡 ROM 中**，属于数据链路层的**平面物理地址**；与网络层 IP 地址（逻辑地址、可随位置变化）解耦，靠 **ARP** 完成 IP→MAC 的映射。

### 3.8 差错检测：奇偶校验与 CRC ⭐⭐

**Q [⭐⭐]【3.8.Q1】：CRC 循环冗余校验的原理是什么？**

A：数据在传输中可能因噪声产生**比特差错**（1 变 0、0 变 1），链路层靠**冗余编码**让接收方发现差错。

1. 收发双方约定一个 $k+1$ 位的**生成多项式** $G(x)$
2. 发送方在数据 $M$ 后补 $k$ 个 0，用**模 2 除法**（只做异或、不借位）除以 $G(x)$，得 $k$ 位余数作 **FCS 帧检验序列**，附在数据后一起发送
3. 接收方用同一个 $G(x)$ 去除收到的数据，**余数为 0 则认为无差错**，否则丢弃该帧

**Q [⭐⭐]【3.8.Q2】：奇偶校验有什么局限？CRC 能纠错吗？**

A：**奇偶校验**只加 1 位校验位（使 1 的个数为奇/偶），**只能发现奇数个比特错**，能力弱。**CRC 只能检错、不能纠错**——发现差错就丢弃，是否重传由上层（ARQ 协议 / TCP）决定。

**Q [⭐⭐]【3.8.Q3】：无差错传输是在哪一层实现的？**

A：分两层看：**差错"检测"** 在数据链路层（帧尾 CRC）和传输层（首部**校验和**）完成；**真正"无差错且可靠"的传输**由传输层的 **TCP**（序号 + 确认 + 超时重传）保证。链路层只做到"发现有错就扔"，不负责让数据一定送到。

### 3.9 面向连接服务 vs 无连接服务 ⭐⭐

**Q [⭐⭐]【3.9.Q1】：面向连接服务和无连接服务的特点有什么不同？**

A：

| | 面向连接服务 | 无连接服务 |
|---|---|---|
| 通信前 | **必须先建立连接**（协商参数） | 无需建立连接，直接发 |
| 顺序性 | 数据**按序**到达 | 不保证顺序 |
| 可靠性 | 可确认/重传，**可靠性高** | 尽力交付，**不可靠** |
| 开销 | 建立/释放连接有额外开销 | 开销小、灵活、效率高 |
| 典型 | **TCP**、虚电路 | **UDP**、IP 数据报 |

**Q [⭐⭐]【3.9.Q2】：数据链路层可能提供哪三种基本服务？**

A：① **无确认的无连接服务**：发完不管，出错交上层处理——**以太网**采用（局域网误码率低，交给 TCP 重传更划算）；② **有确认的无连接服务**：每帧都要求确认，收到确认才发下一帧——适用于误码率较高的链路；③ **有确认的面向连接服务**：先建立链路连接，帧按序传送 + 确认——可靠性最高但开销最大，实际很少用。

### 3.10 局域网的关键技术 ⭐⭐

**Q [⭐⭐]【3.10.Q1】：局域网的关键技术（三要素）是什么？**

A：

| 要素 | 内容 |
|---|---|
| **网络拓扑** | 星形（**主流**，配交换机）、总线形（早期以太网）、环形（令牌环）、树形 |
| **传输介质** | 双绞线（UTP 5/6 类，最常见）、同轴电缆（早期）、光纤（主干/远距离）、无线（Wi-Fi） |
| **介质访问控制方法** | **CSMA/CD**（共享以太网，随机接入）、**令牌传递**（令牌环/令牌总线，受控接入） |

**Q [⭐]【3.10.Q2】：局域网有什么特点？现代以太网是怎么组网的？**

A：局域网的特点是**私有、范围小、速率高、误码率低**。现代以太网采用**星形拓扑 + 双绞线 + 交换机**，每个端口独占带宽、全双工工作，已不再是共享信道（CSMA/CD 实际退居备用）。

## 4. 网络层

### 4.1 IP 地址分类与子网划分 ⭐⭐⭐

**Q [⭐⭐⭐]【4.1.Q1】：IP 地址如何分类？各类的网络号/主机号是多少？**

A：

| 类 | 网络号 | 主机号 | 起始比特 | 最大网络数 |
|---|---|---|---|---|
| A | 8 bit | 24 bit | 0 | 126 |
| B | 16 bit | 16 bit | 10 | 16384 |
| C | 24 bit | 8 bit | 110 | 2097152 |

**Q [⭐⭐⭐]【4.1.Q2】：子网掩码的作用是什么？**

A：**区分 IP 地址中的网络部分与主机部分**——与 IP 地址**按位与**运算即得网络地址，据此判断"两台主机是否在同一子网"（同网段**直接交付**，跨网段交给**路由器**转发）。子网划分把主机号进一步划分为**子网号 + 主机号**。

**Q [⭐⭐]【4.1.Q3】：什么是 CIDR？什么是超网（路由聚合）？**

A：**CIDR**（无类域间路由）用 `/n` 表示网络前缀长度，**不区分 A/B/C 类**，使地址分配更灵活。**超网/路由聚合**：把若干**连续**网段合并成一条路由表项。例：`202.100.0.0/24 ~ 202.100.3.0/24` 四条路由，共同前缀是前 22 位，可聚合为一条 `202.100.0.0/22`。

**Q [⭐⭐]【4.1.Q4】：为什么不能用手机号实现 IP 地址？手机号和 IP 的本质区别是什么？**

A：

- **结构不同**：IP 地址是**分层结构**（网络号 + 主机号），同一网络前缀可**聚合**成一条路由表项，路由器只需记"去哪个网段"；手机号是**平面编号**，无法从号码推出归属网络，若拿它当地址，全球路由表将大到无法维护
- **绑定对象不同**：IP 地址分给"**网络接口/位置**"，随主机移动而改变，与设备身份解耦；手机号绑定"**人/SIM 卡身份**"，跟人走
- **可复用性**：IP 地址可在不同子网内重复使用（配合 NAT），手机号全球唯一、不可复用
- **层次归属**：IP 是网络层**逻辑地址**，与 MAC 地址、域名解耦分层；手机号是运营商业务标识，不参与三层转发

**Q [⭐⭐]【4.1.Q5】：IP 协议的定义和作用是什么？**

A：**IP 协议（网际协议）是网络层的核心协议**，作用有两方面：① **逻辑地标识网络结点的位置**——用 IP 地址给每台主机/路由器的接口编址，屏蔽底层物理网络的差异，使互联网上任意两台主机都能互相找到；② **在数据封装中添加信息**，通过 IP 首部中的**源 IP 地址与目的 IP 地址**表明数据的**原始发送者和最终接收者**。

特点：IP 提供**无连接、尽力交付（best-effort）**的数据报服务——不保证可靠、不保证有序、不保证不丢，可靠性由上层 TCP 补齐；除地址外还提供**分片与重组**、**TTL 防环**等功能，并配套 ARP/ICMP/IGMP 等协议。

**Q [⭐⭐]【4.1.Q6】：如何划分子网？子网数和主机数怎么算？**

A：**做法**：从**主机号**中**借**若干位作**子网号**（subnet id），网络号 + 子网号 + 主机号，并用**子网掩码**标出这个划分。

- **子网数** = $2^{\text{借位数}}$（若子网号全 0/全 1 不可用，则为 $2^{\text{借位数}}-2$）
- **每个子网可用主机数** = $2^{\text{剩余主机位数}} - 2$（去掉全 0 的"本网"和全 1 的"广播"）
- **例**：`192.168.1.0/24` 借 3 位划子网 → 掩码变 `255.255.255.224`（`/27`），得 $2^3 = 8$ 个子网（每个 32 个地址），每子网可用主机 $2^5-2 = 30$ 台
- **判断同网段**：把两个 IP 分别与掩码**按位与**，结果相同即在同一子网（直接交付），否则交给路由器

### 4.2 路由协议对比（RIP / OSPF / BGP）⭐⭐⭐【北航真题：OSPF】

**Q [⭐⭐⭐]【4.2.Q1】：RIP、OSPF、BGP 有什么区别？（北航真题：OSPF）**

A：

| | RIP | OSPF | BGP |
|---|---|---|---|
| 类型 | **内部网关**（IGP） | **内部网关**（IGP） | **外部网关**（EGP） |
| 算法 | 距离向量（Bellman-Ford） | **链路状态（Dijkstra）** | 路径向量 |
| 度量 | **跳数**（最大 15） | 代价（带宽等） | 策略 |
| 收敛速度 | 慢（可能计数到无穷） | **快** | / |
| **和谁换（who）** | 只与**相邻路由器**交换 | **洪泛法**，发给**本 AS 内所有路由器** | 只与**相邻 AS 的 BGP 发言人**交换 |
| **换什么（what）** | **整个路由表**（周期性全量） | **相邻路由器的链路状态** | **可达信息**：启动时完整，之后**增量更新** |
| 承载 | UDP 520，每 30 s | IP 协议号 89 | **TCP 179** |

**Q [⭐⭐⭐]【4.2.Q2】：为什么 OSPF 优于 RIP？（北航真题）**

A：① **算法更优**：OSPF 用链路状态 + Dijkstra，每台路由器掌握**全网拓扑**，算的是真实**最短路径**；RIP 是距离向量，只知"邻居说多远"，易**计数到无穷**、收敛慢。② **度量更合理**：RIP 只数**跳数**（且最大 15 跳，超限即不可达，不适合大网络）；OSPF 用**代价**（带宽、时延等）。③ **收敛快**：OSPF 用**洪泛**同步链路状态，全网快速一致。④ **承载**：RIP 跑在 UDP 上（520），OSPF 直接封装在 IP 里（协议号 89），更可靠地传递路由信息。

**Q [⭐⭐]【4.2.Q3】：BGP 为什么用路径向量而不是距离向量？**

A：BGP 在 **AS 之间**选路，目标是**策略**而非最短：路径向量记录**经过的 AS 序列**，可① 检查是否为**商业策略**允许的路径（如"经过某运营商"）；② 天然**检测环路**（AS 号重复即拒收），避免距离向量的计数到无穷；③ 只与**相邻 AS 的发言人**交换**可达性**（启动全量、之后增量），扩展性远好于域内协议。

### 4.3 ARP 协议 ⭐⭐⭐

**Q [⭐⭐⭐]【4.3.Q1】：ARP 的工作原理是什么？**

A：**功能**：已知 IP 地址，求对应的 MAC 地址。**工作过程**：先查本地 **ARP 缓存** → 没有则**广播 ARP 请求**（"谁的 IP 是 X？"）→ 目标主机**单播 ARP 应答**（"我是 X，我的 MAC 是 Y"）→ 双方**更新缓存**。ARP 是**网络层与数据链路层的桥梁**（在链路层广播、为网络层解析地址）。

### 4.4 ICMP 协议 ⭐⭐

**Q [⭐⭐]【4.4.Q1】：ICMP 的原理和作用是什么？**

A：**网际控制报文协议**（Internet Control Message Protocol），作用是**报告差错情况、提供有关异常情况**——IP 找不到目的地时直接把分组丢弃，由 ICMP 负责"善后"。**地位**：ICMP **不是高层协议**，而是 **IP 层的组成部分**，ICMP 报文封装在 IP 数据报中传输（IP 首部协议字段 = 1）。

**Q [⭐⭐]【4.4.Q2】：ICMP 有哪两类报文？**

A：

- **差错报告报文**（5 种）：**终点不可达**（如 UDP 发现目的端口错误时由 ICMP 发"端口不可达"）、**源点抑制**（发送太快、现已废弃）、**超时**（TTL 减为 0）、**参数问题**（IP 首部检查出错）、**重定向**（存在更优路由时提示源主机）
- **询问报文**：**回送请求/应答**（ping）、**时间戳请求/应答**（时钟同步和时间测量）

**Q [⭐⭐]【4.4.Q3】：哪些情况不应发送 ICMP 差错报告报文？**

A：① 对**差错报告报文本身**不再发（它可能也有错）；② 对第一个分片之后的**后续分片**不发（发一次就够）；③ 对**多播地址**的数据报不发；④ 对**特殊地址**（如 127.0.0.0、0.0.0.0）的数据报不发（都不知道发给谁）。

**Q [⭐⭐⭐]【4.4.Q4】：ping 和 traceroute 的原理是什么？**

A：**ping**（Packet InterNet Groper）：测两主机**连通性**，用回送请求/应答报文——是应用层**直接**使用网络层 ICMP 的例子，不走 TCP/UDP，所以快。**traceroute / tracert**：跟踪分组从源到终点的**路径**，利用 IP 首部 **TTL 字段 + ICMP 超时差错报告报文**（+ 终点不可达报文），逐跳暴露中间路由器。

### 4.5 IGMP 协议 ⭐⭐

**Q [⭐⭐]【4.5.Q1】：IGMP 是什么？作用是什么？**

A：**网际组管理协议**（Internet Group Management Protocol，IP 多播的"成员管理"）。**功能**：让连接在**本地局域网**上的**多播路由器**知道本局域网上**是否有主机（主机上的某个进程）参加或退出了某个多播组**。**地位**：IGMP 报文加 IP 首部构成 IP 数据报传输（IP 协议字段 = 2），同时向上层提供服务，是**网际协议 IP 的组成部分**。

**Q [⭐⭐]【4.5.Q2】：IGMP 工作的两个阶段是什么？**

A：① **加入多播组**：主机向该组多播地址发 IGMP 报文声明成为组成员，本地多播路由器再把组成员关系转发给互联网上其他多播路由器；② **探询成员变化**：本地多播路由器**周期性**（默认每 125 s）探询本局域网主机是否仍是组成员——只要有一个主机响应就认为该组活跃，多次探询无人响应则不再转发该组成员关系。

**Q [⭐⭐]【4.5.Q3】：IGMP 与多播路由选择协议怎么分工？**

A：**IGMP 管成员**：只知道**有无成员**，不知道成员数与成员分布在各网络；**多播路由选择协议管传播**：负责把多播数据报用最小代价传送给组内所有成员。

**Q [⭐]【4.5.Q4】：IGMP 如何降低开销？**

A：所有通信都用 IP 多播；对所有组只发**一个**询问报文；多个多播路由器时只选**一个**来探询；**分散响应**（主机在 0～10 s 内随机选择时延应答）；**抑制机制**（主机听到同组其他主机已响应，自己就不再响应）。

### 4.6 专用地址（私有地址）⭐⭐

**Q [⭐⭐]【4.6.Q1】：哪些是私有地址（专用地址）？可以用在 Internet 中吗？**

A：RFC 1918 指明三大**专用地址块**：

| 地址块 | 类别 | 范围 |
|---|---|---|
| **10.0.0.0/8** | A 类 | 10.0.0.0 ~ 10.255.255.255（1 个网段） |
| **172.16.0.0/12** | B 类 | 172.16.0.0 ~ 172.31.255.255（连续 16 个） |
| **192.168.0.0/16** | C 类 | 192.168.0.0 ~ 192.168.255.255（连续 256 个） |

**不能在 Internet 中直接使用**：专用地址只能作本地地址，互联网中所有路由器对目的地址是专用地址的数据报**一律不转发**，必须借助 NAT 等机制接入。

**Q [⭐⭐]【4.6.Q2】：本地地址与全球地址、专用网的区别是什么？**

A：**本地地址**仅在机构内部使用、由本机构自行分配，无需向互联网管理机构申请；**全球地址**全球唯一、必须申请。采用专用 IP 地址互联的网络称为**专用网**（专用互联网/本地互联网），专用 IP 地址又称**可重用地址**（不同专用网可重复使用同一段）。

### 4.7 NAT 网络地址转换 ⭐⭐

**Q [⭐⭐]【4.7.Q1】：NAT 的转换过程是怎样的？**

A：**NAT 路由器**：在专用网连接到互联网的路由器上安装 NAT 软件，它**至少**有一个有效的**全球 IP 地址**。转换过程发生在 NAT 路由器上，共**两次**：① **离开专用网**时替换**源地址**（内部专用地址 → 外部全球地址）；② **进入专用网**时替换**目的地址**（外部全球地址 → 内部专用地址）。

**Q [⭐⭐]【4.7.Q2】：NAT 有什么局限？NAPT 怎么解决？**

A：

- **局限**：NAT 有 n 个全球 IP 时，专用网内**最多 n 台主机同时**接入互联网（其余轮流使用）；通过 NAT 的通信**必须由内网主机发起**，所以内网主机**不能充当服务器**；NAT 本身**并不能节省 IP 地址**
- **NAPT**（网络地址与端口号转换）：在 NAT 基础上**同时转换传输层端口号**，使多台内网主机**共用一个全球 IP 同时**与不同主机通信（家庭路由器上网用的就是 NAPT）

### 4.8 虚拟专用网 VPN ⭐

**Q [⭐]【4.8.Q1】：什么是 VPN？"专用"和"虚拟"分别指什么？**

A：VPN（Virtual Private Network）利用**公用互联网**作为本机构**各专用网之间的通信载体**。**专用**：本机构主机只用于机构内部通信，不与非本机构主机通信；**虚拟**：实际上**没有使用通信专线**，只是效果与真正的专用网一样。构建时，经公网传送的数据**必须加密**，各网点配置专门的 VPN 软硬件，用**隧道技术**使彼此系统都知道对方的地址。

**Q [⭐]【4.8.Q2】：VPN 有哪三种类型？VPN 与 NAT 有什么区别？**

A：**类型**：① **内联网 VPN**（intranet）——同一机构内部各网络构成；② **外联网 VPN**（extranet）——一个机构与某些外部机构共同建立；③ **远程接入 VPN**（remote access VPN）——外部流动员工通过 VPN 隧道访问公司内网，如同使用本地网络。**VPN vs NAT**：NAT 解决专用网主机**对外**访问互联网（转地址、不加密）；VPN 解决机构各专用网之间经**公网**互连（隧道、加密）。

### 4.9 单播、多播与广播 ⭐⭐

**Q [⭐⭐]【4.9.Q1】：单播、多播（组播）、广播分别指什么？**

A：

| 方式 | 含义 | 典型应用 |
|---|---|---|
| **单播（unicast）** | **一对一**通信（目的地址为单一目标） | 普通 HTTP 网页访问、一切基于 TCP 的协议 |
| **多播 / 组播（multicast）** | **一对一组**通信（组内所有成员都收到） | IPTV、视频会议；用 **D 类地址**标识多播组 |
| **广播（broadcast）** | **一对全体**通信（本网络所有主机都收到） | ARP 请求、DHCP 发现；路由器**不转发**广播 |

**Q [⭐⭐]【4.9.Q2】：多播地址有什么限制？**

A：多播地址（D 类，224.0.0.0 ~ 239.255.255.255）**只能作目的地址，不能作源地址**——它标识"一个**组**"而非"一台主机"。路由器**隔离广播域、不转发广播**，故广播只在同一局域网内传播；互联网范围的多播需要**多播路由器**。链路层对应三种帧：单播帧、广播帧（目的 MAC 全 1）、多播帧。

### 4.10 TTL 生存时间 ⭐⭐

**Q [⭐⭐⭐]【4.10.Q1】：TTL 是什么？作用是什么？**

A：**TTL（Time To Live）**是 IP 首部中的 **8 位**字段，表示数据报在网络中**最多还能经过的路由器数**（一般视作 hop count）。**原理**：每经过一个路由器 TTL **减 1**，减到 **0** 时路由器**丢弃该数据报**，并向源主机发送 **ICMP 超时差错报告报文**。**作用**：防止数据报因路由环路等原因在网络中**无限循环**、浪费网络资源。

**Q [⭐⭐]【4.10.Q2】：哪些工具会用到 TTL？**

A：**traceroute / tracert**：从 TTL=1 开始逐个递增发送，让分组"恰好"在第 1、2、3…跳超时，利用返回的 ICMP 超时报文**逐跳探测出路径上的每个路由器**；**ping**：发送回送请求时设置初始 TTL（Windows 默认 128，Linux 默认 64），从应答的 TTL 可粗略判断对方系统类型。

### 4.11 内部网关协议 IGP vs 外部网关协议 EGP ⭐⭐

**Q [⭐⭐]【4.11.Q1】：IGP 和 EGP 有什么区别？有哪些网关协议？**

A：互联网由许多**自治系统 AS** 组成，路由协议按作用范围分两类：

| | IGP（内部网关协议） | EGP（外部网关协议） |
|---|---|---|
| 作用范围 | **AS 内部** | **AS 之间** |
| 代表协议 | **RIP、OSPF** | **BGP** |
| 关注点 | 域内**最佳路由**（跳数/代价） | 域间**可达性与策略** |

**Q [⭐⭐]【4.11.Q2】：RIP 与 OSPF 有什么不同？**

A：

| | RIP | OSPF |
|---|---|---|
| 算法 | 距离向量（Bellman-Ford） | 链路状态（Dijkstra） |
| 度量 | **跳数**（最大 15，超限不可达） | **代价**（带宽、时延等） |
| 收敛 | 慢（可能计数到无穷） | **快**（全网拓扑同步） |
| 和谁交换 | 只与**相邻路由器** | **洪泛法**发给全网所有路由器 |
| 交换内容 | 整个路由表（UDP 520，每 30 s） | 链路状态信息（IP 89 协议） |

## 5. 传输层

### 5.1 TCP vs UDP ⭐⭐⭐⭐

**Q [⭐⭐⭐]【5.1.Q1】：TCP 和 UDP 有什么区别？工作在哪一层？**

A：二者都工作在**传输层**，为不同主机上的应用进程提供逻辑通信。

| | TCP | UDP |
|---|---|---|
| 连接 | **面向连接**（三次握手） | 无连接 |
| 可靠性 | **可靠**（确认 + 重传 + 流量控制 + 拥塞控制） | 不可靠 |
| 传输方式 | 字节流 | **报文**（保留边界） |
| 头部大小 | 20 字节 + | **8 字节** |
| 效率 | 慢 | **快** |
| 适用 | 文件传输、HTTP、SMTP | DNS、视频流、游戏 |

**Q [⭐⭐⭐]【5.1.Q2】：TCP 如何保证可靠传输？**

A：六件套——

- **校验和**：首部 + 数据出错则丢弃，防止收到被噪声破坏的数据
- **序号 + 确认号**：给每个字节编号，接收方累计确认，可检测丢包、去除重复
- **超时重传**：发送后启动定时器，超时未收到确认就重传
- **连接管理**：三次握手确认双方收发能力，四次挥手保证两个方向都关干净
- **流量控制**：接收方用滑动窗口（rwnd）告知自己的缓冲能力，防止发送过快压垮对方
- **拥塞控制**：慢启动/拥塞避免/快重传/快恢复，按网络整体状况调整速率

**Q [⭐⭐]【5.1.Q3】：会议视频、语音通话采用什么传输层协议？为什么？**

A：用 **UDP**（实时音视频通常跑在 **RTP/RTCP** 之上）。实时媒体**对时延敏感、对丢帧宽容**——重传的包到达时早已错过播放时刻，反而加剧拥塞，所以**宁可丢帧也不重传**；网络抖动由接收端缓冲平滑。

**Q [⭐⭐]【5.1.Q4】：TCP 和 UDP 分别适合什么场景？**

A：**TCP**：需要**可靠、有序、不丢**的场景——文件传输、网页（HTTP）、邮件；**UDP**：需要**低时延、能容忍丢包**的场景——DNS 查询、实时音视频、游戏、广播/多播（UDP 支持一对一、一对多）。

### 5.2 TCP 三次握手 ⭐⭐⭐⭐

**Q [⭐⭐⭐]【5.2.Q1】：TCP 三次握手的过程是怎样的？**

A：

```
Client ──SYN──→ Server     （"我要连接"）
Client ←─SYN+ACK── Server  （"好的，我也要连接"）
Client ──ACK──→ Server     （"确认，开始通信"）
```

即：客户端发 SYN（含初始序号）→ 服务端回 SYN+ACK（确认并给出自己的初始序号）→ 客户端回 ACK 确认，连接建立。

**Q [⭐⭐⭐]【5.2.Q2】：为什么需要三次握手？两次不行吗？**

A：两次无法确认**客户端的接收能力**（也可能因**旧的 SYN** 滞留网络导致服务端误建立连接）。三次是"**双方都确认对方能收能发**"的最少次数：第 3 次 ACK 让服务端确认"客户端确实收到了我的 SYN+ACK"。

### 5.3 TCP 四次挥手 ⭐⭐⭐⭐

**Q [⭐⭐⭐]【5.3.Q1】：TCP 四次挥手的过程是怎样的？**

A：

```
Client ──FIN──→ Server   （"我发完了"）
Client ←─ACK─── Server    （"收到，等我发完"）
Client ←─FIN─── Server   （"我也发完了"）
Client ──ACK──→ Server     （"收到，再见"）
→ Client 等待 2MSL（报文最大存活时间）后关闭
```

**Q [⭐⭐⭐]【5.3.Q2】：为什么需要四次挥手？**

A：TCP 是**全双工**——每个方向需要**单独关闭**。服务端收到 FIN 后可能**还有数据要发**，所以先回 ACK（"我知道你要关了"），等自己数据发完再发 FIN，因此 ACK 与 FIN 不能合并。

**Q [⭐⭐]【5.3.Q3】：为什么客户端要等待 2MSL？**

A：**MSL** = 最大报文段生存时间。等待 2MSL 是为了：① 确保**最后一个 ACK 能到达服务端**——若丢失，服务端会重发 FIN，客户端还能响应；② 让本次连接的**所有滞留报文**都在网络中消失，避免影响后面的新连接。

### 5.4 TCP 拥塞控制 ⭐⭐⭐

**Q [⭐⭐⭐]【5.4.Q1】：简述 TCP 的拥塞控制方法（四个阶段）。**

A：**慢启动 → 拥塞避免 → 快重传 → 快恢复**。

| 阶段 | 窗口变化 | 触发条件 |
|---|---|---|
| **慢启动** | cwnd 从 1 开始**指数增长**（每 RTT 翻倍） | 初始 / 超时 |
| **拥塞避免** | **线性增长**（每 RTT +1） | 窗口达 ssthresh |
| **快重传** | 立即重传丢失报文 | 收到 **3 个重复 ACK** |
| **快恢复** | ssthresh = cwnd/2，cwnd = ssthresh | 快重传后 |

**Q [⭐⭐]【5.4.Q2】：慢启动为什么叫"慢"？拥塞和流量控制有什么区别？**

A：**"慢"不是指速度慢**，而是指从"小窗口"开始**逐步探测**——初始 cwnd = 1 MSS，指数增长，很快就能到高带宽。**流量控制**关注**接收方**（对方来不及收就请我慢下来，靠 rwnd 滑动窗口）；**拥塞控制**关注**网络整体**（中间链路的承载能力，靠 cwnd 与 AIMD 调整）。二者共同决定实际发送窗口 = min(rwnd, cwnd)。

### 5.5 传输层协议 vs 网络层协议 ⭐⭐⭐

**Q [⭐⭐⭐]【5.5.Q1】：传输层协议和网络层协议有什么区别？（TCP 和 IP 的区别）**

A：

| | 网络层（IP） | 传输层（TCP/UDP） |
|---|---|---|
| 通信范围 | **主机到主机**（host-to-host，服务器到服务器） | **进程到进程**（process-to-process，程序到程序） |
| 寻址依据 | **IP 地址**（主机/路由器接口） | **IP 地址 + 端口号**（具体进程） |
| 连接性 | **无连接**、尽力交付、不可靠 | TCP **面向连接可靠**；UDP 无连接不可靠 |
| 传输单位 | **IP 数据报** | TCP **报文段** / UDP **用户数据报** |
| 主要职责 | 路由选择、分组转发（寻路） | 复用/分用、可靠传输、流量与拥塞控制 |

**Q [⭐⭐]【5.5.Q2】：怎么用一句话区分传输层与网络层的职责？**

A："网络层回答'数据**去哪台主机**'（IP 寻址 + 路由），传输层回答'**给主机上的哪个进程**'（端口号）。IP 层只保证尽力交付，可靠性由 TCP 在上层补齐。"

## 6. 应用层

### 6.1 DNS 工作原理 ⭐⭐⭐【北航真题】

**Q [⭐⭐⭐]【6.1.Q1】：什么是 DNS？它的工作原理是什么？（北航真题）**

A：**DNS**（Domain Name System，域名系统）是互联网上作为**域名与 IP 地址相互映射**的一个**分布式数据库**，使用户不必记住机器直接读取的 IP 数字串。

**查询过程**：本地缓存 → **本地 DNS 服务器** → **根域名服务器** → **顶级域名服务器（TLD）** → **权威域名服务器**，拿到目的 IP。

**Q [⭐⭐]【6.1.Q2】：递归查询和迭代查询有什么区别？**

A：**递归查询**：客户端只问本地 DNS，本地 DNS **代为查询所有层级**并返回最终结果（通常是主机→本地 DNS 的方式）；**迭代查询**：本地 DNS 问根服务器，根返回"去问 TLD"，TLD 返回"去问权威"……由本地 DNS **自己逐级去问**（通常是本地 DNS→各级服务器的方式）。

**Q [⭐⭐]【6.1.Q3】：DNS 用什么传输层协议和端口？**

A：查询主要用 **UDP 53**（报文短、要求快、无连接开销）；当响应过长或做**区域传送**时改用 **TCP 53**。

### 6.2 HTTP ⭐⭐⭐

**Q [⭐⭐⭐]【6.2.Q1】：HTTP 各版本有哪些演进？分别解决了什么问题？**

A：

| 版本 | 特点 |
|---|---|
| **HTTP/1.0** | 短连接（每次请求新建 TCP） |
| **HTTP/1.1** | **长连接**（Keep-Alive），管道化 |
| **HTTP/2** | 多路复用、头部压缩、服务器推送 |
| **HTTP/3** | 基于 **QUIC（UDP）**，0-RTT 连接 |

一句话：HTTP/1.1 **长连接**解决短连接开销；HTTP/2 **多路复用**解决 HTTP 层的队头阻塞；HTTP/3 用 **QUIC(UDP)** 解决 **TCP 层的队头阻塞**与建连时延。

### 6.3 C/S 模型 vs P2P 模型 ⭐⭐

**Q [⭐⭐]【6.3.Q1】：C/S 模型和 P2P 模型有什么区别？**

A：

| | C/S（客户/服务器） | P2P（对等连接） |
|---|---|---|
| 角色 | **不对等**：服务器提供服务，客户请求服务 | **对等**：每台主机既是客户机也是服务器 |
| 服务器 | 必须**始终运行**、有固定 IP 地址 | **无中央服务器**，去中心化 |
| 扩展性 | 服务器是瓶颈——客户增多性能下降 | **可扩展性强**——节点越多资源越丰富 |
| 管理 | 集中管理、安全可控 | 无统一管理，安全问题更突出 |
| 场景 | HTTP、DNS、Email | BT 下载、区块链、视频直播 |

核心区别：**C/S 的用户间通信要由服务器中转，服务器故障会导致整个通信瘫痪；P2P 用户间直接通信、去掉了服务器这一层，没有单一的失败点**——一个用户的故障不影响整个 P2P 网络。

### 6.4 DHCP 动态主机配置协议 ⭐⭐

**Q [⭐⭐⭐]【6.4.Q1】：DHCP 的作用是什么？DORA 四步是什么？**

A：**功能**：自动为主机分配 **IP 地址、子网掩码、默认网关、DNS 服务器**等配置，实现**即插即用**。基于 **UDP**（客户机端口 68、服务器端口 67），全程**广播**进行。

**DORA 四步**：① **Discover（发现）**：客户机广播"谁有 IP 给我？"（源 0.0.0.0，目的 255.255.255.255）；② **Offer（提供）**：DHCP 服务器广播应答，提供可用 IP 配置；③ **Request（请求）**：客户机广播确认请求该 IP（同时隐式拒绝其他服务器的 Offer）；④ **Ack（确认）**：服务器广播确认，完成分配。

**Q [⭐⭐]【6.4.Q2】：DHCP 为什么全程广播？分配是永久的吗？**

A：因为请求时**客户机还没有 IP 地址**，只能用 0.0.0.0 作源地址、255.255.255.255 作目的地址，在**本网络内广播**寻找服务器。分配的 IP 有**租期**，到期需**续租**，因此可回收利用地址。

### 6.5 TFTP 简单文件传送协议 ⭐

**Q [⭐]【6.5.Q1】：TFTP 是什么？和 FTP 有什么区别？**

A：**TFTP**（Trivial File Transfer Protocol）：基于 **UDP** 的轻量文件传输协议（端口 **69**），只支持简单文件传输、**无交互、无认证/权限控制**，适用于局域网内的**小文件传输**——无盘工作站引导、路由器/交换机的**固件升级与配置文件备份**。**与 FTP 对比**：FTP 用 **TCP**、**双连接**、**有认证**，功能强但开销大；TFTP 用 UDP、单连接、无认证，简单快速。

### 6.6 综合题：在浏览器输入网址后发生了什么？⭐⭐⭐【北航真题】

**Q [⭐⭐⭐]【6.6.Q1】：在浏览器输入网址后发生了什么？各层用到什么协议？（北航真题）**

A：按"**解析域名 → 建立连接 → 请求响应 → 渲染**"这条主线展开，逐步点明所用协议与层次：

| 步骤 | 做的事 | 协议（层次） |
|---|---|---|
| 1 生成请求 | 查浏览器缓存 / 系统 hosts，未命中则准备 DNS 解析 | 应用层 |
| 2 **DNS 解析** | 本地 DNS → 根 → TLD → 权威服务器，拿到目的 IP | **DNS**（应用层，UDP 53） |
| 3 **路由与 ARP** | 查路由表定下一跳，用 ARP 得到网关 MAC，封装成帧 | **ARP**（网络/链路层）、**IP**（网络层） |
| 4 **TCP 握手** | 与服务器 443/80 端口三次握手建立连接 | **TCP**（传输层） |
| 5 **TLS 握手**（HTTPS） | 校验证书、协商会话密钥，建立加密通道 | TLS（传输层与应用层之间） |
| 6 **发 HTTP 请求** | 发送 GET 请求报文 | **HTTP**（应用层，基于 TCP） |
| 7 服务器响应 | 经反向代理/后端处理，返回 HTML 等资源 | HTTP |
| 8 **渲染** | 解析 HTML/CSS/JS，并发请求静态资源（HTTP/2 多路复用），构建 DOM 并渲染 | HTTP/HTTPS |

一句话总结："URL → DNS 解析出 IP → ARP 拿到网关 MAC → 三次握手建 TCP →（HTTPS 再走 TLS）→ 发 HTTP 请求 → 服务器返回 → 浏览器渲染。"自下而上依次是：链路层封装成帧、网络层 IP 寻路、传输层 TCP 建连、应用层 DNS/HTTP 干活。

## 7. 网络安全基础

### 7.1 数字证书 ⭐⭐

**Q [⭐⭐]【7.1.Q1】：什么是数字证书？它解决了什么问题？**

A：**数字证书**是 **CA（电子认证服务机构）** 签发的一种电子文档，是一串能够**表明网络用户身份信息**的数字，提供了在计算机网络上**验证网络用户身份**的方式。**解决的问题**：公钥密码中"我怎么确定这把公钥真的是对方的"——证书把**公钥**与**身份信息**绑定，由可信第三方 CA 签名背书。**内容**：持有者身份信息、公钥、有效期、CA 名称、**CA 的数字签名**。

**Q [⭐⭐]【7.1.Q2】：数字证书是怎么验证的？**

A：服务器下发证书 → 客户端用 **CA 的公钥验证证书签名** → 验签通过则信任证书内的公钥 → 用它协商会话密钥（TLS/HTTPS 即如此工作）。一句话："证书就是 CA 给公钥开的'身份证明'：CA 用私钥签名，大家用 CA 的公钥验签，从而确认'这把公钥属于这个人'。"

### 7.2 病毒、蠕虫、特洛伊木马的区别 ⭐⭐

**Q [⭐⭐]【7.2.Q1】：计算机病毒、蠕虫、特洛伊木马有什么区别？**

A：

| | 计算机病毒 | 蠕虫 | 特洛伊木马 |
|---|---|---|---|
| **本质** | 一段**可感染**的恶意代码 | 独立**能自我复制**的恶意程序 | 伪装成正常软件的恶意程序 |
| **传播** | **依附寄主**（文件/引导区），靠用户运行寄主传播 | **自主传播**，利用网络漏洞扫描感染，**无需寄主、无需用户操作** | **不自我复制**，靠伪装诱骗用户主动安装 |
| **典型行为** | 感染可执行文件、破坏数据 | 短时间耗尽带宽/资源，造成网络瘫痪 | 开后门、窃取账号密码、被远程控制（僵尸网络） |
| **关键区别** | 需要寄主 + 用户触发 | 能独立自我复制、主动扩散 | 不复制，靠欺骗 |

一句话："病毒靠寄主 + 人为触发传播，蠕虫能自主复制扩散（无需寄主），木马不复制、靠伪装骗你运行——一个是'传染'，一个是'自己繁殖'，一个是'伪装潜入'。"
