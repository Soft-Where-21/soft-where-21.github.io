## 题面

##  `I` 对抗

- 时间限制：1000ms  内存限制：65536kb       

### 题目描述

**注意，本题使用评测插件进行评测**

为了让大家对算法更深的理解，助教们决定以分组对抗的形式举办一场比赛。一共有*n*

名同学。每个同学都有一个编号——从1到*n*

的不同的整数。

比赛分多轮，每轮全员参加比赛。同学们被分成两个组，各组可能有不同数量的同学，但每个组必须至少有一名同学。位于不同组的同学之间存在对抗关系。

为了让大家在比赛中被充分调动，助教们希望每对同学都有过对抗关系。但是由于每轮比赛的安排耗费大量精力，助教们希望轮数越少越好。

请你帮助教们安排分组方案。

### 输入

输入仅一行。

仅一个数为学生人数n(***2 ≤ n ≤ 1000***)。

### 输出

第一行输出***m***

——最少轮次。

然后有***m***

行输出。

第***i***+1行中，先输出 ***f<sub>i</sub>*** ——第i轮第一组的人数（1 ≤***f<sub>i</sub>***< *n*） ，以及***f<sub>i</sub>***个1到*n*之间的数字，对应第一组的同学编号。在这轮中，其他同学将在第二组。数字间用空格分隔。同学编号顺序任意。

如果有多个最佳解决方案，请输出其中任何一个。

### 样例

#### 输入样例1

```c
2
```

#### 输出样例1

```c
1
1 1
```

#### 输入样例2

```c
5
```

#### 输出样例1

```c
3
1 1
3 1 2 3
2 2 4
```

## 题解

### 思路详解

​		阅读完题面之后，我们大致清楚我们的过程是什么，即我们需要让**任意一名**同学与**其他所有**同学都对抗交手一次。如果我们**抽象化**一下，不妨按照题意给每一个同学都**编上一个从1~n的序号**，那么我们需要通过对抗交手使得**二元对（x,y）**（1<=x<=n,1<=y<=10）**全部出现**。如果我们用**图形**来表示的化，我们需要将下图的**灰色矩形填满**（我们以n=10作为例子）![1](.\1.png)

​		但是由于对抗交手**不存在顺序**问题，而且**自己不和自己对抗交手**，因此，我们需要填充的图案有原来的**灰色矩形变成一个灰色的阶梯形**

![2](.\2.png)

​		**现在目标很明确了，就是怎么把灰色区域填满。**此时我们再来考虑一下分组对抗的图形含义，就不难发现**两个人进行了交手对抗**就意味着**填充了以这两个人编号为横纵坐标的矩形区域**。

​		注意到题面是**轮数越少越好**，所以我们需要通过**最少的填充次数**完成我们的目标。

​		那么我们要怎么填充最快呢，那就**每一次都填充最多的矩形区域**呗（其实就是**贪心**嘛），学过高等数学的我们都知道，第一次可以填充最多的矩形区域的方法就是**填充当前阶梯形图案的最大矩形**，如图所示（黄色）：

![3](.\3.png)

​		因此不难看出我们的第一分组可以是： 

> 6 7 8 9 10
>
> 1 2 3 4 5



​		完成了第一次分组对抗之后，我们出现另外两个小的阶梯形，为了填充最大面积，我们还是要**填充当前阶梯形图案的最大矩形**，如图所示（蓝色）：

![4](.\4.png)

​		因此不难看出我们的第二分组可以是： 

> 3 4 5 9 10
>
> 1 2 6 7 8

​		这里的矩形其实**有两种填法**，就如上图所示的一个是2\*3的矩形，一个是3\*2的矩形，为了**对称**，所以我这么填充，其实两个都是2\*3或者两个都是3\*2也可以。

​		

​			以此类推，第三次填充结果为（橙色）：

![5](.\5.png)

​		第三次分组为：

> 2 5 8 10
>
> 1 3 4 6 7 9



​		以此类推，第四次填充结果为（绿色）：

![6](.\6.png)

​		第四次分组为：

> 4 7
>
> 1 2 3 5 6 8 9 10



​		上面是对于n=10的全部模拟，此时我们再想想看，好像第二，三，四次分组的需要填充的阶梯形和第一次的大灰色阶梯形**好像**，只不过是**缩小版**，如果你发现了这个，其实就是一个**很好的开始**。如果你再注意到我们**填充的策略好像也是一模一样的**，那么这个题的难度就直线降低了。

​		假设你已经清楚以上的两点了，那么此时我们再把这个题抽象化，其实就是一个**递归分治**的问题，**每一次都会出现子问题，而且子问题的求解方式和原问题一模一样**，我们先处理当前情况，处理完之后会出现**另外两个子问题**，再处理，再出现，直到处理完毕后结束。

​		所以我们就可以开始我们的**关键算法书写**了，不妨设其名字为`merge`，有三个参数：`merge(int l, int r, int depth)`，分别是左端，右端，**第几次分组（简称层）**。

​		首先我们需要算出来填充的边长，不难发现，其实只需要算出**中点（向上取整）**即可。
$$
mid = ceil((l + r) / 2.0);
$$
​		然后我们将**从中点至右端的所有元素放置入该层（depth）的数组**即可，如果是C++的话，用`vector`容器即可记录，如果是C的话，利用一个二维数组模拟栈，外加一个一维的top数组也可以实现记录该层的元素。

​		最后输出结果输出分组的成员个数时，C++直接输出`vector.size()`即可，C就直接输出top数组的值即可。

​		

​		此时我们回过头来思考最少的分组次数，由于每一次都会出现两个子问题，而且子问题的求解方式和原问题一模一样，此时我们**关注横轴，不关注纵轴**，发现**第一次取了横轴的一半**，**第二次取了横轴的一半的一半**，依次类推，其实最终答案就是`(int)ceil(log2(n))`。

### 时间复杂度分析

​		问题的规模为n , 关键算法`merge`中记录数据的时间复杂度为**O(n)**，递归之后总体时间复杂度为**O(n \* log<sub>2</sub><sup>n</sup>)** ，输出数据为**O(n \* log<sub>2</sub><sup>n</sup>)**  ，故总时间复杂度为**O(n \* log<sub>2</sub><sup>n</sup>)** .

### 参考代码（C++）

```c++
#include <bits/stdc++.h>
#define mp make_pair
#define ms(a, b) memset(a, b, sizeof(a))
#define maxn 17
typedef long long LL;
using namespace std;
int n;
vector<int> v[maxn];	// 记录每一次分组的人员编号 
void merge(int l, int r, int depth)	//分治算法 
{
    if (l > r)
        return;
    int mid = (int)ceil((double)(l + r) / 2.0);	//计算中点 
    for (int i = mid; i <= r; i++)
    {
        v[depth].push_back(i);		//记录该层的结点编号 
    }
    merge(l, mid - 1, depth + 1);	//递归处理左半部分 
    merge(mid + 1, r, depth + 1);	//递归处理右半部分
}
int main()
{
   	scanf("%d",&n); 
    int layer = (int)ceil(log2(n));	//计算最小次数 
	printf("%d\n",layer);
    merge(1, n, 0);
    for (int i = 0; i < layer; i++)
    {
        printf("%d ",v[i].size());	//分组人数 
        for (int j = 0; j < v[i].size(); j++)
        {
            printf("%d ",v[i][j]);	//输入分组人数的对应编号 
        }
        putchar('\n');
    }
    return 0;
}
```
