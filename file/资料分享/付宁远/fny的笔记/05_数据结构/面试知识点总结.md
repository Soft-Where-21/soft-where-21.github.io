---

> [!abstract]+ 学科总览
> 数据结构可以按"线性 vs 非线性"分成两块，而每块内部又有清晰的递进逻辑：
>
> - **线性结构**（数组→链表→栈→队列）：数组最简单但最死板，链表灵活但查得慢，栈和队列是"操作受限"的线性表——限制反而带来特定场景的高效。哈希表虽然不算严格的线性结构，但它用数组做底层，核心问题是"如何快速查找"，所以也放在线性部分。
> - **树形结构**（二叉树→BST→AVL/红黑树→堆→B/B+树）：这条线是"二叉搜索树为了效率不断升级"的故事——BST会退化→AVL严格平衡但旋转多→红黑树近似平衡旋转少→堆放弃查找专注优先级→B+树为磁盘优化。
> - **图**：比树更一般的结构，树是"无圈连通图"。两个核心问题：**怎么存**（邻接矩阵/邻接表）和**怎么用**（遍历、最短路、最小生成树）。
> - **排序**：可以看作数据结构的应用，不同结构适合不同排序。
> - **算法思想**（分治/DP）和 **C 语言基础**：北航软院复试的题单里，"数据结构与算法"与"C 语言与其他"是并列的两块，本笔记把两块都收进来，避免面试时两头找。
> - **第 1 章"薄弱点速攻"**：把自评为薄弱、面试又爱连环追问的 9 个小节（B/B+ 树、哈夫曼树、最小生成树、最短路径、0-1 背包、数组指针/指针数组、struct/union、static、面向对象三特性）从原章节抽出前置，便于优先攻克。因此本章**不按结构递进组织**，而是"薄弱优先"；原章节保留其余知识点，**全部编号已整体重排**（旧 3.4 / 3.5 → 新 1.1 / 1.2，其余同理）。
>
> 整条暗线：**线性结构是基础 → 树是线性到非线性的过渡 → 图是最一般的非线性结构 → 排序/图算法是结构的应用**。每个新结构都是前一个"不够用"时的升级。

### 1.1 B 树与 B+ 树 ⭐⭐⭐

**为什么需要多路树**：磁盘/SSD 的 I/O 以**块**（page，典型 4KB~16KB）为单位，一次读一大块。二叉树每访问一个结点就要一次 I/O，树高 $O(\log_2 n)$ 太大；把每个结点做成"一页能装下的多路结点"，树高降到 $O(\log_m n)$（如 m=500 时 3 层可索引上亿条记录），I/O 次数大幅减少。

**B 树（m 阶 B 树，m-way search tree）的定义**：
1. 每个结点最多 **m 棵子树**、**m-1 个关键字**；
2. 根结点若不是叶子，至少 **2 棵子树**；
3. 除根外的非叶结点至少 **$\lceil m/2 \rceil$ 棵子树**（即至少 $\lceil m/2\rceil - 1$ 个关键字）；
4. 结点内关键字**有序**，子树的关键字都落在相邻关键字划出的区间内（$k_1 <$ 子树1 $< k_2 <$ 子树2 $\dots$）；
5. **所有叶子在同一层**（完全平衡）；
6. **所有结点都存数据**（关键字 + 卫星数据/记录指针）。

**B+ 树的定义**：
1. **内部结点只存索引 key**（不存数据），只有**叶子结点存数据**；
2. 内部出现的 key 会**在叶子中再出现一次**（叶子是最完整的一层索引）；
3. **所有叶子按 key 顺序用链表串起来**，支持顺序扫描与范围查询；
4. 叶子在同一层、树完全平衡。

| | B 树 | B+ 树 |
|---|---|---|
| 数据位置 | **所有结点**都能存数据 | **只有叶子节点**存数据，内部只存 key |
| key 是否重复 | 不重复 | 内部 key 在叶子**重复出现** |
| 查找终点 | 可能在内部结点命中，**提前结束** | **必须走到叶子**，路径长度稳定（利于预测） |
| 单结点容量 | 小（要挤下数据） | **大**（只存 key+指针）→ 树更矮 → I/O 更少 |
| 范围查询 | 需中序遍历 + 回溯，I/O 多 | **叶子链表**顺序扫描，极快 |
| 插入删除 | 可能引起结点分裂/合并，改动内部结构 | 数据只在叶子，内部结点更稳定 |
| 典型应用 | 部分文件系统、内存索引 | **数据库索引**（MySQL InnoDB）、文件系统 |

> [!tip]+ 面试一句话
> B+ 树是数据库索引的标配——内部节点只存 key 使树更矮（I/O 更少），叶子链表使范围查询极快。

**数据库查询优化有哪些方法（老师追问）**——按"从 SQL 到架构"的层次答：

| 层次 | 常用手段 |
|------|----------|
| **索引** | 给 WHERE/JOIN/ORDER BY 的高**区分度**列建 B+ 树索引；**覆盖索引**（查询列全在索引中，避免回表）；**联合索引**遵循**最左前缀**原则；避免在索引列上做函数运算/隐式类型转换/`%like` 前置通配符（会导致索引失效） |
| **SQL 重写** | 用 JOIN 代替嵌套子查询；`SELECT` 只取需要的列；谓词尽早过滤（谓词下推）；大表分页用**延迟关联/游标分页**替代大 `OFFSET`；大表 `EXISTS` 代替 `IN`；无需去重时用 `UNION ALL` |
| **执行计划** | `EXPLAIN` 看访问类型（`type`）、命中索引（`key`）、扫描行数（`rows`）、`Extra` 是否出现 `Using filesort`/`Using temporary`，据此改写 |
| **表结构** | 范式化减少冗余 / 适度反范式减少 JOIN；字段类型尽量小；大表**水平分表、分区** |
| **数据库内部** | 基于代价的优化（CBO）：根据统计信息估算选择率与代价，选连接顺序（动态规划/贪心）、选连接算法（嵌套循环 / 哈希连接 / 排序合并连接）；统计信息需定期 `ANALYZE` |
| **架构** | 加缓存（Redis）；读写分离/主从复制；批量代替逐条；缩短事务避免锁竞争；分库分表 |

> [!tip]+ 一句话兜底
> 查询优化 = **少读数据（索引/减少 I/O）** + **早点过滤（谓词下推/减少中间结果）** + **别让优化器选错（统计信息、避免索引失效）**。核心指标永远是"扫描了多少行、发生了几次 I/O"。

### 1.2 哈夫曼树与哈夫曼编码 ⭐⭐⭐

**哈夫曼树（Huffman tree，最优二叉树）**：给定 n 个带权**叶子**结点，构造一棵**带权路径长度（WPL）最小**的二叉树。

**带权路径长度 WPL**：

$$\text{WPL} = \sum_{i=1}^{n} w_i \times l_i$$

其中 $w_i$ 是第 $i$ 个叶子的权值，$l_i$ 是该叶子的**路径长度**（从根到叶经过的**边数**，也等于层数）。

**构造方法（贪心）**：
1. 把 n 个权值各看成只有根结点的树，组成集合 F；
2. 从 F 中取出**权值最小的两棵树**，合并成一棵新树，根的权 = 两子树根权之和；
3. 把新树放回 F，重复 ②，直到 F 中只剩一棵树。

**用最小堆维护"取两个最小值"**，每次 O(log n)，共 n-1 次合并 → **$O(n\log n)$**。

**性质**：
- 哈夫曼树中**没有度为 1 的结点**（每次都是两两合并）；
- n 个叶子的哈夫曼树共有 **2n-1** 个结点；
- WPL 最小（可用"权值越小的叶子离根越远"的贪心交换论证证明）；
- 权值相同时树形**不唯一**，但 WPL 相同。

**哈夫曼编码**：由哈夫曼树生成的一种**变长前缀编码**——左分支记 0、右分支记 1（或反之），从根到每个叶子的路径上的比特序列就是该字符的编码。**频率高的字符编码短、频率低的编码长**，使得**平均码长最短**。

**为什么是前缀编码（异字头编码）**：编码只对应**叶子**结点，任何叶子都不是另一个叶子的祖先，所以**没有一个编码是另一个编码的前缀** → 解码时从左到右读入、一旦匹配到某个叶子就输出该字符、回到根继续，**无需分隔符、无歧义**。

**平均码长**：$\bar{L} = \sum p_i l_i$（$p_i$ 为字符出现概率），恰好等于 WPL / 总频率。对比**定长编码**需要 $\lceil \log_2 n\rceil$ 位/字符。

**应用与局限**：
- 应用：文件压缩（ZIP 的 DEFLATE、JPEG/MP3 的熵编码阶段）、传真机编码；
- 局限：需要**事先统计全部字符频率**（两遍扫描，无法边读边压）；只能整数位编码（无法达到信息论下界，算术编码/区间编码可突破）；频率分布失真时压缩率下降；可用**自适应哈夫曼（动态哈夫曼）**边读边更新建树。

> [!tip]+ 面试一句话
> 哈夫曼树是"权值越大离根越近"的贪心最优二叉树，WPL 最小；哈夫曼编码就是它的叶子路径编码，是变长前缀码，保证解码无歧义。

### 1.3 最小生成树：Prim 与 Kruskal ⭐⭐⭐

**生成树（spanning tree）**：连通无向图 $G=(V,E)$ 的一棵**包含全部 n 个顶点、恰好 n-1 条边**的连通无圈子图（就是 $G$ 的极小连通子图）。

**最小生成树（MST, Minimum Spanning Tree）**：带权连通图中**边权之和最小**的生成树。注意：
- 边权和最小是唯一确定的，但 **MST 本身可能不唯一**（存在等权边时）；
- 只有**连通**图才有生成树；非连通图得到的是**最小生成森林**；
- MST 只适用于**无向图**（有向图对应的是"最小树形图"，用朱刘算法）。

**切割性质（cut property，贪心正确性的依据）**：对图的任意一个顶点划分 $(S, V-S)$，横跨该切割的**权最小的边**一定属于某棵 MST。Prim 与 Kruskal 都是这条性质的两种不同应用——**Prim 贪点、Kruskal 贪边**。

**Prim 算法（普里姆）——从点扩展**：
1. 任选一个顶点加入集合 $S$（已生成树的部分），其余在 $V-S$；
2. 维护 $d[v]$ = 顶点 $v$（在 $V-S$ 中）**到集合 $S$ 中任一点的最小边权**，$pre[v]$ 记录该边另一端；
3. 每轮从 $V-S$ 中选 $d[v]$ 最小的顶点 $u$ 加入 $S$（并入边 $(u, pre[u])$）；
4. 用 $u$ 的邻边**松弛**所有 $v \in V-S$：若 $w(u,v) < d[v]$ 则更新 $d[v]$；
5. 重复 n-1 次。

复杂度：邻接矩阵 + 朴素选最小 **$O(V^2)$**；邻接表 + 二叉堆 **$O(E\log V)$**；斐波那契堆 $O(E + V\log V)$。

> [!warning]+ 易错点（务必分清）
> Prim 的 $d[v]$ 是"$v$ 到**已生成树集合**的最小边权"，而 Dijkstra 的 $dist[v]$ 是"$v$ 到**起点**的路径长度"。两者代码骨架几乎一样，**含义完全不同**——这是最高频的混淆点。

**Kruskal 算法（克鲁斯卡尔）——从边扩展**：
1. 把所有边按权值**从小到大排序**；
2. 依次取出每条边 $(u,v)$，用**并查集（union-find）**判断 $u,v$ 是否已在同一连通分量中；
3. 若不在同一分量 → **选入该边**并合并两分量；若已在同一分量 → **丢弃**（选它会成环）；
4. 选满 **n-1** 条边即结束。

复杂度：排序 $O(E\log E)$ + 并查集（路径压缩 + 按秩合并，近似 $O(\alpha(E))$ ≈ O(1)）→ 总计 **$O(E\log E)$**。

**并查集三件套**：`find`（带路径压缩）、`union`（按秩/按大小合并）、父数组 `fa[]`。

```c
/* 并查集（C89 风格） */
int fa[MAXV];

void init(int n) { int i; for (i = 0; i < n; i++) fa[i] = i; }

int find(int x)
{
    while (fa[x] != x) { fa[x] = fa[fa[x]]; x = fa[x]; }  /* 路径压缩（迭代写法） */
    return x;
}

int unite(int a, int b)
{
    int ra = find(a), rb = find(b);
    if (ra == rb) return 0;      /* 已连通 → 成环，不能加 */
    fa[ra] = rb;
    return 1;                    /* 可加 */
}
```

**两者对比**：

| 维度 | Prim | Kruskal |
|------|------|---------|
| 贪心对象 | **顶点**（每次选离树最近的点） | **边**（每次选最小且不成环的边） |
| 数据结构 | 优先队列/数组存 $d[]$ | 排序 + **并查集** |
| 复杂度 | $O(V^2)$ 或 $O(E\log V)$ | $O(E\log E)$ |
| 适合 | **稠密图**（$E$ 接近 $V^2$） | **稀疏图**（$E \ll V^2$） |
| 中间状态 | 始终是**一棵树** | 可能是**森林**，最后才连成树 |
| 判环方式 | 天然无环（只从 $V-S$ 取点） | 靠并查集判环 |
| 能否处理非连通 | 可，得到最小生成森林 | 可，得到最小生成森林 |

**为什么贪心能得到全局最优**：由切割性质，每一步都不会"错过"最优解（可用交换论证证明：若最优解不含当前选的最轻横切边，把该边换进去仍然最优）。

### 1.4 最短路径：Dijkstra、Bellman-Ford 与 Floyd ⭐⭐⭐

三类问题：**单源最短路**（一个起点到所有点）、**单终点**（图上反向跑即可）、**全源最短路**（任意两点间）。

| 算法 | 解决 | 适用权值 | 复杂度 | 核心思想 |
|------|------|----------|--------|----------|
| **BFS** | 单源 | 无权（或边权全等） | $O(V+E)$ | 层序扩展 |
| **Dijkstra** | 单源 | **非负权** | $O(V^2)$ / $O(E\log V)$ | **贪心**：每次选当前最近的未确定点 |
| **Bellman-Ford** | 单源 | 可含**负权** | $O(VE)$ | **DP**：对所有边松弛 $V-1$ 轮；第 $V$ 轮还能松弛 → 存在负环 |
| **SPFA** | 单源 | 可含负权 | 平均 $O(KE)$，最坏 $O(VE)$ | Bellman-Ford 的队列优化 |
| **Floyd-Warshall** | **全源** | 可含负权，**不能有负环** | $O(V^3)$ | **DP**：以"允许经过的前 k 个点为中转"为阶段 |

**Dijkstra 算法（单源、非负权）**：
1. 初始化 $dist[s] = 0$，其余为 ∞，所有点未确定；
2. 每次从未确定的点中取 $dist$ **最小**的点 $u$，标记为已确定；
3. 用 $u$ 松弛它的所有出边：若 $dist[u] + w(u,v) < dist[v]$ 则更新 $dist[v]$（并记 $pre[v]=u$）；
4. 重复 n 次。

复杂度：邻接矩阵朴素实现 **$O(V^2)$**（适合稠密图）；邻接表 + 优先队列（二叉堆）**$O(E\log V)$**（适合稀疏图）。要求所有边权非负。

> [!warning]+ Dijkstra 为什么不能有负权边
> 算法的正确性依赖一条**贪心假设**："一旦某个点被取出（$dist$ 最小），它的最短路就已最终确定、不会再被更新。"
> 负权会打破它：如果之后发现的路径经过一个负权边，可能得到比已确定值更短的路径，但算法已经把这个点"封"了，不会再修正。
> **典型反例**：边 $A\to B=1$、$A\to C=5$、$C\to B=-3$。Dijkstra 先确定 $dist[B]=1$（经 $A\to B$），之后发现 $A\to C \to B = 2$…… 更狠的例子是 $A\to B=2,\ A\to C=5,\ C\to B=-4$ → 真值 1 < 2，已被封的 $B$ 却停留在 2。
> 结论：**有负权边 → 用 Bellman-Ford / SPFA**。

**Floyd-Warshall 算法（全源最短路，DP）**：
- 状态 $d^{(k)}[i][j]$ = 只允许用前 $k$ 个顶点作为**中转点**时，$i$ 到 $j$ 的最短距离；
- 转移方程：

$$d[i][j] = \min\bigl(d[i][j],\ d[i][k] + d[k][j]\bigr)$$

- 初始 $d[i][i]=0$、$d[i][j]=w(i,j)$、无边为 ∞；
- 三重循环，**中转点 $k$ 必须在最外层**，然后 $i$、$j$ 各一层 → $O(V^3)$，空间 $O(V^2)$（就地在原矩阵上更新即可）。

```c
/* Floyd 核心三重循环（C89 风格） */
for (k = 0; k < n; k++)
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];

/* 负环检测：结束后若存在 d[i][i] < 0，则从 i 出发可达负权回路 */
```

- **为什么 $k$ 在最外层**：$k$ 是"阶段"（允许哪些中转点），$i,j$ 是"状态"。若把 $k$ 放最内层，$d[i][j]$ 会在同一轮里用"尚未准备完整的 $d[i][k], d[k][j]$"更新，DP 的阶段顺序被破坏，结果可能错误。
- **负权与负环**：Floyd 允许负权边（因为它是 DP 而非贪心），但**不允许负权回路**——有负环时最短路无意义（可以一直绕圈变小）。检测方法：跑完后若 $d[i][i] < 0$ 说明存在负环。
- **INF 溢出**：若用 `0x3f3f3f3f` 之类作 ∞，注意 `d[i][k]+d[k][j]` 两次 INF 相加可能溢出，稳妥写法是先判断 `d[i][k] != INF && d[k][j] != INF`。

**Dijkstra vs Floyd vs Bellman-Ford 一句话区分**：

| 对比项 | Dijkstra | Floyd | Bellman-Ford |
|--------|----------|-------|--------------|
| 问题 | 单源 | **全源** | 单源 |
| 负权 | ❌ 不允许 | ✅ 允许（无负环） | ✅ 允许（能检负环） |
| 思想 | 贪心 | 区间 DP | 边松弛 DP |
| 用途 | 导航、路由（OSPF 用 Dijkstra） | 小图任意两点、传递闭包 | 汇率套利检测、有负权场景 |

### 1.5 0-1 背包与伪多项式时间 ⭐⭐⭐

**0-1 背包问题**：给定 n 件物品，第 i 件重 $w_i$、价值 $v_i$；背包容量 $W$；每件物品**要么全拿要么不拿**（0-1），求能装下的最大总价值。

**状态定义**：$dp[i][w]$ = 只考虑前 $i$ 件物品、容量为 $w$ 时的最大价值。

**状态转移方程**：

$$dp[i][w] = \begin{cases} dp[i-1][w], & w < w_i \quad (\text{装不下}) \\ \max\bigl(dp[i-1][w],\ dp[i-1][w-w_i] + v_i\bigr), & w \ge w_i \end{cases}$$

**边界**：$dp[0][w] = 0$（没有物品时价值为 0），$dp[i][0]=0$。

**答案**：$dp[n][W]$。

**时间复杂度 $O(nW)$**：外层枚举 n 件物品、内层枚举容量 $0 \sim W$，每次转移 O(1)，故为 $O(nW)$。
**空间复杂度**：二维 $O(nW)$；可用**滚动数组**（倒序枚举容量 $w$ 从 $W$ 到 $w_i$）压到 $O(W)$——倒序是保证每件物品**只用一次**（用到了上一层尚未被覆盖的值）。

```c
/* 0-1 背包：一维滚动数组，容量必须倒序（C89 风格） */
#define MAXW 10005
int dp[MAXW];

int knapsack(int n, int W, int w[], int v[])
{
    int i, j;
    for (j = 0; j <= W; j++) dp[j] = 0;             /* 初始化 */
    for (i = 0; i < n; i++)
        for (j = W; j >= w[i]; j--)                 /* 倒序！正序就成了完全背包 */
            if (dp[j - w[i]] + v[i] > dp[j])
                dp[j] = dp[j - w[i]] + v[i];
    return dp[W];
}
```

> [!warning]+ 正序 / 倒序的区别（高频陷阱）
> 一维数组中**容量倒序**枚举 → 0-1 背包（每件只用一次）；**正序**枚举 → **完全背包**（每件可用无限次）。

**$O(nW)$ 是多项式时间复杂度吗？——不是，它是"伪多项式时间（pseudo-polynomial time）"**：

1. **多项式时间的定义**：算法复杂度是**输入规模（输入的长度，即编码位数）**的多项式。这里的"规模"指**编码长度**，不是某个数值本身。
2. 输入长度：n 件物品 + 容量 W。存 W 只需要 $\lceil \log_2 W \rceil$ 位二进制，所以**输入长度 $L \approx O(n\log W)$，而 W 可以是指数级大的数值**（如 $W = 2^{100}$）。
3. 于是 $O(nW)$ 写成输入长度的形式是 $O(n \cdot 2^{L})$——**对输入长度是指数级的**，不是多项式。
4. 直觉：若把容量从 $W$ 增到 $2W$，输入只多 1 个二进制位，但算法时间翻倍。这是"**数值大小线性、但数值位数指数**"的典型特征，故称**伪多项式**（也叫"在 n 和 W 的数值上多项式"）。
5. **为什么要区分**：
   - 0-1 背包的**判定版本**（"是否存在价值 ≥ V 的装法"）是 **NP 完全**的。如果 $O(nW)$ 算多项式时间，就等于证明了 P = NP——所以它**必须不是**多项式时间，否则矛盾；
   - 实际中 W 很大时（如 W 达 $10^9$）$O(nW)$ 直接不可用，此时要靠**近似算法 / 分支限界 / meet-in-the-middle** 等方法。
6. **特例**：如果题目保证 $W$ 是 $n$ 的多项式（$W = \text{poly}(n)$），那么 $O(nW)$ 在这个受限输入类上确实是多项式时间——这也叫**弱 NP 完全**问题的特征（存在伪多项式算法）。
7. **对比**：**分数背包**（可以切分物品）用贪心 **$O(n\log n)$**，是真正的多项式时间；所以"背包问题是不是多项式可解"必须区分 0-1 与分数两种版本。

> [!tip]+ 面试怎么答（老师问"是不是多项式时间复杂度"）
> 直接答："**不是多项式时间，它是伪多项式时间。** 因为复杂度是 $O(nW)$，对容量 W 是线性的，但 W 是**数值**而不是**输入规模**——输入里表示 W 只需要 $\log W$ 个二进制位，所以按输入长度看是指数级的。反过来，如果它是多项式时间，那么 NP 完全的背包判定问题就有多项式解法，P 就等于 NP 了。"
> 这一句同时命中三个得分点：**定义（对输入长度）**、**伪多项式的来源（数值 vs 位数）**、**与 NP 的关系**。

### 1.6 数组名、数组指针与指针数组 ⭐⭐⭐

**数组名是什么类型**：`int a[5];` 中 `a` 的类型是 **`int[5]`（数组类型）**，它**不是指针变量**——数组名是"数组对象的名字"，本身代表一整块连续内存。

**但在表达式中，数组名会"退化（decay）"成指向首元素的指针 `int*`**（更准确地说：除了少数例外，数组类型的表达式被转换为其首元素的指针，值是首地址）。这个退化让 `a[i]` 等价于 `*(a+i)`，也让数组能传给形参是指针的函数。

**两个"不退化"的例外（高频考点）**：
1. **`sizeof(a)`**：得到**整个数组的字节数**（`5 * sizeof(int)`），而 `sizeof` 指针是 8（64 位）。若在函数内部对形参写 `sizeof`，会得到指针大小——所以"在函数里用 sizeof 求数组长度"是经典错误。
2. **`&a`**：得到 **`int (*)[5]`（指向整个数组的指针）**，`&a + 1` 跳过**整个数组**（20 字节），而 `a + 1` 只跳过**一个元素**（4 字节）。

（严格地说 C11 还有 `_Alignof` 和字符串字面量初始化等情形，但面试只需答前两条。）

**关系总结**：`a` 与 `&a[0]` 的**值相同**（都是首地址）、但**类型不同**（`int*` vs `int(*)[5]`）——指针的值只看"指向哪"，指针的类型决定"加减 1 走多远"和"解引用取多少字节"。

| 写法 | 类型 | `+1` 跳过 | 说明 |
|------|------|-----------|------|
| `a`（`int a[5]`） | `int[5]` → 退化为 `int*` | 4 字节（一个元素） | 数组名，不是左值，不能赋值/自增 |
| `&a[0]` | `int*` | 4 字节 | 首元素地址 |
| `&a` | `int (*)[5]` | **20 字节（整个数组）** | 数组指针 |
| `int (*p)[5]` | 指向含 5 个 int 的数组的**指针** | 20 字节 | **数组指针**，`p = a` 合法 |
| `int *p[5]` | 含 5 个 `int*` 的**数组** | （数组，`p[0]` 才是指针） | **指针数组**，别和上面混 |
| `int *p` | 指针，指向 int | 4 字节 | `p = a;` 合法（退化赋值） |

**"数组指针"vs"指针数组"（一句话）**：看**运算符结合优先级**——`()` 和 `[]` 先于 `*`。`int (*p)[5]` 是"指针，指向数组"（数组指针）；`int *p[5]` 是"数组，元素是指针"（指针数组）。

**函数形参中的数组会退化为指针**：`void f(int a[5])`、`void f(int a[])`、`void f(int *a)` **三者完全等价**，编译器只传首地址。因此：
- 函数内 `sizeof(a)` = 8（指针），不是 20；
- 想要数组长度必须**另传一个长度参数**（这也是 C89 风格代码里到处传 `n` 的原因）；
- 想要"整块数组的指针"必须显式写 `int (*a)[5]` 才不退化为 `int*`。

**C 语言指针和数组"实际的类型"**（把上面的结论汇成一段可背的话）：
- `int a[10]`：`a` 的类型是 `int[10]`；
- `int *p = a`：`p` 的类型是 `int*`（退化的产物）；
- 两者**不是一回事**：`a` 不可赋值、不可自增、`sizeof` 得 40；`p` 是变量，可自增、`sizeof` 得 8；
- **"数组名就是一个常量指针"是常见但不严谨的说法**：值上像，类型与语义上不同（数组名不是左值、不占指针变量那 8 字节）。

**延伸：函数名、函数指针、函数入口地址的区别**（同族真题）：
- **函数名**：类型为"函数类型"如 `int(int,int)`，在表达式中退化为**函数指针** `int (*)(int,int)`，值是函数的入口地址；
- **函数入口地址**：函数被编译成一段代码，其首字节地址即入口地址，`&f` 与 `f` 的值相同；
- **函数指针**：`int (*fp)(int,int) = f;` 是**变量**，可赋值、可放入数组/结构体、可作为回调参数；`(*fp)(1,2)` 与 `fp(1,2)` 等价；
- 差异用一句话说：**函数名是"函数的名字"（不可赋值，退化为地址），函数指针是"存地址的变量"（可赋值、可指向不同的函数）**，函数入口地址是"那段代码的起始地址（数值）"。

```c
/* 函数指针与回调（C89 风格） */
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int apply(int (*op)(int, int), int x, int y) { return op(x, y); }

/* 调用：apply(add, 3, 4);  apply(sub, 3, 4); */
```

### 1.7 struct 与 union ⭐⭐⭐

**共同点**：都是由**多个不同类型成员**组成的**用户自定义复合类型**；成员都用 `.`（或指针的 `->`）访问；都可以定义变量、数组、指针。

**不同点**：

| 维度 | struct（结构体） | union（共用体/联合体） |
|------|------------------|------------------------|
| 内存分配 | **每个成员各分配**空间（可能插入**对齐填充**） | 所有成员**共用同一块**空间（起始地址相同） |
| 占用大小 | ≥ 各成员大小之和（+ 填充，且为最大对齐的整数倍） | = **最大成员的大小**（向上取整到最大对齐） |
| 同时有效 | 所有成员**同时存在、互不干扰** | 同一时刻只有**一个**成员有效；新赋值**覆盖重写**旧成员 |
| 用途 | 把多个属性打包成一个整体（如链表结点、记录） | 多个成员**互斥复用**同一块内存（协议解析、位域、类型双关、省内存） |
| 初始化（C89） | 可按顺序初始化所有成员 | 只能初始化**第一个**成员（C99 起支持指定初始化器 `.i = 1`） |
| 修改一个成员 | 不影响其它成员 | 会**改变**其它成员的字节解释（可能得到无意义的值） |

```c
struct S { char c; int i; };   /* 通常 sizeof = 8：c 占 1 + 3 字节填充 + i 占 4 */
union  U { char c; int i; };   /* 通常 sizeof = 4：max(1, 4) = 4 */
```

**内存对齐（顺带常问）**：成员按自身大小对齐（如 `int` 按 4 对齐），结构体总大小补到**最大成员对齐数的整数倍**。所以 `struct { char c; int i; }` 是 8 而不是 5。调整成员顺序（把小的放一起）可以减小填充。

**union 的实际用途**：
1. **判断大小端**：
```c
union { unsigned int i; unsigned char c[4]; } u;
u.i = 1;
if (u.c[0] == 1) printf("小端\n"); else printf("大端\n");
```
   （小端：低位字节存低地址，`u.c[0]` 是 1；大端反之。）
2. **协议/报文解析**：同一段字节按不同格式（如 4 字节 vs 2 个 short）解释；
3. **寄存器/状态机中的互斥字段**：省内存（嵌入式常用）；
4. **类型双关（type punning）**：用同一块内存按不同类型读——注意这依赖字节序和平台对齐，行为是实现定义的，跨平台不可靠。

**为什么 union 的成员会互相覆盖**：它们地址相同，`u.i = 1` 写的是同一块 4 字节内存；此时再读 `u.c` 取的是这 4 字节中的某 1 个字节（取决于字节序），所以"新的赋值会重写覆盖"。

### 1.8 static 关键字的作用 ⭐⭐⭐

`static` 有两层含义，务必分开说：**存储期（storage duration）**和**链接属性（linkage）**。

| 修饰对象 | 作用 | 关键点 |
|----------|------|--------|
| **全局变量** | 把**外部链接改为内部链接** | 该变量**只对本文件可见**；其他文件即使 `extern` 也找不到（同名不会冲突）。作用是"隐藏实现细节、避免命名污染" |
| **函数** | 同上，改为**内部链接** | 该函数**只能在定义它的文件内调用**；头文件里声明的跨模块函数不能加 static（否则无法链接） |
| **局部变量** | 改变**存储期**（作用域不变！） | 从自动存储期改为**静态存储期**：存放在静态数据区（`.data`/`.bss`）而非栈，**函数返回后值保留**，下次进入函数还是上次的值；**初始化只做一次**；未显式初始化则**自动为 0**；作用域仍是块内（外面看不见） |

**static 局部变量 vs 普通局部变量**：

| 维度 | 普通局部变量 | static 局部变量 |
|------|--------------|-----------------|
| 存储位置 | **栈** | **静态数据区**（.data / .bss） |
| 生存期 | 函数返回即销毁 | **整个程序运行期** |
| 初值 | 未初始化时是**垃圾值** | 未初始化时**自动置 0** |
| 初始化次数 | 每次进入函数都重新初始化 | **只在程序启动时初始化一次** |
| 作用域 | 块内 | 块内（**不扩大**） |
| 线程安全 | 各自独立 | **多线程共享 → 不安全**（要加锁或用线程局部存储） |

**典型用途**：① 函数内的"计数器/缓存"（下次调用还记得上次的值）；② 单例的延迟初始化；③ 只想在本文件使用的辅助函数（→ static 函数）。

**C++ 中的额外含义（常被追问）**：
- **静态成员变量**：属于**类**而不是对象，所有对象共享一份，必须在类外**定义并初始化**；
- **静态成员函数**：没有 `this` 指针，不能访问非静态成员，可用 `类名::函数名()` 直接调用；
- 类的 static 成员**不占对象空间**（除了可能的 padding）。

> [!warning]+ 一个小坑
> 函数内 `static` 变量的初始化"只做一次"这件事，若初始化表达式有副作用（如 `static int x = ++y;`），只会在**第一次**进入时执行——多线程环境下的初始化竞争（C++11 起局部 static 初始化是线程安全的，C 不保证）。

### 1.9 面向对象的三大特性 ⭐⭐⭐

**三大特性：封装、继承、多态**（有些教材会再加"抽象"，成为四大）。

| 特性 | 定义 | 目的 | 在 C 中如何模拟 |
|------|------|------|-----------------|
| **封装** | 把**数据**与**操作数据的函数**捆绑在一起，对外只暴露接口、隐藏实现细节（访问控制 `private`/`protected`/`public`） | 降低耦合、防止外部乱改内部状态（信息隐藏） | 结构体保存数据 + 一组函数操作它；用 `static` 函数隐藏内部实现；用**不透明指针（opaque pointer）**在头文件中只暴露不完整类型 |
| **继承** | 子类**复用**父类的属性与方法，并可扩展/覆盖，描述 **is-a** 关系 | 代码复用、层次化建模、便于扩展 | 把"基类结构体"作为**第一个成员**内嵌进"子类结构体"，利用"结构体首地址相同"实现向上转型 |
| **多态** | **同一接口**在不同对象上有**不同行为**——调用同一函数名，实际执行哪个实现由对象的**动态类型**决定 | 解耦调用者与实现，便于替换与扩展（开闭原则） | 在结构体里放**函数指针表**（自建虚表），初始化为不同函数 |

**多态的分类**（讲细一点更稳）：
- **编译期多态（静态绑定）**：函数**重载**（同名不同参数）、**模板/泛型**、运算符重载——编译时就确定调用哪个；
- **运行期多态（动态绑定）**：**虚函数**（virtual）——运行时根据对象的实际类型查找并调用，C++ 通常用"**虚函数表 vtable + 虚指针 vptr**"实现。

**虚函数表机制（追问必答）**：含虚函数的类在编译期生成一张**虚函数表**（每个类一张），对象内存布局的**开头**（常见实现）存放一个指向该表的**虚指针 vptr**；通过基类指针调用虚函数时，运行期沿 `vptr → vtable → 对应槽位` 取出函数地址再调用（**动态绑定**）。构造/析构期间 vptr 的切换是"构造函数中调用虚函数不会多态"的原因。

**C 语言模拟多态的例子（可现场写）**：

```c
/* C 语言用函数指针模拟多态（C89 风格） */
#include <stdio.h>

struct Shape {                    /* "基类"：数据 + 虚表指针 */
    const struct ShapeOps *ops;   /* 相当于 vptr */
};

struct ShapeOps {                 /* "虚表" */
    double (*area)(const struct Shape *self);
    void   (*say)(const struct Shape *self);
};

struct Circle { struct Shape base; double r; };      /* "派生类"：基类作为第一个成员 */
struct Rect   { struct Shape base; double w, h; };

static double circle_area(const struct Shape *s)
{
    const struct Circle *c = (const struct Circle *)s;
    return 3.14159265358979 * c->r * c->r;
}

static double rect_area(const struct Shape *s)
{
    const struct Rect *r = (const struct Rect *)s;
    return r->w * r->h;
}

/* 统一接口：对任何"Shape*"调用，行为由 ops 决定 → 多态 */
static void print_area(const struct Shape *s) { printf("%f\n", s->ops->area(s)); }
```

**三大特性之外常说的一点**：**抽象**——把一类事物的共性提取出来形成接口/抽象类，是封装、继承、多态共同服务的目标。

## 2. 线性结构

> [!note]+ 章节导引
> **本章知识点之间的关系**：线性结构是最简单的数据组织方式——元素排成一排。知识点递进：**数组**（连续存储，查快改慢）→ **链表**（离散存储，改快查慢）→ **栈**（只能一端操作，LIFO）→ **队列**（两端操作，FIFO）。后两个是"故意限制操作"的线性表——限制换来特定场景的高效。**堆**放在这里做对比，是因为面试常把"堆、栈、队列"三者连着问（虽然堆其实是非线性的树形结构，见 4.3）。**哈希表**也放线性部分，因为它本质是用数组+哈希函数实现 O(1) 查找。
>
> **与上一章的关系**：无（这是起点）。
>
> **与学科的关系**：线性结构是所有数据结构的基础——栈用于函数调用和 DFS，队列用于 BFS 和调度，哈希表是查找的利器。

### 2.1 数组与链表 ⭐⭐⭐

| 维度 | 数组 | 链表 |
|------|------|------|
| 存储 | 连续内存，需预知大小、可能浪费或不够 | 离散分配，按需申请 |
| 随机访问 | **O(1)**（首地址 + 下标 × 元素大小） | O(n)（需从头遍历） |
| 插入/删除 | O(n)（需搬移后续元素） | **O(1)**（修改指针，已知前驱时） |
| 空间开销 | 无额外开销（可能预留浪费） | 每结点多一个指针域 |
| 缓存友好性 | **好**（连续存储→预取有效） | 差（跳跃访问，缓存命中率低） |
| 能否扩容 | 静态数组不能，动态数组需整体拷贝 | 天然可动态增长 |

**为什么数组随机访问是 O(1)**：数组元素地址 = 首地址 + i × sizeof(T)，一次乘加即可算出，与 i 无关；链表要先走 i 个指针，与 i 线性相关。

**为什么数组缓存更友好**：CPU 一次载入一个 cache line（64B），连续存储的邻居元素顺带被装入缓存且能被硬件预取命中；链表结点地址散乱，每次访问都可能 cache miss。

> [!tip]+ 面试一句话
> 数组查快改慢，链表改快查慢。现代 CPU 缓存让数组的实际性能优势比复杂度看起来的更大——所以"链表插入是 O(1)"在工程上常常并不划算。

**怎么选**：查询/随机访问为主、元素个数可估 → 数组（或动态数组）；频繁在中间插入删除、个数变化剧烈 → 链表。工程上还有折中方案：**跳表**（链表 + 多层索引，Redis zset 用）、**块状链表**、**动态数组**（`std::vector`，摊还 O(1) 尾插）。

### 2.2 栈与队列 ⭐⭐⭐

**栈（Stack）**：**LIFO**（后进先出），只能在栈顶插入/删除。
**队列（Queue）**：**FIFO**（先进先出），队尾入队、队头出队。

| 维度 | 栈 | 队列 |
|------|-----|------|
| 出入规则 | 同一端（栈顶）进出 | 一端进（队尾）、另一端出（队头） |
| 顺序 | 后进先出 LIFO | 先进先出 FIFO |
| 基本操作 | push / pop / top | enqueue / dequeue / front |
| 复杂度 | 均为 O(1) | 均为 O(1)（数组/链表实现） |
| 典型应用 | 函数调用栈、表达式求值、括号匹配、DFS、撤销栈 | BFS、任务调度、消息缓冲、生产者-消费者 |

**循环队列**：顺序存储的队列出队后队头前会出现无法使用的空位（"假溢出"），把数组看成首尾相接的环即可复用空间。判满常用"牺牲一个单元"：

```c
/* 队列容量 capacity，实际最多存 capacity-1 个元素 */
#define QUEUE_SIZE 100
int q[QUEUE_SIZE];
int front = 0, rear = 0;          /* rear 指向下一个空位 */

int is_empty(void) { return front == rear; }
int is_full(void)  { return (rear + 1) % QUEUE_SIZE == front; }
void enqueue(int x) { q[rear] = x; rear = (rear + 1) % QUEUE_SIZE; }
int  dequeue(void)  { int x = q[front]; front = (front + 1) % QUEUE_SIZE; return x; }
```

也可以用"计数器 `size`"或"标志位 `last_op`"区分空与满，这样不浪费一个单元。

**表达式的三种形式**（面试常追问）：
- **中缀**：`a + b * c`，运算符在中间，需要优先级和括号；
- **后缀（逆波兰）**：`a b c * +`，无括号、无优先级，用**一个栈**从左到右扫描即可求值（遇操作数入栈，遇运算符弹出两个运算数算完入栈）；
- **前缀（波兰）**：`+ a * b c`，从右往左扫描同理。
- 中缀转后缀：用**运算符栈**，遇左括号入栈、遇右括号弹到左括号、遇运算符弹出优先级 ≥ 它的栈顶再入栈。

> [!tip]+ 面试要点
> 栈在操作系统中的核心作用——每个线程有自己的栈，函数调用时压栈（参数、返回地址、局部变量），返回时弹栈。**递归的本质就是利用函数调用栈**：所以"用栈模拟递归"永远可行（DFS 的非递归写法即此）。

### 2.3 堆、栈、队列的定义与区别 ⭐⭐⭐

**先给结论**：栈和队列是**线性表**（受操作限制），堆是**完全二叉树**（非线性），三者共同的抽象是"**限定从哪里取元素**"——栈取最新的、队列取最旧的、堆取最值。

| 维度 | 栈 | 队列 | 堆 |
|------|-----|------|-----|
| 逻辑结构 | 受限线性表 | 受限线性表 | **完全二叉树**（堆序树） |
| 存取规则 | LIFO 后进先出 | FIFO 先进先出 | 每次取**最值**（大根堆取最大，小根堆取最小） |
| 底层实现 | 数组 / 链表 | 数组（循环）/ 链表 | **数组**（不存指针，靠下标关系） |
| 插入 | O(1) 压栈顶 | O(1) 入队尾 | O(log n) 上浮 |
| 删除 | O(1) 弹栈顶 | O(1) 出队头 | O(log n) 下沉（取顶 O(1)） |
| 顺序性 | 完全有序（按时间） | 完全有序（按时间） | **只有堆顶是最值**，兄弟之间无序 |
| 典型用途 | 递归/DFS/括号匹配/撤销 | BFS/调度/缓冲区 | 优先队列、Top-K、堆排序、Huffman、Dijkstra |

> [!warning]+ 最容易混的一点：数据结构里的"堆" ≠ 内存里的"堆"
> - **数据结构的堆（heap / priority queue）**：二叉树形态的数据结构，解决"动态反复取最值"的问题。
> - **操作系统内存的堆（heap 区）**：进程地址空间中由 `malloc/free` 管理的一块区域，与"栈区"相对。
>
> 两者只是英文都叫 heap，**没有任何关系**。C 语言里 `malloc` 返回的指针指向内存堆区，跟堆这种数据结构无关——说清这一点本身就是加分项。

**内存分区里的"栈"和"堆"（常与内存管理一起问）**：

| 维度 | 栈区 stack | 堆区 heap |
|------|-----------|-----------|
| 管理者 | **编译器自动**分配/释放 | **程序员** `malloc`/`free`（或 `new`/`delete`） |
| 存放内容 | 局部变量、函数参数、返回地址、寄存器现场 | 动态申请的对象/数组 |
| 生长方向 | 通常向**低地址**生长 | 通常向**高地址**生长 |
| 空间大小 | 小（典型 1~8 MB），超了 → **栈溢出** | 大（受虚拟内存限制） |
| 分配速度 | **快**（移动栈指针） | 慢（要查找合适的空闲块，可能系统调用） |
| 典型问题 | 递归太深 / 大局部数组 → 栈溢出 | 内存泄漏、碎片、重复释放 |

## 3. 哈希表

> [!note]+ 章节导引
> **本章知识点之间的关系**：哈希表的目标是"用计算代替比较"实现 O(1) 查找。逻辑链：**哈希函数**（把 key 映射到数组下标）→ **冲突**（不同 key 映射到同一位置）→ **冲突解决**（链地址法 vs 开放寻址法）→ **装载因子**（衡量多满，影响性能）→ **扩容**（够满就翻倍重哈希）。整个哈希表的设计就是"哈希函数 + 冲突解决 + 扩容策略"三件事。
>
> **与上一章的关系**：哈希表底层用数组存储，是数组查找能力的升级版。
>
> **与学科的关系**：哈希表是"查找"场景的终极方案，也是数据库、缓存、编程语言运行时的核心数据结构。

### 3.1 哈希的定义与哈希函数 ⭐⭐⭐

**哈希（hash，又称散列）**：通过一个**哈希函数** $h$ 把关键字 $key$ 映射成存储地址 $h(key)$，使得查找时"算一下就知道在哪"，而不用逐个比较。

**哈希表（散列表）= 数组 + 哈希函数 + 冲突解决策略**。

**为什么平均是 O(1)**：把 key 到位置的寻址从"与元素个数 n 相关"变成"与 n 无关"——只要哈希函数把 key 均匀打散，平均查找长度就与 n 无关（期望 O(1)）。**对比**：有序数组二分查找 $O(\log n)$，BST $O(\log n)$，哈希表期望 $O(1)$。

**常见哈希函数构造方法**：

| 方法 | 做法 | 特点 |
|------|------|------|
| **除留余数法** | $h(k) = k \bmod m$ | 最常用；$m$ 取**质数**且远离 $2^n$ 时分布更均匀 |
| 直接定址法 | $h(k) = a\cdot k + b$ | 无冲突，但要求 key 连续、空间浪费大 |
| 数字分析法 | 取 key 中分布均匀的若干位 | 适合事先知道 key 分布（如学号） |
| 平方取中法 | 取 $k^2$ 的中间几位 | 中间位受全体数字影响，分布较好 |
| 折叠法 | 把 key 分段相加 | 适合位数很多的长 key |
| 随机数法 | $h(k) = \text{random}(k)$ | key 长度不等时用 |

**设计原则**：① 计算简单快速；② 地址分布均匀（减少冲突）；③ 值域落在表长范围内。

**为什么冲突不可避免**：由**鸽巢原理**，只要 key 的可能取值比表长大（一定如此，key 空间通常远大于表长），就必然存在两个 key 映射到同一地址，**再好的哈希函数也只能减少冲突、不能消除**。

### 3.2 哈希冲突及解决方法 ⭐⭐⭐

**冲突（碰撞，collision）**：$key_1 \ne key_2$ 但 $h(key_1) = h(key_2)$，两者争同一个位置。

| 方法 | 思想 | 优点 | 缺点 |
|------|------|------|------|
| **链地址法**（拉链法） | 同一位置的 key 用链表串起来（数组存头指针） | 简单；不怕冲突多；删除方便；装载因子可 > 1 | 指针额外开销；链过长时退化为 O(n)（可接红黑树，如 Java HashMap） |
| **开放寻址法** | 冲突时按探测序列"找下一个空位"，所有元素都存在数组里 | 无指针开销、缓存友好、空间利用率高 | 删除麻烦（要标记"墓碑"）；聚集严重；装载因子必须 < 1 |
| **再哈希法** | 用第二个哈希函数再算一次地址 | 不易聚集 | 计算量增加 |
| **建立公共溢出区** | 冲突的元素统一放到溢出区 | 实现简单 | 溢出区查找退化为顺序查找 |

**开放寻址的三种探测策略**：

| 策略 | 探测序列 | 特点 |
|------|----------|------|
| **线性探测** | $h(k)+1, h(k)+2, \dots$ | 简单，但产生**一次聚集**（连续被占形成长块） |
| **二次探测** | $h(k)\pm 1^2, \pm 2^2, \dots$ | 减轻一次聚集，产生**二次聚集**（同哈希值才同步探测） |
| **双重散列** | $h_1(k) + i\cdot h_2(k)$ | 分散最好，接近理想随机探测 |

> [!tip]+ 面试一句话
> 工程里最常用**链地址法**（Java `HashMap`、Python `dict` 思路、Go `map` 的 bucket）；开放寻址在"追求缓存友好、元素少"时用（如 Python dict 的探测实现、线性探测的 Swiss Table）。

### 3.3 装载因子与扩容 ⭐⭐

$$\alpha = \frac{\text{已存元素数}\,n}{\text{哈希表长度}\,m}$$

**作用**：$\alpha$ 越大 → 表越满 → 冲突越多 → 平均查找长度越长。

- 链地址法：平均查找长度约 $1 + \alpha/2$（成功），与 $\alpha$ 同阶；$\alpha$ 可大于 1。
- 开放寻址法：$\alpha$ **必须小于 1**（元素总数不能超过表长），且 $\alpha$ 接近 1 时探测次数急剧上升，通常 $\alpha > 0.7$ 就该扩容。

**扩容（rehash）**：新建一个约 2 倍大小的表，把旧元素**逐个重新计算哈希**插入新表。单次代价 O(n)，但触发间隔翻倍，**摊还代价 O(1)**。扩容因子（如 Java HashMap 的 0.75）是"空间 vs 时间"的折中。

> [!tip]+ 关键
> 哈希表平均 O(1)，最坏 O(n)。要"平均 O(1)"成立，需要：**好的哈希函数**（分散均匀）+ **合适的装载因子**（及时扩容）。最坏情况出现在所有 key 都冲突到同一位置（如刻意构造的 DoS 攻击），工程上可用**随机化哈希种子**抵御。

## 4. 树形结构

> [!note]+ 章节导引
> **本章知识点之间的关系**：树形结构是"二叉搜索树不断升级"的故事。逻辑链：**二叉树**（基础结构，三种遍历）→ **BST**（左<根<右，查找O(log n)）→ **BST 的问题**（有序插入退化为链表）→ **AVL 树**（严格平衡，查找最快但旋转多）→ **红黑树**（近似平衡，旋转少，工程首选）→ **堆**（放弃查找，专注优先级）。**B/B+ 树与哈夫曼树**（另一条支线：最优前缀编码）同样是树的重要分支，但已**前置到第 1 章的 1.1 / 1.2**，本章不再重复，只保留上面这条主线。
>
> 每种树的存在都是因为前一种"不够用"：BST会退化→AVL严格但慢→红黑树折中→B+树适应磁盘；哈夫曼树则是"带权路径长度最小"这一优化目标的答案。
>
> **与上一章的关系**：哈希表只能做"精确查找"，树可以做"范围查找"和"有序遍历"——这是树结构不可替代的价值。
>
> **与学科的关系**：树是数据结构中最重要的非线性结构，也是数据库索引、文件系统、编译器语法树、压缩编码的基础。

### 4.1 二叉树与三种遍历 ⭐⭐⭐

**遍历的定义**（按"访问根结点"的时机命名）：

| 遍历 | 顺序 | 记忆 | 结果特点 |
|------|------|------|----------|
| **前序（先序）** | 根 → 左子树 → 右子树 | 根左右 | 第一个必是根；适合复制/序列化树 |
| **中序** | 左子树 → 根 → 右子树 | 左根右 | **BST 的中序序列是升序**；适合排序输出 |
| **后序** | 左子树 → 右子树 → 根 | 左右根 | 最后一个必是根；适合释放内存（先子后父） |
| **层序** | 逐层从左到右 | 用**队列** | BFS 思想 |

**递归写法**（以中序为例，三种只差 printf 的位置）：

```c
typedef struct Node {
    int val;
    struct Node *left, *right;
} Node;

void inorder(Node *t)
{
    if (t == NULL) return;
    inorder(t->left);
    printf("%d ", t->val);   /* 前序放最前，后序放最后 */
    inorder(t->right);
}
```

**非递归**：前/中序用**显式栈**模拟；后序可"根右左入栈再逆序"或"记录上一个访问结点"；层序用**队列**。

**由遍历序列还原树**：
- 已知**前序 + 中序** → 唯一确定：前序第一个是根，在中序中定位根即可切出左右子树，递归即可；
- 已知**后序 + 中序** → 同理（后序最后一个是根）；
- 已知**前序 + 后序** → **不能**唯一确定（无法区分只有单孩子的子树，结果可能有多种）；
- 已知**层序 + 中序** → 也可以唯一确定。

> [!tip]+ 面试要点
> 已知前序+中序 → 唯一确定二叉树；已知后序+中序同理；但前序+后序**不能**唯一确定（缺少中序无法区分左右子树）。

### 4.2 BST 的问题 → 平衡树的诞生 ⭐⭐⭐

**二叉搜索树（BST / 二叉排序树）**：任一结点满足 **左子树所有值 < 根 < 右子树所有值**。
- 查找/插入/删除复杂度 = **树高**：平衡时 $O(\log n)$，退化成链时 $O(n)$。
- **退化场景**：按有序序列 1,2,3,…,n 依次插入 → 树变成单链，查找退化为顺序查找。这正是不平衡树的痛点。

| 树 | 平衡策略 | 查找/插入/删除 | 特点 |
|----|----------|----------------|------|
| **AVL 树** | 严格平衡（任一结点左右子树高度差 ≤ 1） | **O(log n)** | 查找最快，但插入删除要频繁旋转（适合查找密集） |
| **红黑树** | 近似平衡（最长路径 ≤ 2×最短路径） | **O(log n)** | 旋转次数少（适合插删密集），STL map/set、Java TreeMap 底层 |
| **B 树** | 多路平衡（每节点多个 key） | O(log n) | 适合磁盘，降低树高、减少 I/O |
| **B+ 树** | B 树 + 叶子链表 | O(log n) | **数据库索引**标准结构 |

**红黑树的性质**（常被追问）：① 结点非红即黑；② 根黑；③ 叶子（NULL）黑；④ 红结点的子结点必为黑（不能红红相连）；⑤ 从任一结点到其所有叶子的路径上黑结点数相同。由性质 4、5 可推出**最长路径 ≤ 2×最短路径**，故高度 $O(\log n)$。

> [!tip]+ AVL vs 红黑树
> AVL 更严格平衡→查找更快；红黑树旋转更少→插删更快。实际工程（STL、Java TreeMap、Linux CFS 调度器）多用红黑树——因为真实负载是插删查混合。

### 4.3 堆（优先队列）⭐⭐⭐

**堆** = 满足堆序性质的**完全二叉树**：大根堆中每个结点 ≥ 其子结点，小根堆反之。

**为什么用数组存**：完全二叉树可以**按层序连续存储**（无空洞），父子下标关系由算术给出，不用存指针，空间最省、缓存友好：

- 下标从 1 开始：`parent = i/2`，`left = 2i`，`right = 2i+1`；
- 下标从 0 开始：`parent = (i-1)/2`，`left = 2i+1`，`right = 2i+2`。

**注意堆不是 BST**：堆只保证"父 ≥ 子"的**偏序**，左右孩子之间没有大小关系，所以堆**不能**做有序查找、不能中序输出有序序列。

**核心操作**：

| 操作 | 做法 | 复杂度 |
|------|------|--------|
| 取堆顶 | 直接取 `a[0]`（最值） | **O(1)** |
| 插入 | 放到数组末尾（保持完全二叉树），然后**向上调整（上浮 sift-up）** | O(log n) |
| 删除堆顶 | 把末尾元素补到堆顶，**向下调整（下沉 sift-down）** | O(log n) |
| 建堆 | 从最后一个非叶结点（`n/2-1`）开始逐个下沉 | **O(n)**（不是 O(n log n)） |

**堆排序**：① 建大根堆 O(n)；② 依次把堆顶（最大值）与末尾交换，堆长度减 1，对新堆顶下沉 O(log n)，共 n-1 次 → 总计 $O(n\log n)$，空间 O(1)（原地），**不稳定**。

**建堆为什么是 O(n)**：高度为 h 的结点数约 $\frac{n}{2^{h+1}}$，代价 $\sum_h \frac{n}{2^{h+1}}h = O(n)$——越靠下的层结点越多但下沉越浅，级数收敛。

> [!tip]+ 用途
> 大根堆 → 升序堆排序、求第 K 小；小根堆 → Top-K 大的元素（维护大小 K 的小根堆，$O(n\log K)$）、优先队列、Dijkstra、Huffman 建树。

## 5. 图

> [!note]+ 章节导引
> **本章知识点之间的关系**：图是最一般的非线性结构——树是"无圈连通图"，线性表是"退化的树"。图的四个核心问题：**怎么存**（邻接矩阵/邻接表/边集数组）、**怎么遍历**（DFS/BFS，所有图算法的基础）、**怎么连通最省**（最小生成树）、**怎么走最短**（最短路径）。存法决定空间与查边效率，遍历决定算法骨架。**本章只展开"怎么存"与"怎么遍历"两块**——最小生成树与最短路径（含 Bellman-Ford）已**前置到第 1 章的 1.3 / 1.4**。
>
> **与上一章的关系**：树是图的特例（无圈连通图）。图放松了树"无圈"的限制，能表达更复杂的关系。
>
> **与学科的关系**：图是社交网络、路由协议、编译器依赖分析等场景的核心结构。图算法（最短路、MST、拓扑排序）在算法部分详细展开。

### 5.1 图的存储方法 ⭐⭐⭐

| 方法 | 结构 | 空间 | 查边 | 遍历 | 适用 |
|------|------|------|------|------|------|
| **邻接矩阵** | 二维数组 `a[i][j]` 存边权（无边存 0 或 ∞） | $O(V^2)$ | **O(1)** | O(V²) | **稠密图**、需频繁判边、Floyd |
| **邻接表** | 每个顶点一个链表，存所有邻接点（带权加权域） | $O(V+E)$ | O(度数) | O(V+E) | **稀疏图**、绝大多数场景 |
| **逆邻接表** | 存"指向自己"的顶点 | $O(V+E)$ | 入度 O(度数) | — | 有向图需快速求**入度** |
| **边集数组** | 只存所有边 `(u, v, w)` | $O(E)$ | O(E) | 不方便 | 以边为主体的算法（**Kruskal**） |
| **十字链表** | 每个弧结点同时挂在"出边链"和"入边链"上 | $O(V+E)$ | 出/入度都方便 | — | 有向图（同时要出度和入度） |
| **邻接多重表** | 无向图每条边只对应**一个**结点，被两端共享 | $O(V+E)$ | 方便 | — | 无向图需频繁删除边 |
| **链式前向星** | 数组模拟邻接表：`head[]`/`nxt[]`/`to[]`/`w[]` | $O(V+E)$ | — | O(V+E) | 竞赛/工程实现（无指针、缓存友好） |

**邻接矩阵的关键性质**（选择题常考）：
- 无向图矩阵**对称**，可只存上三角；
- 有向图中，**行和 = 出度，列和 = 入度**；
- $A^k$ 的第 $(i,j)$ 元素 = 从 i 到 j **长度为 k 的通路条数**；
- 带权图：无边用 ∞（求最短路时要注意 ∞ 相加溢出）。

**邻接表的优缺点**：优点是空间省、找邻接点快（O(V+E) 遍历）；缺点是**判断两点间是否有边较慢**（要遍历该点的链表），且**有向图求入度不便**（需逆邻接表或额外记录入度数组）。

> [!tip]+ 面试一句话
> 实际中大多数图是稀疏的（如社交网络：人均好友几百，远小于用户数），用邻接表更合适；只有稠密图或需要 O(1) 判边（如 Floyd）才用邻接矩阵。

### 5.2 深度优先与广度优先遍历 ⭐⭐⭐

**深度优先遍历（DFS, Depth-First Search）**：沿着一条路**尽可能深地走**，走到不能再走（无未访问邻接点）就**回溯**到上一个还有未访问分支的顶点，继续深入。**对每个顶点只访问一次**。

**广度优先遍历（BFS, Breadth-First Search）**：从起点出发**按层扩散**，先访问所有距离为 1 的顶点，再访问距离为 2 的……直到所有可达顶点被访问。**系统地展开并检查所有顶点**。

| 维度 | DFS | BFS |
|------|-----|-----|
| 数据结构 | **栈**（递归调用栈 / 显式栈） | **队列** |
| 访问顺序 | 一根筋到底，再回溯 | 一层一层向外扩 |
| 空间 | O(树高/最长路径)，路径深时可能**栈溢出** | O(最宽一层的顶点数)，可能很大 |
| 复杂度 | O(V+E)（邻接表）/ O(V²)（矩阵） | 同左 |
| 最短路性质 | **不保证**最短路 | 无权图（边权均为 1）**得到最短路** |
| 典型应用 | 连通分量、环检测、拓扑排序、割点/桥、回溯求解（全排列、N 皇后、迷宫所有解） | 无权最短路、层次遍历、求最短步数、二分图判定、社交网络 N 度好友、洪泛/爬虫 |

**为什么 BFS 能求无权图最短路、DFS 不能**：BFS 按"距离起点 1, 2, 3…"的层序扩展，第一次到达某顶点时走的必然是最少边数的路径；DFS 可能沿一条长路先到达目标，之后才从更短的路径到达，且它不回溯重算，因此不保证最短。

**DFS 的非递归写法**就是"显式用栈模拟递归"；BFS 的队列保证"先发现的先扩展"，这正是层序的来源。

```c
/* 邻接表上的 BFS 骨架（C89 风格：变量声明在块首） */
void bfs(int s, int n, int (*adj)[MAXD], int *deg)
{
    int q[MAXV], head = 0, tail = 0;
    int vis[MAXV] = {0};
    int i, u, v;
    vis[s] = 1; q[tail++] = s;
    while (head < tail) {
        u = q[head++];
        printf("%d ", u);
        for (i = 0; i < deg[u]; i++) {
            v = adj[u][i];
            if (!vis[v]) { vis[v] = 1; q[tail++] = v; }
        }
    }
}
```

> [!tip]+ 面试要点
> 两者是**所有图算法的基础**：DFS 的"深度优先搜索树"能求割点、桥、强连通分量（Tarjan）；BFS 的"层"能求无权最短路、二分图染色。**连通分量**用哪个都行，但实现上 DFS 更简洁。

## 6. 排序算法

> [!note]+ 章节导引
> **本章知识点之间的关系**：排序算法是数据结构的应用——不同数据结构适合不同排序。逻辑链：简单排序（冒泡/选择/插入，O(n²)）→ 分治排序（快排/归并，O(n log n)）→ 选择类排序（堆排，O(n log n) 原地）→ 非比较排序（基数/计数，线性但受限）。快排和归并是"分治思想"在排序上的体现，堆排是"堆"的应用。**稳定性**是横向贯穿所有排序的另一条线。

### 6.1 常见排序算法对比 ⭐⭐⭐

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|------|------|------|------|------|
| 冒泡 | O(n²) | O(n²) | O(1) | ✅ | 简单；可加 flag 提前退出，最好 O(n) |
| 选择 | O(n²) | O(n²) | O(1) | ❌ | 交换次数最少（n-1 次） |
| 插入 | O(n²) | O(n²) | O(1) | ✅ | **近似有序时接近 O(n)**；小数组首选 |
| 希尔 | O(n^1.3) | O(n²) | O(1) | ❌ | 插入排序的增量改进 |
| 快排 | **O(n log n)** | O(n²) | O(log n) | ❌ | **实际最快**；最坏出现在已有序 + 取首元素为 pivot |
| 归并 | O(n log n) | O(n log n) | O(n) | ✅ | **稳定排序首选**；外排基础 |
| 堆排 | O(n log n) | O(n log n) | O(1) | ❌ | 原地、无最坏退化；缓存不友好 |
| 计数 | O(n+k) | O(n+k) | O(n+k) | ✅ | 非比较，要求 key 是小范围整数 |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ | 非比较，按位稳定排序 d 轮 |

**快速排序**：选一个基准 pivot → **分区（partition）**使左边都 ≤ pivot、右边都 ≥ pivot → 对左右子区间递归。
- 平均 $O(n\log n)$：递归式 $T(n)=2T(n/2)+O(n)$；
- **最坏 $O(n^2)$**：每次划分极不均匀（已有序且取首元素为 pivot，分区退化为 1 : n-1）；
- **规避**：随机化选 pivot、三数取中、小区间改用插入排序、递归太深转堆排（即 **Introsort**，`std::sort` 的实现）；
- **实际最快的原因**：① 原地（无需辅助数组）；② 内层循环简单、常数小；③ **缓存友好**（顺序扫描数组）；④ 分区过程中数据局部性好。

**怎么选**：
- 要求**稳定** → 归并（或冒泡/插入）；
- 要求**原地 + 最坏也是 O(n log n)** → 堆排；
- 通用最快 → 快排（配合随机化）；
- key 是小范围整数 → 计数/基数排序，可到线性；
- **数据量极大、内存装不下** → 外部排序（分块 + 多路归并）。

> [!tip]+ 面试必答
> - 稳定排序：冒泡、插入、归并、计数、基数
> - 不稳定排序：选择、快排、堆排、希尔
> - 工程实践：`std::sort` 是 Introsort（快排 + 插入 + 堆排混合），`std::stable_sort` 用归并

### 6.2 排序的稳定性 ⭐⭐⭐

**稳定排序的定义**：如果待排序序列中**两个元素的关键字相等**（$k_i = k_j$），排序**前后它们的相对次序保持不变**，则称这个排序算法是**稳定的**；否则是不稳定的。

形式化：若排序前 $i < j$ 且 $k_i = k_j$，排序后 $i$ 依然排在 $j$ 前面。

**为什么需要稳定性**（面试必答的"有什么用"）：
1. **多关键字排序**：先按次要关键字排一遍，再按主要关键字排一遍。第二轮必须用**稳定**算法，才能保住第一轮的次序。例：先按"成绩"排，再按"班级"排，稳定算法能实现"按班级分组、组内按成绩降序"。
2. **数据库 ORDER BY**：SQL 排序常要求"相等键保持原有（如主键/插入）顺序"，不稳定算法结果不可复现。
3. **用户可感知的顺序**：如按价格排序商品，同价商品不应乱跳。

**哪些稳定**（记忆口诀：**冒泡、插入、归并、计数、基数**稳定；**选择、快排、堆排、希尔**不稳定）：

| 稳定 ✅ | 为什么不稳定 | 典型反例 |
|---------|--------------|----------|
| 冒泡 | —— | 只在逆序时才交换，相等不交换 |
| 插入 | —— | 从后往前找位置，停止条件是严格大于，相等时插在其后 |
| **归并** | —— | 合并时写 `if (a[i] <= a[j])` 取左半，相等时左半先出 |
| 计数 | —— | 按值从前往后回填 |
| 基数 | —— | 每轮用稳定排序（计数排序）从低位到高位 |
| 选择 | 不稳定 | 第一轮把最小值与位置 0 交换，把位置 0 的元素甩到末尾，跨越了其它相等元素 |
| **快排** | 不稳定 | 分区时的交换是**远距离**的，会跨越相等元素 |
| 堆排 | 不稳定 | 堆顶与末尾元素交换，末尾元素被拽到根再一路下沉，跨度极大 |
| 希尔 | 不稳定 | 按增量跳跃分组，相等元素可能跨组移位 |

**选择排序的反例**：`[2a, 2b, 1]` → 第一轮选最小 1 与 2a 交换得 `[1, 2b, 2a]`，2a 与 2b 的相对次序被颠倒。

**快速排序的反例**：以首元素为 pivot 的 Hoare/Lomuto 分区中，`[3a, 3b, 1]` 之类的序列会发生远距离交换，使 3a 与 3b 颠倒。

> [!tip]+ 一句话总结
> 稳定的本质是"**排序时只做相邻/同侧比较的、不跨越相等元素的移动**"。冒泡和插入天然只有相邻交换；归并靠"相等取左"；快排和堆排都有**远距离交换**，所以不稳定。

### 6.3 二路归并排序 ⭐⭐⭐

**二路归并（merge sort，2-way merge sort）**：把序列**两两对半**地分（二路），递归排好左右两半，再把两个**有序**子序列**归并**成一个有序序列。是**分治思想**最标准的体现：**分解 → 递归求解 → 合并**。

**归并（merge）过程**：两路指针分别指向两个有序段的头部，每次把较小的那个取出来放进辅助数组（相等时优先取左边那一路，保证稳定），某一路取完后把另一路剩余整体拷贝过去。

**归并排序的递归定义**：
- 递归基：区间长度 ≤ 1 时天然有序，直接返回；
- 否则取中点 `mid = lo + (hi - lo) / 2`，递归排 `[lo, mid]` 与 `[mid+1, hi]`，再 merge。

```c
/* 二路归并排序（C89 风格：声明在块首，块注释，无 VLA 依赖） */
#include <stdlib.h>

#define MAXN 100005
static int tmp[MAXN];

static void merge(int a[], int lo, int mid, int hi)
{
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];   /* <= 保证稳定 */
        else              tmp[k++] = a[j++];
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    for (k = lo; k <= hi; k++) a[k] = tmp[k];  /* 回写 */
}

void merge_sort(int a[], int lo, int hi)
{
    int mid;
    if (lo >= hi) return;                      /* 递归基 */
    mid = lo + (hi - lo) / 2;                  /* 防溢出写法 */
    merge_sort(a, lo, mid);
    merge_sort(a, mid + 1, hi);
    merge(a, lo, mid, hi);
}
```

**复杂度**：$T(n) = 2T(n/2) + O(n)$ → **$O(n\log n)$**（由主定理情形 2；也可用递归树理解：共 $\log n$ 层，每层合并总代价 $O(n)$）。
- **优点**：**任何输入都是 $O(n\log n)$**——没有快排的最坏退化；且是**稳定**排序；
- **缺点**：需要 $O(n)$ 辅助空间（快排 O(log n)、堆排 O(1)）；小数组时常数比快排大、缓存局部性稍差。

**为什么稳定**：合并时用 `a[i] <= a[j]` 而不是 `<`，两元素相等时优先取**左半**（即原序列中靠前的那一个），因此相等元素永远保持原有相对次序。

**多路归并（k-way merge）与外部排序**：
- 当数据量远超内存时，用**外部排序**：① 把大文件分成若干能装进内存的块，块内排序后写回磁盘，得到若干**有序归并段（run）**；② 再对这些归并段做**多路归并**（k 路同时合并），边读边写、顺序 I/O。
- 为什么用**多路**而非二路：归并的**趟数** $= \lceil \log_k m \rceil$（m 为归并段数），k 越大趟数越少 → **磁盘 I/O 次数越少**（外排的瓶颈是 I/O，不是 CPU）。
- 代价：k 路比较要 k 次选最小，可用**败者树（loser tree）**把每次选最小的比较次数降到 $O(\log k)$，或直接用**小根堆**维护 k 个当前元素。
- 这就是 3.5 之外"堆"的另一个大用途，也是海量数据排序（Top-K 之外）的标准解法。

> [!tip]+ 面试一句话
> 二路归并 = "对半分 + 两个有序段合并"，$O(n\log n)$、稳定、需 O(n) 辅助空间；数据装不下内存时升级成"分块排序 + k 路归并"的外部排序。

## 7. 算法思想专题

> [!note]+ 章节导引
> **本章知识点之间的关系**：面试问"思想"远多于问"代码"。分治是"把大问题拆成独立小问题"，DP 是"分治 + 记忆化（子问题重叠时）"，贪心是"每步取局部最优"，三者是"通用 → 特殊"的递进。**0-1 背包**是串起三者的最佳例题：它既不能用贪心（反例），又必须用 DP，而且它的复杂度 $O(nW)$ 里藏着"伪多项式"这个高频陷阱（**背包这一节已前置到 1.5**，本章只讲分治与 DP 的思想对比）。

### 7.1 分治与动态规划的异同 ⭐⭐⭐

**分治（Divide and Conquer）**：把原问题**分解**成若干**规模更小、结构相同**的子问题 → **递归求解** → 把子问题的解**合并**成原问题的解。三步：**分、治、合**。典型：归并排序、快排、二分查找、大整数乘法、Strassen 矩阵乘法。

**动态规划（DP, Dynamic Programming）**：把问题拆成子问题，**记录子问题的解**避免重复计算，自底向上（或自顶向下 + 记忆化）递推。两大要素：**最优子结构**（问题的最优解可由子问题最优解构造）+ **重叠子问题**（不同路径会反复求解同一子问题）。

**相同点**：
1. 都基于"**把大问题分解为子问题**、递归/递推求解"的思想；
2. 都要求问题具有**最优子结构**（原问题最优解包含子问题最优解）；
3. 都在图上形成"状态 + 转移"的结构，都可以用递归表达；
4. 都常用于求解最优化问题（最大/最小/最优）。

**不同点**：

| 维度 | 分治 | 动态规划 |
|------|------|----------|
| **子问题关系** | 相互**独立**，互不重叠 | **重叠**（同一子问题被多次用到） |
| **是否重复计算** | 会算多次（若重叠则退化为指数级） | 用**表/记忆化**保证每个子问题只算一次 |
| 求解方向 | 自顶向下分解，递归后合并 | 通常**自底向上**递推（也可自顶向下记忆化） |
| 额外要求 | 只需最优子结构 + 子问题独立 | 还需**重叠子问题** + **无后效性**（状态确定后与路径无关） |
| 解的构造 | 靠**合并**子问题的解 | 靠**状态转移方程**递推 |
| 典型问题 | 归并排序、二分查找、大整数乘法、Strassen | 0-1 背包、LCS、编辑距离、Floyd、最短路径 |

**两者的桥梁**：**DP = 分治 + 记忆化**。
- 子问题**不重叠**时，分治就够了，用 DP 只是徒增空间；
- 子问题**重叠**时，朴素分治会重复计算同一个子问题，复杂度可能从多项式退化为指数级。经典例子：斐波那契 `fib(n) = fib(n-1) + fib(n-2)`，朴素递归 $O(2^n)$（递归树里大量重复结点），加记忆化或改递推后降到 $O(n)$。

**为什么贪心能"更快"**：贪心不做全局规划，每步直接取局部最优——**当且仅当贪心选择性质成立**时才正确（可以理解为"DP 的状态转移只依赖一个最优分支，退化为一维选择"）。0-1 背包**不能**用贪心（按单位价值贪心会出错），但**分数背包可以**（因为可以任意分割，贪心选性价比最高的一定最优）。

> [!tip]+ 面试时怎么讲（老师追问细节也不慌）
> 先给**一句话结论**："同的都是'分而治之、最优子结构'，区别在**子问题是否重叠**——不重叠就是分治，重叠就要用 DP 存表避免重复计算，所以 DP = 分治 + 记忆化。"
> 再举**一个正例一个反例**：正例是斐波那契递归 $O(2^n)$ → DP $O(n)$；反例是 0-1 背包贪心失效、必须 DP。
> 最后点**范式谱系**：分治 → DP（子问题重叠）→ 贪心（还能再退化为局部选择），说清"为什么会一级级简化"。

### 8.1 for(a;b;c) 的三个表达式 ⭐⭐

`for (a; b; c) body` 的执行语义可以精确写成：

```c
a;                      /* 只执行一次 */
while (b) {             /* 每轮循环体前判断 */
    body;
    c;                  /* 每轮循环体之后执行 */
}
```

| 表达式 | 名称 | 含义 | 执行时机 |
|--------|------|------|----------|
| `a` | 初始化表达式 | 进循环体**之前**做的准备（如 `i = 0`） | **仅一次** |
| `b` | 条件表达式 | 判断是否继续循环，为真（非 0）继续 | 每轮**进入循环体前**求值一次 |
| `c` | 步进表达式 | 循环体结束**后**执行（如 `i++`） | 每轮**循环体结束后**执行一次 |

**执行顺序**：`a → b → body → c → b → body → c → …` 直到 `b` 为假。

**三个都可以省略**（但两个分号不能省）：

| 写法 | 等价于 | 说明 |
|------|--------|------|
| `for (;;)` | `while (1)` | `b` 为空视为**恒真** → 死循环，靠 `break` 退出 |
| `for (a; b; )` | `a; while (b) { body; }` | 缺 `c`，步进要写在循环体内 |
| `for ( ; b; c)` | `while (b) { body; c; }` | 缺 `a`，初始化写在前面 |
| `for (a; ; c)` | 死循环 + 每轮步进 | `b` 为空恒真 |

**`continue` 与 `break` 的关键差异**：
- `break`：立即跳出整个循环，**不执行** `c`；
- `continue`：跳过本次循环体内**剩余**语句，但**仍会执行 `c`**，然后回到 `b` 判断。

> [!warning]+ 严谨一点（容易说错的地方）
> ① "`for(a;b;c)` 与 `while(b)` 等价"只在 **`a`、`c` 都留空**时成立（即 `for(;b;)` ≡ `while(b)`）；`for(a;b;c)` 整体等价于 `{ a; while(b){ body; c; } }`，与 while 版本的差别恰在 **continue 会跳到 `c`**、而 while 版本 continue 会跳过步进。
> ② `a` 在 **C89 中不能是声明**（`for (int i = 0; ...)` 是 C99 才有的语法）——北航机试要求 `-std=c89`，所以变量必须在 `for` 之前声明。

### 8.2 #define 与 const ⭐⭐

| 维度 | `#define` | `const` |
|------|-----------|---------|
| **处理阶段** | **预处理**（编译之前）做**文本替换** | **编译阶段**，是一个真正的变量（对象） |
| 类型 | **无类型** | **有类型**，编译器做类型检查 |
| 作用域 | 从定义处到 `#undef` 或文件末尾（**不看块作用域**） | 遵循 C 的作用域规则（块内、函数内、文件内） |
| 是否占存储 | 不占（编译后名字就不存在了） | 通常占（可被优化掉，但可取地址 `&MAX`） |
| 能否取地址 | **不能**（`&MAX` 非法） | 可以 |
| 调试 | 调试器看不到符号（已被替换） | 可见，可查看值 |
| 安全性 | **低**：不检查类型、不做括号保护 | **高**：一旦初始化不可修改，类型受检 |

**结论一句话**：`#define` 是**简单的文本替换**，`const` 是**一个有类型的常量**，一旦声明其值不可修改，**安全性更高**——所以常量优先用 `const`（或 `enum`），`#define` 主要用于**条件编译、头文件保护、字符串化/拼接**等 `const` 做不到的场景。

**`#define` 的括号陷阱（必答）**：

```c
#define SQR(x) x * x          /* 危险！ */
SQR(1 + 2)                    /* 展开为 1 + 2 * 1 + 2 = 5，不是 9 */

#define SQR_OK(x) ((x) * (x)) /* 正确：参数和整体都加括号 */
```

- 参数要加括号：`((x) * (x))`；整体也要加括号：`#define ADD(a,b) ((a)+(b))`；
- 副作用问题：`SQR_OK(i++)` 仍会自增两次（宏展开了两次），**宏无法避免重复求值**，这类场景应改用 `static inline` 函数；
- `#define MAX 100;` 带分号会导致 `if (x > MAX)` 展开成 `if (x > 100;)` 编译错误——**宏结尾不写分号**。

**C 与 C++ 的一个差异**（可能被追问）：在 C 中 `const` 修饰的文件作用域变量默认是**外部链接**（其他文件可 `extern` 引用），C++ 中默认是**内部链接**；另外 C89 里 `const int n = 10; int a[n];` **不能**作数组长度（不是常量表达式），C99 才允许（且那实际上是 VLA）。

### 8.3 全局变量与局部变量重名 ⭐⭐

**能重名吗**：**可以**。C 允许内层作用域的同名声明**遮蔽（shadow）**外层同名标识符（局部变量遮蔽全局变量、内层块遮蔽外层块）。

**直接访问得到谁**：名字解析规则是"**从最内层作用域开始逐层向外查找**"，所以函数体内的直接使用只能访问到**局部变量**。

**局部如何访问全局变量**：
- **在 C 中，同名遮蔽后没有语法能直接引用被遮蔽的全局变量**——C 没有 C++ 的**作用域解析运算符 `::`**（`::x` 是 C++ 语法，在 C 中是**语法错误**）。
- C 中的可行手段：
  1. **给全局变量改个不同的名字**（最推荐，工程上就是这么做的：全局加前缀如 `g_x`，局部用小写）；
  2. 在**内层块**里对被遮蔽的名字再加一个 `extern` 声明，让它重新指回文件作用域的全局变量：
```c
int x = 1;                        /* 全局 */
void f(void)
{
    int x = 2;                    /* 局部遮蔽 */
    {
        extern int x;             /* 本层的 x 重新引用文件作用域的 x（外部链接） */
        printf("%d\n", x);        /* 输出 1 */
    }
    printf("%d\n", x);            /* 输出 2 */
}
```
  3. 让全局变量通过一个**函数或指针**暴露（接口化），不直接靠名字访问。

> [!warning]+ 勘误（重要）
> 如果参考资料里写"**`::x` 可以访问全局变量 x**"，那是 **C++ 的规则**，**C 语言不支持 `::`**。面试回答时要么明确说"在 C 中无法直接访问、需要改名或内层 `extern` 技巧；在 C++ 中可以用 `::x`"，要么会被追问时露怯。**(这一段是本笔记对原资料的有意更正。)**

**相关易混点**：
- **形式参数也是局部变量**，与函数体内同作用域的变量不能重名；但内层块可以重名；
- 全局变量与**静态全局变量**重名：同名会冲突（同一作用域内重复定义）；
- 局部变量遮蔽全局后，若全局变量在其它文件用 `extern` 引用，**不受影响**（别的文件里没有遮蔽）。

### 8.4 变长参数函数 ⭐⭐⭐

**需求**：像 `printf`、`scanf`、`execl` 那样，参数个数不固定。C 语言用 **`<stdarg.h>`** 提供的 `va_list` / `va_start` / `va_arg` / `va_end` / `va_copy` 实现。

**完整写法（C89 兼容）**：

```c
#include <stdio.h>
#include <stdarg.h>

/* n 是"后续参数的个数"，由调用者保证正确 */
int sum(int n, ...)
{
    va_list ap;
    int i, s = 0;

    va_start(ap, n);              /* 初始化：以最后一个具名参数 n 为基准 */
    for (i = 0; i < n; i++)
        s += va_arg(ap, int);     /* 取出一个 int 并让指针前进 */
    va_end(ap);                   /* 清理（在 return 前必须调用） */

    return s;
}

int main(void)
{
    printf("%d\n", sum(3, 10, 20, 30));   /* 60 */
    return 0;
}
```

**三条硬性规则**：
1. **必须至少有一个具名参数**：`va_start(ap, last)` 需要最后一个具名参数来定位后续参数的位置，所以 `int f(...)` 是非法的；
2. **必须自己知道参数个数与类型**：C 在运行期**无法得知**变长部分有多少个、都是什么类型——所以 `printf` 靠**格式串**、`sum` 靠**计数 n**、`execl` 靠**末尾的 NULL 哨兵**；
3. **`va_arg` 写的类型必须与实际实参"提升后"的类型一致**，否则是**未定义行为**（可能读到垃圾值甚至崩溃）。

**原理（为什么能拿到参数）**：
- 函数调用时，参数按**调用约定**放到约定位置：x86-64 SysV 下前 6 个整型参数依次放 `rdi, rsi, rdx, rcx, r8, r9`，其余压栈；x86-32 的 `cdecl` 下全部从**右向左**压栈。
- `va_start` 根据最后一个**具名参数**在内存/寄存器保存区的位置，推算出"变长部分的起点"；`va_arg(ap, T)` 按 `T` 的大小读出值并让 `ap` 前进到下一个参数。
- 因此变长参数机制本质是"**按地址顺序取参数**"——必须在**参数个数可推断**的前提下才安全（这也是 C 变长参数"不安全"的根源）。

**默认实参提升（高频坑）**：变长部分发生**默认实参提升**——`char`、`short` 提升为 `int`，`float` 提升为 `double`（结构体等不做提升）。
- 因此**不能**写 `va_arg(ap, char)`（应写 `int` 再强转），**不能**写 `va_arg(ap, float)`（应写 `double`）；
- 指针和 `int` 混用（该传指针却传了 int）在不匹配宽度下会直接错位。

**风险与防护**：
- 无编译期类型检查，类型/个数对不上就是 UB；
- GCC/Clang 可用 `__attribute__((format(printf, 1, 2)))` 让编译器按 `printf` 规则检查；
- C11 有 `_Generic` / 宏 `_Generic` 技巧做有限检查，但不如 C++ 的 variadic template 安全；
- 替代方案：传**数组 + 长度**（最安全）、传**结构体指针**、用哨兵值结尾。

**易混点**：
- **变长参数 ≠ 变长数组参数**：`int f(int n, int a[n])`（C99 的 VLA 参数）是"数组长度由前面参数决定"，与 `...` 无关；
- **`va_copy`**：需要多次遍历参数时要先 `va_copy` 复制一份 `va_list`（因为 `va_arg` 会破坏原 `va_list`）；
- **`va_end` 必须调用**：某些实现里它要释放资源，漏掉是 UB；
- 变长参数函数的参数**不做类型检查**，与"函数原型里的 `...` 必须放在参数表最后"这一点一起记。

**补充：为什么 `printf` 能自己数出参数个数**：因为它靠**格式串中 `%` 的个数与类型**，而不是靠 C 语言机制——格式串写错（如 `%d` 对应 `double`）就是典型的 UB。

## 附：数据结构面试速查表

| 问题 | 一句话回答 |
|------|-----------|
| 数组 vs 链表 | 数组查快改慢（连续+缓存友好），链表改快查慢；链表"插入 O(1)"工程上常不划算 |
| 栈的应用 | 函数调用、表达式求值（前缀/中缀/后缀）、括号匹配、DFS、撤销 |
| 队列的应用 | BFS、任务调度、消息缓冲；循环队列解决"假溢出" |
| 堆、栈、队列 | 栈 LIFO／队列 FIFO（都是线性表），堆是取最值的完全二叉树；内存的"堆区/栈区"与数据结构的堆无关 |
| 哈希的本质 | 数组 + 哈希函数 + 冲突解决；用计算代替比较 → 期望 O(1)，最坏 O(n) |
| 哈希冲突 | 链地址法（简单、不怕冲突多）或开放寻址法（缓存友好、α 必须 < 1） |
| 三种遍历 | 前序根左右、中序左根右、后序左右根；前序+中序可唯一还原，前序+后序不行 |
| AVL vs 红黑树 | AVL 严格平衡查找快，红黑树旋转少插删快；工程多用红黑树 |
| 堆的核心操作 | 插入→上浮；删顶→下沉；都是 O(log n)；建堆 O(n) |
| B+ 树优势 | 叶子链表→范围查询快；内部只存 key→树更矮→I/O 更少；数据库索引标配 |
| 图怎么存 | 邻接矩阵（稠密图、判边 O(1)）／邻接表（稀疏图、O(V+E)）；边集数组适合 Kruskal |
| DFS vs BFS | DFS 用栈、一根筋到底、不保证最短路；BFS 用队列、按层扩散、无权图可得最短路 |
| MST 两种 | Prim 贪点（稠密图 O(V²)，d[v] 是"到树的最小边权"）／Kruskal 贪边（稀疏图 O(E log E)，排序+并查集） |
| 最短路三种 | Dijkstra 单源非负权贪心；Floyd 全源区间 DP（k 必须最外层）；Bellman-Ford 可负权能检负环 |
| 稳定排序 | 冒泡、插入、归并、计数、基数稳定；选择、快排、堆排、希尔不稳定 |
| 为什么快排实际最快 | 原地 + 常数小 + 缓存友好；最坏 O(n²) 可随机化规避 |
| 二路归并 | 对半分 + 两个有序段合并；O(n log n) 无最坏退化、稳定、需 O(n) 辅助空间 |
| 多路归并 | 外排用 k 路归并减少趟数 → 减少磁盘 I/O；用败者树/小根堆优化选最小 |
| 哈夫曼树 | 每次合并权最小的两棵树 → WPL 最小的最优二叉树；小根堆维护，O(n log n) |
| 哈夫曼编码 | 变长**前缀**编码（异字头），高频短码；平均码长最短，解码无歧义 |
| 分治 vs DP | 分治子问题独立，DP 子问题重叠（DP = 分治 + 记忆化）；都要最优子结构 |
| 0-1 背包 | $dp[i][w]=\max(dp[i-1][w], dp[i-1][w-w_i]+v_i)$，O(nW)；O(nW) 是**伪多项式**（W 是数值不是规模） |
| 数据库查询优化 | 索引（覆盖索引/最左前缀/避免失效）+ SQL 重写（谓词下推/延迟关联）+ 执行计划 + 分区分表 + 缓存 |
| 数组名的类型 | `int a[5]` 的 `a` 是 `int[5]`，表达式中退化为 `int*`；`sizeof(a)`=20、`&a` 是 `int(*)[5]` |
| 数组指针 vs 指针数组 | `int (*p)[5]` 是指向数组的**指针**；`int *p[5]` 是元素为指针的**数组** |
| 函数形参中的数组 | `int a[5]`、`int a[]`、`int *a` 完全等价（退化为指针，`sizeof` 得 8） |
| for(a;b;c) | a 初始化（一次）、b 条件（每轮前）、c 步进（每轮后）；`for(;b;)` ≡ `while(b)`；continue 会执行 c |
| struct vs union | 同：多类型成员组成；异：struct 各成员独立占空间，union 共享一块内存（大小 = 最大成员），新值覆盖旧值 |
| static | 全局/函数 → 内部链接（只本文件可见）；局部 → 静态存储期（值保留、只初始化一次、默认 0） |
| #define vs const | 宏是预处理文本替换（无类型、无作用域、不查错），const 是有类型的常量（可检查、可取地址） |
| 全局与局部重名 | 可以重名，直接访问只得到局部；**C 无 `::`**，需改名或内层 `extern` 技巧（C++ 才能 `::x`） |
| 变长参数 | `<stdarg.h>`：`va_start(ap, 最后一个具名参数)` → 循环 `va_arg(ap, 提升后类型)` → `va_end`；必须自备个数与类型，char/float 会提升 |
| 面向对象三特性 | 封装（捆绑+隐藏）、继承（复用+is-a）、多态（同接口不同行为；虚表+虚指针） |
