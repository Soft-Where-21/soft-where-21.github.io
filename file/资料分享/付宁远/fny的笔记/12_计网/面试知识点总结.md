# 计算机网络 - 保研面试知识点总结

> [!info]+ 复习策略  
> 计网的核心逻辑是"数据如何从一台主机可靠地传输到另一台主机"。每一层解决一个特定问题，上层不关心下层怎么实现——这就是"分层"的价值。面试时从"每层解决什么问题"入手，再展开协议细节。
>
> 重点标注：⭐⭐⭐ 高频 | ⭐⭐ 中频 | ⭐ 低频但重要
>
> 北航软院面试高频考点：**各层功能、DNS 工作原理、OSPF 协议、TCP/UDP 区别**

---

> [!abstract]+ 学科总览  
> 计算机网络按"分层抽象"组织——每一层只解决一种通信问题，下层为上层提供服务：
>
> - **物理层**：比特流如何在介质上传输（编码、调制、信道容量）
> - **数据链路层**：相邻节点间的可靠传输（成帧、差错检测、MAC 寻址）
> - **网络层**：跨网络的主机间通信（IP 寻址、路由选择）
> - **传输层**：进程到进程的通信（端口号、可靠/不可靠传输）
> - **应用层**：面向用户的服务（HTTP、DNS、SMTP 等）
>
> 暗线：**物理层解决"信号传输"，链路层解决"相邻可靠性"，网络层解决"跨网寻路"，传输层解决"端到端可靠性"，应用层解决"用户服务"**。每层的核心问题是不同的，所以协议也不同。

---

## 1. 网络体系结构

> [!note]+ 章节导引  
> **本章知识点之间的关系**：分层的"世界观"——为什么分层、怎么分层。逻辑链：**三种交换方式**（电路/报文/分组）→ **OSI 七层 vs TCP/IP 四层**→ **协议/接口/服务**（协议是水平的，服务是垂直的）。
>
> **与上一章的关系**：无（起点）。
>
> **与学科的关系**：OSI vs TCP/IP 是面试经典题。

### 1.1 OSI vs TCP/IP ⭐⭐⭐

| OSI 七层 | TCP/IP 四层   | 功能        |
| ------ | ----------- | --------- |
| 应用层    | \\          | 用户服务      |
| 表示层    | > **应用层**   | 数据格式转换/加密 |
| 会话层    | /           | 会话管理      |
| 传输层    | **传输层**     | 端到端通信     |
| 网络层    | **网际层**     | 路由选择      |
| 数据链路层  | > **网络接口层** | 相邻节点传输    |
| 物理层    | /           | 比特流传输     |

**五层教学模型**（谢希仁教材体系，面试常与七层并列提问）：物理层 → 数据链路层 → 网络层 → 传输层 → 应用层——即把 TCP/IP 四层模型中的"网络接口层"**拆成物理层 + 数据链路层**，其余与四层模型一致。

> [!tip]+ 面试一句话  
> 协议是水平的（对等层之间），服务是垂直的（下层向上层提供）。各层之间通过接口交互，不能跨层。

### 1.2 各层的作用 ⭐⭐⭐（面试必问）

**从下往上，每层只解决一个通信问题：**

| 层次        | 作用                                | 要点                                            |
| --------- | --------------------------------- | --------------------------------------------- |
| **物理层**   | **透明的传输比特流**                      | 屏蔽不同传输媒体和通信手段的差异，确定机械/电气/功能/过程四大特性；设备：中继器、集线器 |
| **数据链路层** | 将网络层传来的 **IP 数据报封装成帧**            | 概括为**封装成帧、透明传输、差错控制、流量控制、介质访问控制**；设备：网桥、交换机   |
| **网络层**   | 将分组**封装成 IP 数据报**，完成**路由选择与分组转发** | 跨网络的逻辑寻址（IP 地址）+ 路由；还包括 ARP/ICMP/IGMP 等配套协议   |
| **传输层**   | **进程到进程**的通信                      | 通过端口号多路复用/分用；TCP 可靠、UDP 不可靠                   |
| **应用层**   | 面向**用户的服务**                       | HTTP、DNS、SMTP、DHCP、TFTP 等                     |

> [!tip]+ 记忆口诀  
> 物理层"透明传比特"，链路层"组帧管相邻"，网络层"寻路跨网络"，传输层"端口连进程"，应用层"服务给用户"。

### 1.3 数据在各层的传输单位（PDU）⭐⭐⭐

**从上往下逐层封装（加首部），从下往上逐层解封装（去首部）：**

| 层次    | 传输单位（PDU）                          |
| ----- | ---------------------------------- |
| 应用层   | **报文**（message）                    |
| 传输层   | TCP：**报文段**（segment）；UDP：**用户数据报** |
| 网络层   | **IP 数据报 / 分组**（packet）            |
| 数据链路层 | **帧**（frame）                       |
| 物理层   | **比特**（bit）                        |

> [!tip]+ 封装过程（发送方向）  
> 应用层产生报文 → 传输层加端口号等首部成报文段 → 网络层加 IP 首部成数据报 → 链路层加 MAC 地址等首尾部成帧 → 物理层转成比特流发送。接收方逆向解封装。

### 1.4 协议、接口、服务 ⭐⭐

- **协议**：**水平的**——对等层实体之间通信的规则（如两台主机的传输层之间按 TCP 规则交互）
- **服务**：**垂直的**——下层为上层提供的功能（如链路层为网络层提供成帧、差错检测服务）
- **接口**：上下层之间交换信息的**连接点与规则**（如何调用下层服务）

> [!tip]+ 面试一句话  
> "协议是水平方向（对等层），服务是垂直方向（下层向上层提供），接口是层间交互的通道"——分层设计把复杂通信拆成可复用模块。

### 1.5 三种交换方式 ⭐⭐⭐

|      | 电路交换           | 报文交换       | 分组交换              |
| ---- | -------------- | ---------- | ----------------- |
| 通信前  | **建立连接**（独占线路） | 无需连接       | 无需连接              |
| 数据单元 | 连续比特流          | **整个报文**   | **分组**（报文拆分）      |
| 时延   | 连接建立时延大，传输时延小  | 整文存储转发，时延大 | 存储转发，时延**较小**     |
| 线路利用 | 独占、利用率低        | 共享链路       | 共享链路、利用率**高**     |
| 特点   | 实时性好、可靠        | 无速率/格式转换问题 | **路由器存储转发**，灵活、健壮 |

> [!tip]+ 面试一句话  
> 分组交换是**存储转发**，无需预先建立连接，适合**突发数据**；因为分组比整个报文短得多，时延更小、灵活性更高，所以分组交换优于报文交换。

### 1.6 传统电话网络 vs 计算机网络 ⭐

**核心区别：电话网络是电路交换，计算机网络是分组交换。**

|      | 传统电话网络             | 计算机网络             |
| ---- | ------------------ | ----------------- |
| 交换方式 | **电路交换**           | **分组交换**          |
| 连接   | 先建立连接，通信期间**独占线路** | 无连接、**按需共享带宽**    |
| 资源分配 | 预先分配固定带宽，空闲也浪费     | 动态竞争使用，利用率高       |
| 适合流量 | **持续的大流量**（语音）     | **突发流量**（网页/文件）   |
| 时延特征 | 建立连接时延大、之后稳定       | 有存储转发和**排队时延**，可变 |

## 2. 物理层

> [!note]+ 章节导引  
> **本章知识点之间的关系**：物理层解决"比特如何在信道上传输"。逻辑链：**通信基础**（波特率 vs 比特率、奈氏定理、香农定理）→ **传输介质**（双绞线/同轴/光纤/无线）→ **物理层设备**（中继器、集线器）。
>
> **与学科的关系**：奈氏定理和香农定理是面试常考计算题。

### 2.1 奈氏定理与香农定理 ⭐⭐⭐

**奈氏定理**（理想无噪声信道）：  
$\text{极限数据率} = 2W \log_2 V \quad \text{(b/s)}$

**香农定理**（有噪声信道）：  
$\text{极限数据率} = W \log_2(1 + S/N) \quad \text{(b/s)}$

> [!tip]+ 关键  
> 奈氏限定了码元速率上限，香农限定了信息速率上限。**实际最大速率 = min(奈氏, 香农)**。信噪比 $10\log_{10}(S/N)$ 单位 dB。
>
> （W是信道带宽）

## 3. 数据链路层

> [!note]+ 章节导引  
> **本章知识点之间的关系**：链路层解决"相邻节点间的可靠传输"。逻辑链：**两种信道**（点对点的 PPP / 广播的以太网）→ **差错检测**（CRC 循环冗余校验）→ **流量控制**（停等协议/GBN/SR）→ **介质访问控制**（CSMA/CD、CSMA/CA、令牌传递）→ **VLAN**（虚拟局域网，隔离广播域）→ **设备**（网桥、交换机）。
>
> **与上一章的关系**：链路层在物理层的比特流基础上封装成帧，增加可靠性。
>
> **与学科的关系**：GBN 和 SR 是面试常考的可靠传输协议对比。

### 3.1 三种可靠传输协议 ⭐⭐⭐

| 协议            | 窗口            | 重传方式              | 效率        |
| ------------- | ------------- | ----------------- | --------- |
| **停止等待协议**    | 发送窗口=1        | 超时重传当前帧           | 低         |
| **GBN（后退N帧）** | 发送窗口>1，接收窗口=1 | 超时重传**所有已发送未确认帧** | 中         |
| **SR（选择重传）**  | 发送窗口>1，接收窗口>1 | 只重传**出错帧**        | 高（但窗口有限制） |

### 3.2 CSMA/CD ⭐⭐⭐

**载波监听多点接入/碰撞检测**（以太网的核心协议）

- **先听后发**：发送前监听信道是否空闲
- **边发边听**：发送时持续监听是否冲突
- **冲突停发**：检测到冲突立即停止，发干扰信号
- **随机重发**：等待随机时间后重试（二进制指数退避）

> [!tip]+ 争用期（碰撞窗口）与最短帧长  
> **端到端传播时延**决定冲突最晚何时能被发现：只有"发送一帧所需时间 ≥ 往返传播时延"，发送方才能确认自己没被撞。这段最坏往返时延就是**争用期（碰撞窗口）**。
>
> 以太网规定争用期 = **512 比特时间**（10 Mb/s 下即 **51.2 μs**），对应最短帧长 **64 字节**——帧长不足 64 字节会在检测到冲突前就发完，无法判错（因此 **< 64 字节的帧一律按无效帧丢弃**）。

### 3.3 PPP 协议 ⭐

**点对点协议（Point-to-Point Protocol）**——点对点信道上使用最广泛的数据链路层协议

- **应用场景**：用户到 ISP 的拨号链路（广域网串行链路）。与以太网（广播信道）相对，PPP 工作在**点对点信道**
- **特点**：面向**字节**、**不可靠**——不提供差错控制/流量控制，差错检测和纠错交给上层
- **三个组成部分**：
  1. **封装方法**：将 IP 数据报封装到串行链路
  2. **链路控制协议 LCP**：建立/释放数据链路层连接，协商链路参数
  3. **网络控制协议 NCP**：配置网络层，为用户分配**临时的 IP 地址**

> [!tip]+ 帧格式与透明传输  
> 帧首尾是标志字段 F=0x7E。透明传输两类做法：**同步传输用零比特填充**（发现 5 个连续 1 就插入一个 0）；**异步传输用字节填充**（7E→7D 5E、7D→7D 5D、控制字符前加 7D）。

> [!tip]+ PPP 链路工作过程  
> 拨号建立物理连接 → LCP 建立链路 → NCP 分配临时 IP 地址 → 通信完毕：NCP **先**释放网络层连接并收回 IP，LCP 再释放数据链路层连接，**最后**释放物理层连接。

### 3.4 VLAN 虚拟局域网 ⭐⭐

**VLAN（Virtual LAN）**：由一些局域网网段构成的**与物理位置无关的逻辑组**，利用**以太网交换机**很方便地实现（标准为 **IEEE 802.1Q**）。

- **本质**：只是局域网给用户提供的一种**服务**，**不是**新型局域网
- **隔离广播域**：每个 VLAN 是一个**广播域**——限制了接收广播信息的工作站数，防止"**广播风暴**"引起网络性能恶化

> [!tip]+ 三大优点  
> **改善性能**（减少到其他 VLAN 的不必要通信）→ **简化管理**（地理位置分散的用户可轻松划入同一 VLAN，无需移动设备）→ **降低成本**（用便宜的交换机代替网络层路由器来划分广播域）。

**划分方法**（按所在层次）：

- 基于**端口**划分（第 1 层，最简单常用）
- 基于 **MAC 地址**划分（第 2 层，需输入和管理大量 MAC 地址）
- 基于**协议类型**划分（第 2 层）
- 基于 IP 子网 / 高层应用划分（第 3 层）

> [!tip]+ 跨 VLAN 通信  
> 二层交换机（工作于链路层）只能隔离广播域；**跨 VLAN 通信必须经过网络层**——需要路由器或**三层交换机**（如 VLAN 接口充当各 VLAN 的网关）。

### 3.5 令牌传送机制 ⭐⭐

**受控接入（受控访问）**的介质访问控制方式，与 CSMA/CD 的随机接入相对——用于**令牌环**、**令牌总线**网络。

- **原理**：网络中只有一个特殊帧"**令牌（token）**"沿环（或总线）传递，**只有拿到令牌的站才能发送数据**，发完把令牌传给下一站
- **无冲突**：同一时刻只有一台主机有发送权，**不会发生碰撞**，因此没有最短帧长限制
- **优劣势**：
  - **重负载时效率高**：不会像 CSMA/CD 那样因冲突频繁而性能骤降
  - **轻负载时效率低**：主机必须等令牌绕一圈才能发送，等待时间长

> [!tip]+ vs CSMA/CD  
> CSMA/CD 是"抢着发、撞了重发"（随机接入、冲突不可避免）；令牌是"排队发、轮到才发"（受控接入、无冲突但轻负载时延大）。

### 3.6 各层设备对比 ⭐⭐⭐

| 设备           | 工作层次  | 功能                         | 隔离冲突域            | 隔离广播域             |
| ------------ | ----- | -------------------------- | ---------------- | ----------------- |
| **中继器**      | 物理层   | **信号再生**放大，延长传输距离          | 不隔离              | 不隔离               |
| **集线器（Hub）** | 物理层   | 多端口中继器，转发比特流               | 不隔离（全部端口一个冲突域）   | 不隔离               |
| **网桥**       | 数据链路层 | 连接两个网段，**按 MAC 地址**有选择地转发帧 | **隔离**（每端口一个冲突域） | 不隔离               |
| **交换机**      | 数据链路层 | 多端口网桥，硬件查表转发，支持 VLAN       | **隔离**           | 不隔离（VLAN 可隔离）     |
| **路由器**      | 网络层   | 按 **IP 地址**路由选择并转发分组       | **隔离**           | **隔离**（每个接口一个广播域） |

> [!tip]+ 关键结论
>
> - 中继器/集线器只能"放大+转发"比特，**不分冲突域也不分广播域**
> - 网桥/交换机是**智能设备**，能按地址有目的地管理帧，**隔离冲突域但不隔离广播域**
> - **路由器才叫"网络互连"**——转发器/网桥/交换机只是把一个网络扩大，仍是一个网络；跨网络必须用路由器或三层交换机

### 3.7 网络接口卡（网卡/网络适配器）⭐

**网卡（NIC）**是计算机与局域网的连接接口，工作于数据链路层（同时完成物理层的比特收发）。

**四大功能**：

- **串行/并行转换**：总线上是并行数据，线路上是串行比特流
- **数据缓存**：网络数据率与总线数据率不同，靠缓存匹配速度差异
- **实现以太网协议**：封装/解封装 MAC 帧、实现 CSMA/CD
- **MAC 地址**：全球唯一的 48 位 MAC 地址**固化在网卡 ROM 中**（还需安装设备驱动程序配合操作系统收发）

> [!tip]+ 面试一句话  
> "网卡是主机接入以太网的'桥头堡'：串/并转换、缓存、MAC 成帧解帧、CSMA/CD 都由它完成，MAC 地址烧死在 ROM 里。"

### 3.8 差错检测：奇偶校验与 CRC ⭐⭐

**目标**：数据在传输中可能因噪声产生**比特差错**（1 变 0、0 变 1）。链路层靠**冗余编码**让接收方有能力发现差错。

- **奇偶校验**：加 1 位校验位使 1 的个数为奇数/偶数——只能发现**奇数个**比特错，能力弱
- **CRC 循环冗余校验**（以太网使用）：
  1. 收发双方约定一个 $k+1$ 位的**生成多项式** $G(x)$
  2. 发送方在数据 $M$ 后补 $k$ 个 0，用**模 2 除法**（只做异或、不借位）除以 $G(x)$，得到 $k$ 位余数作 **FCS 帧检验序列**，附在数据后一起发送
  3. 接收方用同一个 $G(x)$ 去除收到的数据，**余数为 0 则认为无差错**，否则丢弃该帧

> [!tip]+ 关键结论  
> **CRC 只能检错、不能纠错**——发现差错就丢弃，是否重传由上层（ARQ 协议 / TCP）决定。

> [!tip]+ 面试一句话（无差错传输在哪一层实现？）  
> 分两层看：**差错"检测"**在数据链路层（帧尾 CRC）和传输层（首部校验和）完成；**真正"无差错且可靠"的传输**由传输层的 **TCP**（序号 + 确认 + 超时重传）保证。链路层只做到"发现有错就扔"，不负责让数据一定送到。

### 3.9 面向连接服务 vs 无连接服务 ⭐⭐

|     | 面向连接服务            | 无连接服务          |
| --- | ----------------- | -------------- |
| 通信前 | **必须先建立连接**（协商参数） | 无需建立连接，直接发     |
| 顺序性 | 数据**按序**到达        | 不保证顺序          |
| 可靠性 | 可确认/重传，**可靠性高**   | 尽力交付，**不可靠**   |
| 开销  | 建立/释放连接有额外开销      | 开销小、灵活、效率高     |
| 典型  | **TCP**、虚电路       | **UDP**、IP 数据报 |

> [!tip]+ 数据链路层的三种基本服务
>
> - **无确认的无连接服务**：发完不管，出错交上层处理——**以太网**采用（局域网误码率低，交给 TCP 重传更划算）
> - **有确认的无连接服务**：每帧都要求确认，收到确认才发下一帧——适用于误码率较高的链路
> - **有确认的面向连接服务**：先建立链路连接，帧按序传送 + 确认——可靠性最高但开销最大，实际很少用

### 3.10 局域网的关键技术 ⭐⭐

局域网（LAN）的三个关键要素：

| 要素           | 内容                                               |
| ------------ | ------------------------------------------------ |
| **网络拓扑**     | 星形（**主流**，配交换机）、总线形（早期以太网）、环形（令牌环）、树形            |
| **传输介质**     | 双绞线（UTP 5/6 类，最常见）、同轴电缆（早期）、光纤（主干/远距离）、无线（Wi-Fi） |
| **介质访问控制方法** | **CSMA/CD**（共享以太网，随机接入）、**令牌传递**（令牌环/令牌总线，受控接入）  |

> [!tip]+ 关键点  
> 局域网的特点是**私有、范围小、速率高、误码率低**。现代以太网采用**星形拓扑 + 双绞线 + 交换机**，每个端口独占带宽、全双工工作，已不再是共享信道（CSMA/CD 实际退居备用）。

## 4. 网络层

> [!note]+ 章节导引  
> **本章知识点之间的关系**：网络层解决"数据如何跨网络从源到目的"。逻辑链：**IP 地址**（分类/子网划分/CIDR）→ **ARP**（IP→MAC 映射）→ **路由协议**（RIP/OSPF/BGP）→ **ICMP**（差错报告）→ **IGMP**（多播成员管理）→ **NAT/VPN**（专用地址 + 地址转换 + 虚拟专用网）。
>
> **与上一章的关系**：网络层在链路层提供的相邻节点传输基础上，实现跨网络的端到端传输。
>
> **与学科的关系**：IP 地址和路由协议是面试核心。

### 4.1 IP 地址分类与子网 ⭐⭐⭐

| 类 | 网络号   | 主机号   | 起始  | 最大网络数   |
| - | ----- | ----- | --- | ------- |
| A | 8bit  | 24bit | 0   | 126     |
| B | 16bit | 16bit | 10  | 16384   |
| C | 24bit | 8bit  | 110 | 2097152 |

**子网掩码**：作用是**区分 IP 地址中的网络部分与主机部分**——与 IP 地址按位与运算即得网络地址，据此判断"两台主机是否在同一子网"（同网段直接交付，跨网段交给路由器）。把主机号进一步划分为**子网号 + 主机号**。

**CIDR**：无类域间路由，用 `/n` 表示网络前缀长度，支持超网

- 无类：不区分ABC类
- 超网：CIDR聚合，如4 个 C 类网段：

```
202.100.0.0/24
202.100.1.0/24
202.100.2.0/24
202.100.3.0/24
```

4 个网段，单独写要 4 条路由； 用 CIDR 聚合，共同前缀是前 22 位：`202.100.0.0 /22`

> [!tip]+ 为什么不能用手机号实现 IP 地址？（开放题）
>
> - **结构不同**：IP 地址是**分层结构**（网络号 + 主机号），同一网络前缀可**聚合**成一条路由表项，路由器只需记"去哪个网段"；手机号是**平面编号**，无法从号码推出归属网络，若拿它当地址，全球路由表将大到无法维护。
> - **绑定对象不同**：IP 地址分给"**网络接口/位置**"，随主机移动而改变，与设备身份解耦；手机号绑定"**人/SIM 卡身份**"，跟人走。
> - **可复用性**：IP 地址可在不同子网内重复使用（配合 NAT），手机号全球唯一、不可复用。
> - **层次归属**：IP 是网络层**逻辑地址**，与 MAC 地址、域名解耦分层；手机号是运营商业务标识，不参与三层转发。

### 4.2 路由协议对比 ⭐⭐⭐

|               | RIP                | OSPF                      | BGP                           |
| ------------- | ------------------ | ------------------------- | ----------------------------- |
| 类型            | **内部网关**（IGP）      | **内部网关**（IGP）             | **外部网关**（EGP）                 |
| 算法            | 距离向量（Bellman-Ford） | **链路状态（Dijkstra）**        | 路径向量                          |
| 度量            | **跳数**（最大 15）      | 代价（带宽等）                   | 策略                            |
| 收敛速度          | 慢（可能计数到无穷）         | **快**                     | /                             |
| **和谁换（who）**  | 只与**相邻路由器**交换      | **洪泛法**，发给**本 AS 内所有路由器** | 只与**相邻 AS 的 BGP 发言人**交换       |
| **换什么（what）** | **整个路由表**（周期性全量）   | **相邻路由器的链路状态**            | **可达信息**：启动时交换完整信息，之后**增量更新** |
| 承载            | UDP 520，每 30 s     | IP 协议号 89                 | **TCP 179**                   |

> [!tip]+ 面试一句话  
> RIP 简单但收敛慢（距离向量+最大15跳），OSPF 收敛快（链路状态+全网拓扑+Dijkstra），BGP 用于自治系统间（策略路由）。

### 4.3 ARP 协议 ⭐⭐⭐

**功能**：已知 IP 地址，求对应的 MAC 地址

> [!tip]+ ARP 工作过程  
> 先查本地 ARP 缓存→没有则广播 ARP 请求→目标主机单播 ARP 应答→更新缓存。ARP 是网络层和数据链路层的桥梁。

### 4.4 ICMP 协议 ⭐⭐

**网际控制报文协议（Internet Control Message Protocol）**——差错报告

**功能**：主机或路由器向源主机**报告差错和异常情况**——IP 找不到目的地时直接把分组丢弃，由 ICMP 负责"善后"。

**地位**：ICMP **不是高层协议**，而是 IP 层的组成部分——ICMP 报文封装在 IP 数据报中传输（IP 首部协议字段 = 1）。

**两类报文**：

- **差错报告报文**（共 5 种）：
  - **终点不可达**（目标找不到；如 UDP 发现目的端口号错误时，由 ICMP 发送"端口不可达"）
  - **源点抑制**（发送太快、接收方承受不住；现在已废弃）
  - **超时**（TTL 减为 0）
  - **参数问题**（IP 首部检查出错）
  - **重定向**（存在更优路由时提示源主机下次走更好的路）
- **询问报文**：**回送请求/应答**（ping）、**时间戳请求/应答**（tracert 时钟同步和时间测量）

> [!tip]+ 不应发送 ICMP 差错报告报文的情况  
> ① 对差错报告报文本身不再发送差错报告（因为它可能也有错）；② 对第一个分片之后的**后续分片**不发送（发一次就够了）；③ 对**多播地址**的数据报不发送；④ 对**特殊地址**（如 127.0.0.0、0.0.0.0）的数据报不发送（都不知道发给谁）。

> [!tip]+ ICMP 的两个经典应用
>
> - **ping**（Packet InterNet Groper）：测试两主机**连通性**，用回送请求/应答报文。是应用层**直接**使用网络层 ICMP 的例子，不走 TCP/UDP，所以快。
> - **traceroute / tracert**：跟踪分组从源到终点的**路径**。利用 IP 首部 **TTL 字段 + ICMP 超时差错报告报文**（+ 终点不可达报文），逐跳暴露中间路由器。

### 4.5 IGMP 协议 ⭐⭐

**网际组管理协议（Internet Group Management Protocol）**——IP 多播的"成员管理"

**功能**：让连接在**本地局域网**上的**多播路由器**知道本局域网上**是否有主机参加或退出某个多播组**。

> [!tip]+ 与多播路由选择协议的分工  
> **IGMP 管成员**：只知道**有无成员**，不知道成员数和成员分布在各网络；**多播路由选择协议管传播**：负责把多播数据报用最小代价传送给组内所有成员。

**地位**：IGMP 报文加上 IP 首部构成 IP 数据报传输（IP 首部协议字段 = 2）；同时 IGMP 也向 IP 提供服务，因此它和 ICMP 一样是**网际协议 IP 的组成部分**。

**工作两个阶段**：

1. **加入多播组**：主机向该组的多播地址发送 IGMP 报文，声明成为组成员；本地多播路由器收到后，把组成员关系转发给互联网上的其他多播路由器。
2. **探询成员变化**：本地多播路由器**周期性**（默认每 125 秒发一次询问）探询本局域网主机是否仍是组成员；只要有一个主机响应就认为该组活跃，多次探询无人响应则不再转发该组成员关系。

> [!tip]+ 降低开销的措施  
> 所有通信都用 IP 多播；对所有组只发**一个**询问报文；多个多播路由器时只选**一个**来探询；**分散响应**（主机在 0～10 秒内随机选择时延应答）；**抑制机制**（主机听到本组其他主机已响应，自己就不再响应）。

### 4.6 专用地址（私有地址）⭐⭐

**背景**：机构内部计算机也用 TCP/IP 通信，但 IP 地址紧缺，且并非所有主机都需要接入互联网。于是机构可给自己内部计算机**自行分配** IP 地址——RFC 1918 指明了三大**专用地址（private address）** 块。

- **本地地址**：仅在机构内部使用的 IP 地址，由本机构自行分配，无需向互联网管理机构申请
- **全球地址**：全球唯一的 IP 地址，必须向互联网管理机构申请
- **三大专用地址块**（可重用——不同专用网可重复使用）：

| 地址块                | 类别  | 范围                                      |
| ------------------ | --- | --------------------------------------- |
| **10.0.0.0/8**     | A 类 | 10.0.0.0 ~ 10.255.255.255（1 个网段）        |
| **172.16.0.0/12**  | B 类 | 172.16.0.0 ~ 172.31.255.255（连续 16 个）    |
| **192.168.0.0/16** | C 类 | 192.168.0.0 ~ 192.168.255.255（连续 256 个） |

> [!tip]+ 关键特性  
> 专用地址**只能用作本地地址，不能用作全球地址**——互联网中的所有路由器对目的地址是专用地址的数据报**一律不转发**。所以专用地址**不能直接在互联网中使用**，需要借助 NAT 等机制接入。

> [!tip]+ 专用网  
> 采用专用 IP 地址互联的网络称为**专用网**（专用互联网/本地互联网）；专用 IP 地址又称**可重用地址**。

### 4.7 NAT 网络地址转换 ⭐⭐

**问题**：专用网上使用专用地址的主机，如何与互联网上的主机通信（无需加密）？主要方法：**网络地址转换 NAT**（Network Address Translation）。

- **NAT 路由器**：在专用网连接到互联网的路由器上安装 NAT 软件；它**至少**有一个有效的外部**全球 IP 地址**
- **转换过程**：内外主机通信时在 NAT 路由器上发生**两次**地址转换——
  - **离开**专用网：替换**源地址**（内部专用地址 → 外部全球地址）
  - **进入**专用网：替换**目的地址**（外部全球地址 → 内部专用地址）

> [!tip]+ 局限与 NAPT
>
> - NAT 具有 n 个全球 IP 时，专用网内**最多 n 台主机同时**接入互联网（其余轮流使用）；通过 NAT 的通信**必须由内网主机发起**，所以内网主机**不能充当服务器**
> - NAT 本身**并不能节省 IP 地址**；**NAPT（网络地址与端口号转换）**在 NAT 基础上**同时转换传输层端口号**，使多台内网主机**共用一个全球 IP 同时**与不同主机通信（家庭路由器上网用的就是 NAPT）

### 4.8 虚拟专用网 VPN ⭐

**定义**：利用**公用互联网**作为本机构**各专用网之间的通信载体**，这样的专用网称为**虚拟专用网 VPN**（Virtual Private Network）。

- **专用**：本机构主机用于机构内部通信，不与非本机构的主机通信
- **虚拟**：实际上**没有使用通信专线**，只是在效果上与真正的专用网一样
- **构建**：保密要求下，经公网传送的数据**必须加密**；各网点需配置专门的 VPN 软硬件，使彼此系统都知道对方的地址（用**隧道技术**实现）

> [!tip]+ VPN 三种类型
>
> - **内联网 VPN**（intranet）：同一机构内部各网络构成
> - **外联网 VPN**（extranet）：一个机构与某些外部机构共同建立
> - **远程接入 VPN**（remote access VPN）：外部流动员工通过 VPN 隧道访问公司内网，如同使用本地网络

> [!tip]+ VPN 与 NAT 的对比  
> **NAT**：专用网主机**对外**访问互联网（转地址、不加密）；**VPN**：机构各专用网之间经**公网**互连（隧道、加密）。

### 4.9 单播、多播与广播 ⭐⭐

| 方式                     | 含义                     | 典型应用                        |
| ---------------------- | ---------------------- | --------------------------- |
| **单播（unicast）**        | **一对一**通信              | 普通 HTTP 网页访问、传统点对点通信        |
| **多播 / 组播（multicast）** | **一对一组**通信（组内所有成员都收到）  | IPTV、视频会议；用 **D 类地址**标识多播组  |
| **广播（broadcast）**      | **一对全体**通信（本网络所有主机都收到） | ARP 请求、DHCP 发现；路由器**不转发**广播 |

> [!tip]+ 关键点
>
> - 多播地址（D 类，224.0.0.0~239.255.255.255）**只能作目的地址，不能作源地址**——它标识"一个组"而非"一台主机"
> - 路由器**隔离广播域**，不转发广播，因此广播只在同一局域网内传播；**互联网范围的多播需要多播路由器**
> - 链路层对应三种帧：单播帧、广播帧（目的 MAC 全 1）、多播帧

### 4.10 TTL 生存时间 ⭐⭐

**TTL（Time To Live）**：IP 首部中的 **8 位**字段，表示数据报在网络中**最多还能经过的路由器数**。

- **原理**：每经过一个路由器 TTL **减 1**，减到 **0** 时路由器**丢弃该数据报**，并向源主机发送 **ICMP 超时差错报告报文**
- **作用**：防止数据报因为路由环路等原因在网络中**无限循环**

**哪些工具用到它**：

- **traceroute / tracert**：从 TTL=1 开始逐个递增发送，让分组"恰好"在第 1、2、3…跳超时，利用返回的 ICMP 超时报文**逐跳探测出路径上的每个路由器**
- **ping**：发送回送请求时设置初始 TTL（Windows 默认 128，Linux 默认 64），从应答的 TTL 可粗略判断对方系统类型

> [!tip]+ 面试一句话  
> "TTL 是 IP 首部的'限次计数器'，每跳减 1，归零即丢弃——防数据报兜圈子；tracert 正是靠把 TTL 从 1 递增来逐跳暴露路径的。"

### 4.11 内部网关协议 IGP vs 外部网关协议 EGP ⭐⭐

互联网由许多**自治系统 AS** 组成，路由协议按作用范围分两类：

|      | IGP（内部网关协议）       | EGP（外部网关协议）  |
| ---- | ----------------- | ------------ |
| 作用范围 | **AS 内部**         | **AS 之间**    |
| 代表协议 | **RIP、OSPF**      | **BGP**      |
| 关注点  | 域内**最佳路由**（跳数/代价） | 域间**可达性与策略** |

**IGP 内部：RIP vs OSPF**

|      | RIP                  | OSPF             |
| ---- | -------------------- | ---------------- |
| 算法   | 距离向量（Bellman-Ford）   | 链路状态（Dijkstra）   |
| 度量   | **跳数**（最大 15，超限不可达）  | **代价**（带宽、时延等）   |
| 收敛   | 慢（可能计数到无穷）           | **快**（全网拓扑同步）    |
| 和谁交换 | 只与**相邻路由器**          | **洪泛法**发给全网所有路由器 |
| 交换内容 | 整个路由表（UDP 520，每 30s） | 链路状态信息（IP 89 协议） |

> [!tip]+ 面试一句话  
> "AS 内部用 IGP（RIP 简单但收敛慢、最多 15 跳；OSPF 链路状态收敛快），AS 之间用 EGP（BGP 按策略选路）。面试答 OSPF 优于 RIP 更稳妥。"

## 5. 传输层

> [!note]+ 章节导引  
> **本章知识点之间的关系**：传输层是"端到端"的最后一层——它提供进程级别的通信。逻辑链：**端口号**（区分进程）→ **UDP**（无连接、不可靠、快）→ **TCP**（面向连接、可靠、慢但有保障）→ **TCP 三次握手/四次挥手**（面试极高频）→ **TCP 流量控制/拥塞控制**。
>
> **与上一章的关系**：网络层提供主机间通信，传输层在此基础上提供进程间通信（通过端口号多路复用/分用）。
>
> **与学科的关系**：TCP 三次握手和拥塞控制是计网面试最核心的考点。

### 5.1 TCP vs UDP ⭐⭐⭐⭐（面试极高频）

|      | TCP                     | UDP          |
| ---- | ----------------------- | ------------ |
| 连接   | **面向连接**（三次握手）          | 无连接          |
| 可靠性  | **可靠**（确认+重传+流量控制+拥塞控制） | 不可靠          |
| 传输方式 | 字节流                     | **报文**（保留边界） |
| 头部大小 | 20 字节+                  | **8 字节**     |
| 效率   | 慢                       | **快**        |
| 适用   | 文件传输、HTTP、SMTP          | DNS、视频流、游戏   |

> [!tip]+ TCP 如何保证可靠传输？（六件套）
>
> - **校验和**：首部 + 数据出错则丢弃，防止收到被噪声破坏的数据
> - **序号 + 确认号**：给每个字节编号，接收方累计确认，可检测丢包、去除重复
> - **超时重传**：发送后启动定时器，超时未收到确认就重传
> - **连接管理**：三次握手确认双方收发能力，四次挥手保证两个方向都关干净
> - **流量控制**：接收方用滑动窗口（rwnd）告知自己的缓冲能力，防止发送过快压垮对方
> - **拥塞控制**：慢启动/拥塞避免/快重传/快恢复（见 5.4）按网络整体状况调整速率

> [!tip]+ 会议视频、语音通话用哪个传输层协议？  
> 用 **UDP**（实时音视频通常跑在 **RTP/RTCP** 之上）。理由：实时媒体**对时延敏感、对丢帧宽容**——重传的包到达时早已错过播放时刻，反而加剧拥塞，所以宁可丢帧也不重传；网络抖动由接收端缓冲平滑。

### 5.2 TCP 三次握手 ⭐⭐⭐⭐

```
Client ──SYN──→ Server     （"我要连接"）
Client ←─SYN+ACK── Server  （"好的，我也要连接"）
Client ──ACK──→ Server     （"确认，开始通信"）
```

> [!tip]+ 为什么三次？  
> 两次无法确认客户端的接收能力（可能旧 SYN 导致服务端误建立连接）；三次是"双方都确认对方能收发"的最少次数。

### 5.3 TCP 四次挥手 ⭐⭐⭐⭐

```
Client ──FIN──→ Server   （"我发完了"）
Client ←─ACK─── Server    （"收到，等我发完"）
Client ←─FIN─── Server   （"我也发完了"）
Client ──ACK──→ Server     （"收到，再见"）
→ Client 等待 2MSL （报文最大存活时间）后关闭
```

> [!tip]+ 为什么四次？  
> TCP 是全双工——每个方向需要单独关闭。服务端收到 FIN 后可能还有数据要发，所以先 ACK，等发完再 FIN。

> [!tip]+ 为什么等 2MSL？  
> 确保最后一个 ACK 能到达服务端（如果丢失，服务端会重发 FIN，Client 需要还能响应）。MSL = 最大报文段生存时间。

### 5.4 TCP 拥塞控制 ⭐⭐⭐

**四个阶段**：慢启动→拥塞避免→快重传→快恢复

| 阶段       | 窗口变化                                      | 触发条件         |
| -------- | ----------------------------------------- | ------------ |
| **慢启动**  | ssthresh = cwnd/2，cwnd = 1 指数增长（每 RTT 翻倍） | 初始/超时        |
| **拥塞避免** | 线性增长（每 RTT +1）                            | 窗口达 ssthresh |
| **快重传**  | 立即重传丢失报文                                  | 收到 3 个重复 ACK |
| **快恢复**  | ssthresh = cwnd/2，cwnd = ssthresh         | 快重传后         |

> [!tip]+ 慢启动为什么"慢"？  
> "慢"不是指速度慢，而是指从"小窗口"开始逐步探测——初始 cwnd=1 MSS，指数增长，很快就能到高带宽。

### 5.5 传输层协议 vs 网络层协议 ⭐⭐⭐

|      | 网络层（IP）                 | 传输层（TCP/UDP）                  |
| ---- | ----------------------- | ----------------------------- |
| 通信范围 | **主机到主机**（host-to-host） | **进程到进程**（process-to-process） |
| 寻址依据 | **IP 地址**（主机/路由器接口）     | **IP 地址 + 端口号**（具体进程）         |
| 连接性  | **无连接**、尽力交付、不可靠        | TCP **面向连接可靠**；UDP 无连接不可靠     |
| 传输单位 | **IP 数据报**              | TCP **报文段** / UDP **用户数据报**   |
| 主要职责 | 路由选择、分组转发（寻路）           | 复用/分用、可靠传输、流量与拥塞控制            |

> [!tip]+ 面试一句话  
> "网络层回答'数据去哪台主机'（IP 寻址+路由），传输层回答'给主机上的哪个进程'（端口号）。IP 层只保证尽力交付，可靠性由 TCP 在上层补齐。"

## 6. 应用层

> [!note]+ 章节导引  
> **本章知识点之间的关系**：应用层是面向用户的服务层。逻辑链：**C/S vs P2P 模型**→ **DNS**（域名→IP）→ **HTTP**（网页请求）→ **Email**（SMTP/POP3/IMAP）。
>
> **与上一章的关系**：应用层协议基于传输层（TCP 或 UDP）提供的服务。
>
> **与学科的关系**：DNS 和 HTTP 是面试常考。

### 6.1 DNS 工作原理 ⭐⭐⭐

**DNS = 分布式层次数据库**，把域名解析为 IP 地址

**查询过程**：本地缓存 → 本地 DNS 服务器 → 根域名服务器 → 顶级域名服务器 → 权威域名服务器

**递归查询 vs 迭代查询**：

- 递归：客户端只问本地 DNS，本地 DNS 代为查询所有层级
- 迭代：本地 DNS 问根服务器，根服务器返回"去问 TLD"，TLD 返回"去问权威"...

### 6.2 HTTP ⭐⭐⭐

| 版本           | 特点                        |
| ------------ | ------------------------- |
| **HTTP/1.0** | 短连接（每次请求新建 TCP）           |
| **HTTP/1.1** | **长连接**（Keep-Alive），管道化   |
| **HTTP/2**   | 多路复用、头部压缩、服务器推送           |
| **HTTP/3**   | 基于 **QUIC（UDP）**，0-RTT 连接 |

> [!tip]+ 面试一句话  
> HTTP/1.1 长连接解决短连接开销；HTTP/2 多路复用解决队头阻塞；HTTP/3 用 QUIC(UDP) 解决 TCP 队头阻塞。

### 6.3 C/S 模型 vs P2P 模型 ⭐⭐

|     | C/S（客户/服务器）            | P2P（对等连接）             |
| --- | ---------------------- | --------------------- |
| 角色  | **不对等**：服务器提供服务，客户请求服务 | **对等**：每台主机既是客户机也是服务器 |
| 服务器 | 必须**始终运行**、有固定 IP 地址   | **无中央服务器**，去中心化       |
| 扩展性 | 服务器是瓶颈——客户增多性能下降       | **可扩展性强**——节点越多资源越丰富  |
| 管理  | 集中管理、安全可控              | 无统一管理，安全问题更突出         |
| 场景  | HTTP、DNS、Email         | BT 下载、区块链、视频直播        |

> [!tip]+ 面试一句话  
> "C/S 是'中心服务型'：集中管理、稳定可控，但服务器是扩展瓶颈；P2P 是'人人都是服务器'：去中心、可扩展性好，但没有统一管理。"

### 6.4 DHCP 动态主机配置协议 ⭐⭐

**功能**：自动为主机分配 **IP 地址、子网掩码、默认网关、DNS 服务器**等配置，实现**即插即用**（无需手工配置）。

- 基于 **UDP**（客户机端口 68、服务器端口 67），全程**广播**进行

**DORA 四步**：

1. **Discover（发现）**：客户机广播"谁有 IP 给我？"（源地址 0.0.0.0，目的地址 255.255.255.255）
2. **Offer（提供）**：DHCP 服务器广播应答，提供可用 IP 配置
3. **Request（请求）**：客户机广播确认请求该 IP（同时隐式拒绝其他服务器的 Offer）
4. **Ack（确认）**：DHCP 服务器广播确认，完成分配

> [!tip]+ 关键  
> 分配的 IP 有**租期**，到期需**续租**；DHCP 使用 0.0.0.0 作源地址、255.255.255.255 作目的地址的广播方式，因为此时客户机还没有 IP。

### 6.5 TFTP 简单文件传送协议 ⭐

**TFTP（Trivial File Transfer Protocol）**：基于 **UDP** 的轻量文件传输协议（端口 69）。

- **特点**：只支持简单文件传输，**无交互、无认证/权限控制**
- **适用**：局域网内的**小文件传输**——无盘工作站引导、路由器/交换机的**固件升级与配置文件备份**
- **与 FTP 对比**：FTP 用 TCP、双连接、有认证，功能强但开销大；TFTP 用 UDP、单连接、无认证，简单快速

> [!tip]+ 面试一句话  
> "TFTP 是'轻量级 FTP'：UDP、端口 69、无认证，常用于设备引导和固件升级；常规文件传输用 FTP（TCP，更可靠）。"

### 6.6 综合题：在浏览器输入网址后发生了什么？⭐⭐⭐

按"**解析域名 → 建立连接 → 请求响应 → 渲染**"这条主线展开，逐步点明所用协议与层次：

| 步骤                  | 做的事                                             | 协议（层次）                      |
| ------------------- | ----------------------------------------------- | --------------------------- |
| 1 生成请求              | 查浏览器缓存 / 系统 hosts，未命中则准备 DNS 解析                 | 应用层                         |
| 2 **DNS 解析**        | 本地 DNS → 根 → TLD → 权威服务器，拿到目的 IP                | **DNS**（应用层，UDP 53）         |
| 3 **路由与 ARP**       | 查路由表定下一跳，用 ARP 得到网关 MAC，封装成帧                    | **ARP**（网络/链路层）、**IP**（网络层） |
| 4 **TCP 握手**        | 与服务器 443/80 端口三次握手建立连接                          | **TCP**（传输层）                |
| 5 **TLS 握手**（HTTPS） | 校验证书、协商会话密钥，建立加密通道                              | TLS（传输层与应用层之间）              |
| 6 **发 HTTP 请求**     | 发送 GET 请求报文                                     | **HTTP**（应用层，基于 TCP）        |
| 7 服务器响应             | 经反向代理/后端处理，返回 HTML 等资源                          | HTTP                        |
| 8 **渲染**            | 解析 HTML/CSS/JS，并发请求静态资源（HTTP/2 多路复用），构建 DOM 并渲染 | HTTP/HTTPS                  |

> [!tip]+ 面试一句话  
> "URL → DNS 解析出 IP → ARP 拿到网关 MAC → 三次握手建 TCP →（HTTPS 再走 TLS）→ 发 HTTP 请求 → 服务器返回 → 浏览器渲染。"自下而上依次是：链路层封装成帧、网络层 IP 寻路、传输层 TCP 建连、应用层 DNS/HTTP 干活。

## 7. 网络安全基础

> [!note]+ 章节导引  
> **本章知识点之间的关系**：回答"如何确认对方身份、如何防范恶意代码"。逻辑链：**数字证书 / CA**（身份可信）→ **病毒 / 蠕虫 / 木马**（威胁形态的区别）。
>
> **与学科的关系**：多作为开放题出现，答清"三者区别"即可。

### 7.1 数字证书 ⭐⭐

**数字证书**是 **CA（电子认证服务机构）** 签发的一种电子文档，是一串能够**表明网络用户身份信息**的数字，提供了在计算机网络上**验证网络用户身份**的方式。

- **解决的问题**：公钥密码中"我怎么确定这把公钥真的是对方的"——证书把**公钥**与**身份信息**绑定，由可信第三方 CA 签名背书
- **内容**：持有者身份信息、公钥、有效期、CA 名称、**CA 的数字签名**
- **使用流程**：服务器下发证书 → 客户端用 **CA 的公钥验证证书签名** → 验签通过则信任证书内的公钥 → 用它协商会话密钥（TLS/HTTPS 即如此工作）

> [!tip]+ 面试一句话  
> "证书就是 CA 给公钥开的'身份证明'：CA 用私钥签名，大家用 CA 的公钥验签，从而确认'这把公钥属于这个人'。"

### 7.2 病毒、蠕虫、特洛伊木马的区别 ⭐⭐

|          | 计算机病毒                      | 蠕虫                                  | 特洛伊木马                  |
| -------- | -------------------------- | ----------------------------------- | ---------------------- |
| **本质**   | 一段**可感染**的恶意代码             | 独立**能自我复制**的恶意程序                    | 伪装成正常软件的恶意程序           |
| **传播**   | **依附寄主**（文件/引导区），靠用户运行寄主传播 | **自主传播**，利用网络漏洞扫描感染，**无需寄主、无需用户操作** | **不自我复制**，靠伪装诱骗用户主动安装  |
| **典型行为** | 感染可执行文件、破坏数据               | 短时间耗尽带宽/资源，造成网络瘫痪                   | 开后门、窃取账号密码、被远程控制（僵尸网络） |
| **关键区别** | 需要寄主 + 用户触发                | 能独立自我复制、主动扩散                        | 不复制，靠欺骗                |

> [!tip]+ 面试一句话  
> "病毒靠寄主 + 人为触发传播，蠕虫能自主复制扩散（无需寄主），木马不复制、靠伪装骗你运行——一个是'传染'，一个是'自己繁殖'，一个是'伪装潜入'。"

| 输入网址后流程       | DNS 解析→ARP/路由→TCP 三次握手→(TLS)→HTTP 请求→渲染                         |
| 手机号 vs IP     | IP 分层可聚合、绑位置、可复用；手机号平面、绑身份、全球唯一                                 |
| 数字证书          | CA 签发，绑定公钥与身份，用 CA 公钥验签                                         |
| 病毒/蠕虫/木马      | 病毒靠寄主+触发；蠕虫自主复制扩散；木马不复制、靠伪装                                     |
| 路由协议 who/what | RIP 只跟邻居换"结论"(整张路由表)；OSPF 洪泛"原料"(链路状态)；BGP 相邻 AS 换可达性+策略        |
| 路由协议承载        | RIP = UDP 520 / 每 30 s，OSPF = IP 协议号 89，BGP = TCP 179           |
